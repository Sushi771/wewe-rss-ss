# 小红书完整归档与互动阶段

> 订阅和显式更新的首阶段先遍历获授权范围，并逐篇保存详情响应中的发布时间、四项指标及可用正文；该阶段不下载媒体。字段缺失保持未知，基础信息阶段结束不代表媒体或本地归档完成。已验证完整缓存及四项指标可复用。下文的归档顺序适用于用户另行执行的归档流程。

平台目录正常保留标题和原文链接。点击笔记跳转来源；完整文件下载后在 Obsidian 等本地工具阅读。本改动不新增平台正文缓存状态或阅读接口。

## 复合任务顺序

显式启动或恢复博主复合任务后，执行：发现目录 → 原完整下载器保存正文/媒体 → 指标、一级评论及根回复 → 原保存器在同一目录更新互动附页。

第一篇根回复失败会暂停互动工作，但不会阻断已经在前一阶段保存的其他笔记正文。来源验证、会话、预算和未知错误仍按原规则停止；正文/媒体下载本身遇到限制时不绕过。目录标题不是成功归档的证据。

旧任务恢复时先核对完整归档保存回执，保留同一任务预算账本、评论游标和既有下载子任务。重启只暂停，不自动执行。旧下载子任务迁移为 `archiveTask`；无法从旧回执确认的项目通过同目录保护保存器重新核验，原文件和手改内容继续受保护。

## 两种独立正向回执

订阅任务私有文档增加 `localArchives`：只有原完整下载器通过正文与媒体门槛、原生保存器成功返回后才记录 `savedAt`。跳过的视频、列表元数据、数据库中完整缓存、失败媒体或未知提交结果均不能产生该回执。

`confirmedLocalArchives(taskId)` 只返回已完成/已复用条目的持久正文与媒体保存回执。它沿用现有对账及未知回执阻断规则，不读取或推测用户目录。

原 `localReceipts` / `confirmedLocalSaves` 继续表示有效互动附页保存回执。无指标、无评论的原生正文归档可能没有附页；此时完整归档可以确认成功，互动附页仍待补。不能再以附页是否存在代替正文是否落盘。

博主任务项提供独立字段：

| 字段 | 值与证据 |
| --- | --- |
| `archive` | `saved` 仅来自完整正文/媒体持久回执，否则 `pending` |
| `engagement` | `unknown`、`partial`、`returned-range-complete`，由本轮指标及评论/根回复检查点决定 |
| `supplement` | 兼容原 `saved/pending`，仅来自互动附页正向回执 |
| `localSave` | `saved/pending/unknown`，补充表达当前附页保存回执不明 |

完整复合任务完成需同时具备完整归档、指标、一级评论、根回复及附页回执。一级评论结束不代表根回复结束，也不代表来源全部历史范围已覆盖。

## 独立互动查询

`engagement(creatorId, noteId)` 可直接读取同一笔记已有指标与评论，不以正文缓存或完整下载成功为前提。它继续严格校验归属；没有快照为 null，未知计数为 null，实际 0 保持 0。following 尚无可确认的源合同，维持 null，界面可以隐藏。归档失败不会删掉已有互动数据。

## 不变的保护与离线证据

原完整媒体数量、字节、容器、视频及本地保存门槛保持不变；没有新媒体路径、预算扩容、令牌存储或自动重试。空文本且媒体未取得不能成为完整归档，完整缓存也不等于用户目录已保存。

`xhs-archive-order.spec.ts` 以临时合成 SQLite、实际 `prepareLocalDownload` 和 `LocalArticleStore` 覆盖：目录状态与互动四组合、旧根回复任务保留原预算恢复、所有完整文件先落盘再出现根回复失败、重启不自动请求、同目录恢复保留手改正文并补附页、无任何互动时原生正文成功且附页为空的独立回执、空正文/媒体不完整时不确认保存。数据仅为自有合成夹具，测试不访问来源或下载图片。

还需运行既有订阅回执、取消恢复、本地保存和共享界面回归。离线测试不代表在线来源可用、部署成功或真实用户路径已验收。

# SQLite 备份与应用写入协调

提交前的一致性备份固定读取快照，避免外部提交不断重启分步复制。`PrismaService` 在进入 Prisma 引擎、取得连接和开始事务之前统一取得应用许可；备份等已取得许可的操作结束，再独占许可。新写入在队列中等待，事务的运行超时从实际启动时计时，不包含这段排队时间。原事务及其回调只执行一次，不自动重放任何业务或上游请求。

## 真实入口与覆盖方式

| 写入入口                                                                                  | 协调方式                                                                   |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| tRPC 账号、订阅、文章、笔记、分组等 ORM 创建/修改/删除，后台普通状态写入                  | Prisma `$use` 中间件在调用 `next` 之前取得许可                             |
| 原始 SQL `$executeRaw*`、可能包含 DML 的 `$queryRaw*`                                     | 同一中间件保守地取得许可；不根据字符串猜测只读                             |
| `CollectionService` 正文及旧数据保护事务、订阅激活/回退、小红书落库、只新增缓存及回执事务 | `$transaction` 包装器在进入引擎前取得许可；事务内中间件复用该有效许可      |
| 原路由的数组批量 `$transaction([...])`，以及只读交互事务                                  | 同一包装器，保留原返回值及事务选项，不拆散数组原子性                       |
| 自治 Python 周期快照                                                                      | 使用原分步在线复制，不固定长时间源库读锁；保持完整性校验、校验和和租约规则 |

普通 ORM 只读查询继续可用。原始 SQL 读取和只读事务因不能证明没有写入，保守排队。所有生产应用客户端由 `PrismaService` 构造；测试及维护脚本中直接构造的 `PrismaClient` 不构成生产入口，也不参与此进程内协调。未来添加独立客户端必须接入协调，不能假定中间件自动覆盖它。

队列按到达顺序推进；备份排在队首后，新写入不能插队造成饥饿。最多排队 256 项，每项最多等待 75 秒；耗尽时明确返回“尚未开始写入”，移除该项，之后不会偷偷执行。该队列不是重启后持久化任务队列：进程退出时未完成调用不能被当作成功，原持久化任务/客户端必须保留失败状态及意图。事务错误按原行为返回，协调层不重试非幂等事务，也不重发已受理、收费或回执未知的上游操作。

固定源库读取预算默认 15 秒，`SQLITE_BACKUP_COPY_TIMEOUT_SECONDS` 可收紧至 1–15 秒；复制完立即释放源库连接，再校验备份和计算哈希。预算不能替代实际磁盘验证。周期复制可能在持续写入下失败关闭；应用提交前的备份排空应用写入后复制，因此不会被本应用的新提交反复重启。两类复制仍共用操作锁，核验失败不签发保护凭证，也不允许据此提交上游。

超时子进程退出未确认时，除备份重试封锁外，还封锁新的应用写入许可。实际 `close` 到达后解除；排队超时仍明确失败，不持有数据库连接。禁止在已开始的事务中申请备份，避免自锁；现有业务备份应保持在事务开始前。

## 验证与边界

真实 SQLite 和实际 Python 备份回归验证：源库读锁持续超过交互事务的 100 毫秒超时期间，ORM、原始 SQL、数组事务和交互事务尚未进入引擎；释放后全部提交，非幂等递增及回调各执行一次，备份保留此前状态。小型合成回归另覆盖 DELETE/WAL 一致性、自治周期复制期间 50 毫秒超时的独立写入者可提交、复制失败后的锁释放/重试、子进程真实退出及不确定退出封锁、队列溢出/过期不执行、嵌套许可和过期异步上下文。

协调范围是一套本机应用进程及其配置数据库。外部维护脚本、迁移、手工 SQL 和其他应用进程不受许可控制，必须在独立维护窗口运行；不能据此宣称多进程写入无冲突。WAL 固定快照可让外部写入继续提交，已有合成回归验证这一点，但切换日志模式涉及启动、文件系统和恢复策略，本轮不改变日志模式。没有创建生产全量副本或执行生产写入，实际大库磁盘性能仍由唯一生产负责人整合验证。

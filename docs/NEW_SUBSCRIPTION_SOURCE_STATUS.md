# 新增公众号入口的来源状态

新增弹窗原调用链为 `feeds/index.tsx → feed.addFromArticle → TrpcService.addSubscriptionFromArticle → wechat2RssProvider`。旧来源停用时，最后一步抛出 `WECHAT2RSS_DISABLED`，发生在备份、网络请求及创建订阅之前；这条错误不表示登录过期。

现在原入口先读取经过原认证保护的 `feed.addCapability`。停用来源时，弹窗明确说明新号发现及持续更新仍未接通，保留文章链接，禁止提交到旧来源。后端同样在调用旧 Provider、备份或写库之前返回有解释的前置条件失败。状态未知或读取失败也保留输入，不声称新增成功。

这项修复没有启用或购买 Wechat2RSS，也没有把当前单篇 DOM 结果冒充订阅来源。已有明确配置的来源仍保留原受理语义，任务受理不等于新文章已取得。自建新增通路仍需真实公众号发现/稳定身份/目录及原刷新合同验收，不能靠正常扫码或修改提示补足。

## 新号与已绑定订阅的接线边界（2026-10-07）

新文章链接的新增入口与已有订阅的刷新入口使用不同合同：

| 阶段                       | 当前实现                                                                                          | 尚缺的证据                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 文章链接 → 新公众号身份    | `addFromArticle` 仍由旧 Provider 的 `/addurl`、`/list` 返回来源确认的公众号身份                   | 自建来源对用户指定链接返回真实公众号 ID、名称及可持续读取的目录身份；短链不能靠字符串推算 |
| 选定账号 → 目标公众号绑定  | 正常 Web 登录记录与已有私有目标配置核对后，原连接入口确认绑定                                     | 未知公众号尚无可信目标配置；登录成功不能补足这一项                                        |
| 已绑定订阅 → 原手动刷新    | `feed.refreshArticles → resolveCollectionRoute → collectOwnerWereadLatest`                        | 第二个真实目标目录/正文成功及后续自然新发布实测                                           |
| 最近目录 → 正文图片 → 入库 | 按每个目标的私有配置选择账号，核目录和原文身份、真实发布时间；备份后事务写库、保留旧 ID/正文/指标 | 有限最近窗口不能证明历史齐全或无人值守更新                                                |
| 已保存正文 → 原单篇保存    | 原 `/download/article` 可复用已核完整缓存，保存 Markdown 与实际图片文件                           | 新真实文章的文件及图片打开验收                                                            |

已绑定的 `owner-weread-latest` 刷新不需要 Wechat2RSS，也不使用随机可用账号。目标配置的 biz 与公众号 ID 冲突，或会话 ownerVid 与目标账号不符，均在目录请求前停止。账号连接功能先读取已有目标配置，因此手动填写订阅元数据、复制一次页面正文或预置配置都不能称为新号自动发现。

`apps/server/src/collection/owner-subscription-flow.spec.ts` 使用两个不同的合成公众号和两个不同的合成会话。保留原 tRPC、私有配置校验、Provider、SQLite 迁移/事务、真实 Python 一致性备份和原 HTTP 保存器，仅替换外部 HTTP 响应与请求间隔。覆盖两个已预置绑定的最近十篇首次入库，第二号窗口前移后新增一篇，重复刷新去重，第一号/旧正文/指标/笔记保护，以及真实写出的 Markdown 和逐字节 PNG。这是离线接线回归，预置绑定不是新增入口验收，合成文章不是线上新文。

下一次真实验收只需要围绕一个经用户指定的新目标进行：先取得并核对上述身份发现结果，再连接该目标；由用户通过原刷新按钮取得真实最近目录/正文/图片；该号自然发布后再次通过原按钮刷新，确认只新增新文、重复点击不重复入库、旧数据不变；最后用原保存入口打开新文 Markdown 及图片。每一步以前一步成功和原授权为前提，遇官方验证或访问限制立即停下并保留准确记录。当前没有真实新号发现证据，不能把安装单篇扩展作为这条订阅链路的完成条件。

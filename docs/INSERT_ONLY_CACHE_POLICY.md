# 纯新增缓存事务与周期快照（方案三）

本变更只优化已经通过原 ProviderPage 合同核验的本地缓存新增。开关
`SQLITE_INSERT_ONLY_FAST_PATH=1` 显式启用；默认关闭。周期快照的独立开关、
启动备份、15 分钟调度、失败告警和许可生命周期由配套 snapshot guard 负责。
父任务统一集成、验证和启用；本窗口没有修改生产配置或执行生产迁移。

## 用户可见行为与保护边界

- 真正不存在的新文章允许跳过这一批写前全库备份。批次、文章和必要本地同步状态
  在同一 SQLite 事务提交；失败全部回滚。重复缓存投递不会重复新增或覆盖用户修改。
- 旧文章、正文、来源、封面、指标、笔记不进入 INSERT 更新分支。已有正文补写、
  图片补写、删除和迁移继续使用原完整写前备份。关闭开关即回到原策略，已正确
  新增的文章继续保留，不自动撤销。
- 标题及时间只用于检测可能冲突，不能构造、猜测或合并文章身份。事务重新核验
  biz/mid/idx、文章 ID、源 URL、公众号及来源绑定。旧短链身份不明时退回原保护；
  原保存器前缀匹配可能漏掉的不同参数顺序或跨号身份冲突直接隔离报错。
- 仅有列表时 `bodyReady=false`，不推进正文同步时间。含图片未完成标记的正文
  不宣称完成。快路径不启动图片请求；远程或需要补写的媒体返回原保护流程。

这项策略不等效于每批完整备份，也不保证零延迟。主库整体损坏时，可能损失最近
成功完整快照之后的新增及后续编辑。15 分钟是调度配置，不是成功备份的保证；
真实窗口从快照保守起点与成功验证记录计算。备份期间的并发写入不会把这个窗口
虚假缩短为“刚刚备份”。

## 事务和最终 lease 合同

消费配套 `sqlite-snapshot-guard.ts` 的以下接口，不创建第二套周期任务：

```ts
recentVerifiedSqliteSnapshot(): Promise<InsertOnlySnapshot | null>;
assertInsertOnlySnapshotPermit(tx, originalPermit): Promise<void>;
notifySqliteSnapshotDirty(originalPermit): Promise<void>;
```

`InsertOnlySnapshot` 的 source/sha256/verifiedAtMs 三项不能单独授权写入。
原始对象携带 owner 在内存签发的短时 lease，关联源库路径、设备/文件身份、schema、
owner generation、snapshot generation、保守覆盖起点及过期时间。消费者保存原始
对象，不能在事务中重新查询一个许可并替换它。

启动无合格备份、查询不可读、备份失败、过期、文件或 schema 改变、owner 停止等
情况必须返回 null 或拒绝断言。快路径在事务开始、文章写前及批次/同步状态写后
调用断言。拒绝后回滚，再进入原写前全备路径；未知存储故障回滚并报错，不擅自重试。
提交后才增加原 cache revision，并通知 dirty。通知失败不能假称事务回滚或重新保存
已提交批次；owner 还通过 data_version 检出未收到通知的变更。

复用原 PID 文件锁串行化同机快 INSERT，避免两个 Prisma 延迟事务同时升级读锁。
这只约束本快路径，没有新增全库写屏障。外部程序直接替换数据库、未协调的迁移、
多机写入仍不属于支持范围，必须按现有写前备份和停止写入流程处理。

## schema 与部署顺序

追加 `cache_insert_batches` 表，只记录批次哈希、文章 manifest、快照/owner generation、
快照保守时间及新增数量。它和文章、feed 状态原子提交，没有自动清理或级联删除。
缺少此表时快路径安全回退，不自行建表。

父任务先保留完整一致性备份，再在隔离副本演练新增迁移与配套 owner；确认构建和
lease 联测后才决定生产迁移及开关。迁移后需要新 schema 对应的成功启动快照，旧 schema
快照不能授予许可。凭据、数据库、备份、缓存原始样本和完整日志不进入 Git。

## 恢复与退出

1. 停止刷新和所有写入，关闭快路径，保留损坏库及当前文件的独立副本。
2. 选择成功验证的完整快照，核对验证报告、SHA-256 和 integrity_check。
3. 先恢复到新的隔离数据库并验证旧文章和其他表，再由用户确认切换。不得在线覆盖
   正在运行的源库。
4. 最近快照之后的新增和用户编辑需要另行核实、保留再处理。关闭策略不会删除这些
   数据。新增批次一旦有后续编辑，就不能按批次粗暴 DELETE；本变更没有开发这样的
   撤销工具，也没有承诺单批撤销能保留后续编辑。

离线恢复回归将实际验证过的完整快照恢复到新目标并核对旧行；它不代表可自动恢复
最近快照之后的数据。

## 验证与基准

对应回归为 `insert-only-cache.spec.ts` 与原 `cache-sync-storage.spec.ts`，覆盖事务半失败、
重试、重复投递、旧字段与用户后编、来源变化、身份冲突、并发、快照拒绝、禁用、
缺表、备份失败及提交后通知。守卫自身异常与租约校验由配套窗口另行验收。

`benchmark-insert-only-cache.cjs` 仅接受明确的只读源库/缓存路径和新工作目录。它从现成
真实缓存取已在旧库核验过的身份与可信时间，只在隔离 seed 移除选定文章以模拟纯新增。
同一 seed、同一 5 篇列表在旧路径及真实周期 owner 的快路径各测 6 次。它不发平台、
登录、/add 或图片请求；不使用合成身份冒充真实新增，也不宣称取得新正文。

总耗时包括预检、保存事务和提交后通知；事务内 lease 校验同时属于事务耗时，不能重复
相加。启动全备、复制、schema 准备及保护核对单独记录，不计入保存延迟。有限样本的
p95 等于最慢样本，不能视为生产 SLA。最终实测数值和验收结论见交付记录。

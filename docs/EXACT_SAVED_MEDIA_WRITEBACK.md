# 精确复用已下载媒体

`article.supplementSavedMedia` 是主服务内的受保护 mutation，只接受
`{ "ids": ["已有本地文章ID"] }`。每次最多五个不重复 ID，限定同一个已启用的
Wechat2RSS 订阅，且每个 ID 必须出现在服务端绑定清单中。需要原有身份验证、本地
控制上下文及启动写门禁；验收只读模式仍拒绝该写操作。RPC 不接受路径、HTML、
URL、状态、媒体字节或任意配置。

此操作仅复用已取得且验证过的文件，不请求文章、图片、订阅列表、更新或 add。
它不会改变 `WECHAT2RSS_CACHE_MEDIA`、安全停机标记或夜间策略。内部
`verifiedImages` 缓存存在时，归档核心对未命中的地址也禁止 HTTP，保留缺口。
已有有效内嵌图片保留。此入口不启动独立维护进程，也不使用停服维护出口。

## 服务端绑定

操作人员在私有任务资源根放置 UTF-8 无 BOM 的 `manifest.json`，并在受信任的
服务配置中设置该真实绝对目录 `WEWE_SAVED_MEDIA_ROOT` 和清单原始字节的
`WEWE_SAVED_MEDIA_MANIFEST_SHA256`。缺少配置或摘要变化时拒绝执行。两者均不能
从 RPC 提供或修改。清单、图片和审计证据不提交仓库。

清单结构如下，示例只说明字段，不是可执行的任务授权：

```json
{
  "version": 1,
  "mpId": "MP_WXS_1234567890",
  "articles": [
    {
      "id": "已有本地ID，允许已证明身份的旧短ID",
      "sourceUrl": "已保存且可核验的原文长链接",
      "bodySha256": "绑定当前保存正文UTF-8字节的64位小写摘要",
      "assets": [
        {
          "sourceUrl": "正文中该图片的精确HTTPS CDN地址",
          "file": "image-1.png",
          "bytes": 100,
          "sha256": "文件字节摘要",
          "type": "image/png",
          "decodedSha256": "此前完整解码通过的同一文件摘要"
        }
      ]
    }
  ]
}
```

操作人员须从既有下载及完整图像解码证据生成清单；不得凭文件扩展名、标题、
图片顺序或声明的 MIME 推测成功。`decodedSha256` 表示受信任操作人员已经完整
解码通过的字节身份，必须等于文件 SHA。服务端重新验证摘要、长度和既有
`decodeInlineImage` 容器校验；它不执行完整图像解码器，不能替代此前的完整帧验证。

清单最多五篇、每篇最多六十个资源、128KiB；图片 basename 只能含普通字母、
数字、连字符和下划线及支持的图片扩展名。禁止目录段、盘符、ADS、符号链接或
跳出根目录。文件必须是普通文件；打开后复核文件身份，执行有界读取并复核尺寸
和修改时间，再核对内容摘要。单文件不超过10MB，本次读取资源累计不超过32MB，
当前正文累计不超过32MB，归档核心保留默认每篇20MB预算，增量写保留64MiB载荷上限。

## 合并与回执

服务端按精确 ID 读取现有正文与原文身份，旧短 ID 必须有同一公众号和原文身份的
已保存长链接证明。只为正文中仍缺失且清单精确命中的来源读取资源。正文版本必须
符合清单绑定；完整重入且已无待替换来源时是只读 no-op，不重复写入。

主服务原有 `activeCollections`、采集实例占用、`incrementalWrite` 跨进程互斥、
写协调器、物理余量检查和 FULL/EXTRA synchronous/journal 校验均保留。既有采集
合并事务在任何写入前复核有界初始快照；正文、身份、时间、标题、状态或版本变化
会返回冲突。任意条件更新未命中也抛出冲突并回滚整个事务，不覆盖并发编辑、不
自动重放。不会插入新文章或改文章 ID。

此模式仅允许更改媒体合并后的 `contentHtml`、相应 `lastBodyStatus` 和数据库正常
更新时间。文字、注释、指标、发布日期、来源、封面及未选文章保留；订阅摘要、
同步时间、历史覆盖和历史 `cache_refresh_commits`/提交 claim 均不重写。

返回结果包含实际更新数、每个 ID 的当前读取状态和 `mediaReady`。完成条件来自
写入后重新读取的正文，不能用 HTTP 200 或更新条数代替。未知图片、未命中来源、
遗留 pending 标记、CSS 图片、srcset 和其他未支持媒体保留为 `unconfirmed`。
文件缺失、校验失败或冲突会明确失败，不删除缺口或伪造成功。

## 最小发布与验收

首次安装包含该入口的新代码仍走既有候选构建、版本/数据库保护检查和受控切换。
如果当前库与恢复点因新增 claim、文章或其他持久内容不相等，必须按原保护流程
取得合格恢复点；不得伪造相等、恢复旧库、删回执或关闭保护来避免升级备份。
本功能没有 schema 迁移或备份生命周期修改。

代码升级/受控启动所需的恢复保护，与之后已经运行的主服务内普通媒体写回是两个
阶段。普通调用仅走现有增量事务，不调用 `createVerifiedSqliteBackup`，不要求停服
或重启，也不因每次补图制造整库副本。独立定时快照仍遵循原来的预算和生命周期。

唯一生产操作窗口在候选检查通过后，绑定已授权的精确清单并调用一次受保护入口；
核对返回的每篇状态、实际落库字节/媒体可打开、未选历史与原回执保留，再做一次
no-op 重入。存在未确认项则保留具体缺口。开发测试只能使用合成库和合成图片；
此代码交付不表示已部署或已替用户执行五篇写回。

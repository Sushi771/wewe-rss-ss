# 微信读书搜索卡片到正文：公开源码链路核查

日期：2026-09-30。范围仅为腾讯公开搜索页静态脚本、固定版本开源客户端与本项目已有的脱敏结果。本轮没有读取私有候选、凭据或生产 SQLite，没有发目标准确号名、文章或正文请求。

## 已有搜索结果能提供什么

本项目先前在同一合法移动凭据换取的 Web 会话中，按腾讯页面的游标形状查询目标号：首屏有 11 张、次页有 15 张 `source.title` 精确匹配卡片，两页候选键无交集；这是[搜索索引](REFRESHED_MOBILE_SEARCH_CURSOR_PROBE.md)的陈述，不是 26 篇已核原文。后续[结构诊断](SEARCH_CANDIDATE_ARTICLE_PROBE.md)在首屏取得 11 条带目标 `__biz` 的原存腾讯原文 URL，私有候选保留 `docID/doc_url`，但没有 `reviewId`。一次原文 HTTP 200 的页面解析 `sn` 与搜索 URL 不符，另一不同旧文被 HTTP 302 导向验证或登录；按[差异分析](SEARCH_SN_MISMATCH_ANALYSIS.md)已停止该匿名原文请求形状。这些结果不能把 `docID` 当作文章 ID，也不能通过同形状重复请求补证。

## 可用结论与后续证据条件

在本轮固定第一方搜索 JS 与上表五种近期搜索/封面实现中，**没有找到实际发送代码能把搜索 `docID` 或 `doc_url` 变成 `reviewId`**。可审查的两类真实链路是：

1. 搜索卡片 `doc_url` → 微信原文页面；其链接当前可能遭验证或与页面字段不符，必须逐篇核 `biz/mid/idx/sn/ct`、正文和图片。已有 302 停止条件不得通过连续换卡重试规避。
2. 已知书架 `MP_WXS_*` → WeRead 封面/列表返回的真实 `reviewId` → `/web/mp/content`；现有合法移动桥接会话对目标封面尚未成功，且封面没有多篇列表能力。

因此不得把 `docID` 拼入 `/web/mp/content?reviewId=`、用原文 URL 猜 `reviewId`、或把搜索卡片数当五篇验收。若找到另一份第一方资源或开源实现，下一轮须先给出**真正发送的腾讯端点、入参来自哪个已认证响应字段、会话来源及成功回包**，再交独立 Probe 审查；本文件的阴性结论只覆盖上述已审代码。

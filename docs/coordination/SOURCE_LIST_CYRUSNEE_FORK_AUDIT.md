[本机完整审计](../WEREAD_CLIENT_FLOW_AUDIT.md#L22-L35)已经核对相同 E-Ink 设备类型、版本头、正常扫码、`vid/accessToken`、`GET i.weread.qq.com/mp/chapters?bookId=<目标>&count=20&synckey=0` 无 `offset`。本人同账号目标首屏为 HTTP 499 / 业务 `-2041`；同设备移动 `/login` 成功续期，再发同形首屏仍 `-2041`。本次固定 fork 的列表发送行及传输层与当时审的上游版本逐字节相同，且没有新真实成功响应。因此**不建议仅为验证此 fork 重发目标列表**。这只排除“近期 fork 带来不同列表协议或补足本账号认证”这一具体假设；不证明 `/mp/chapters` 对所有账号或未来时点不可用。

## `steptian/weread-mp` Web 路线核对

固定 [`steptian/weread-mp@e786991`](https://github.com/steptian/weread-mp/tree/e7869918144f592d5cc485946f0bfa0e68737622)。其最后一次源码变动为 2026-05-29 的初始提交；之后至固定版本是同日文档提交。[README](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/README.md)给出使用命令与示例号，但仓库没有附实际脱敏文章数组；核查时公开 issue 列表为空。它的近期性和功能声明不等于本账号当前成功。

1. [Cookie 来源 L67–100](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L67-L100)从本人正常登录的 Chrome/Edge/Brave 浏览器 Cookie 库读取 `weread.qq.com` Cookie，或让用户手工传入；[真正 HTTP 发送 L108–119](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L108-L119)用 `urllib.request.urlopen` 直接请求腾讯 `https://weread.qq.com`，只加 Cookie、桌面浏览器 UA、Accept。代码未设置 `x-wrpa-0`、`x-wr-ticket` 或 `randstr`；没有腾讯第一方页面当前请求签名调用链。它无第三方闭源中转，但脚本默认跟随重定向、异常时可能打印响应正文，不应直接运行在目标实验上。
2. [文章列表 L156–188](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L156-L188)的真实发送为 `GET https://weread.qq.com/web/mp/articles?bookId=<MP_WXS_ID>&offset=0`；后页取本页 `reviews[].createTime` 最小值作为 `offset`。解析 `reviews[].subReviews[].review.mpInfo` 的 `originalId/title/mp_name/time`，`clearAll` 或空页结束。号列表由[本人书架 `/web/shelf/sync`](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L146-L153)给出；代码里所谓“跨号搜索”是在这些号已取列表内逐一筛本地标题，不是额外的腾讯全文或跨号目录端点。
3. [原文 L191–249](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L191-L249)按 `originalId` 请求 `mp.weixin.qq.com/s`，从 HTML 提取文字、封面和页面日期线索；列表中的 `mpInfo.time` 与原文日期未在公开响应中交叉验证，图片实际二进制下载/离线重写未见实现。脚本最大字符数默认 3000，README 称“全文”也需按代码区分展示截断与取文能力。
4. [异常分支 L121–143](https://github.com/steptian/weread-mp/blob/e7869918144f592d5cc485946f0bfa0e68737622/weread_mp.py#L121-L143)只把特定文本或 HTTP 401/403 解释为 Cookie 过期并提示本人重新打开网页登录；源码没有 `/web/login/renewal`、新票据签发或自动续期调用。因此只能随本人正常浏览器会话使用，尚不能证明无人值守定时订阅。

[本机审计](../DEVELOPMENT_HANDOFF.md#L57-L58)记录本人 Web 人工验证后目标 `/web/mp/articles` 仍为 `-2041`，官方 Edge 阅读器自然首屏也为业务 `-2041`；旧脱敏记录**未保存该次官方 Reader 请求头**，所以不能声称它当时一定有或没有新鲜 `x-wrpa-0`。但[当前腾讯第一方页面静态调用链](WEREAD_WEB_TICKET_LIFECYCLE.md#第一方调用链)确实会为相对路径生成 `x-wrpa-0`，验证成功后才临时携带 `x-wr-ticket`。本 fork 只有普通 Cookie，既未给出与旧受限端点不同的路径，也未补出一个可审查的新认证来源。不能以更少的已知头去重发同一目标首屏；同时不能把这项比较写成“Cookie 单独永远无效”或“旧官方 Reader 票据已验证”。

## 2026 Web 列表实现与本账号旧失败的关系

最新 [we-mp-rss 固定提交](https://github.com/rachelos/we-mp-rss/blob/126993c81a00466e9a6bbab041eef34ab27abe9c/core/wx/model/weread_mp.py#L149-L189)实发 `GET https://weread.qq.com/web/mp/articles?bookId=<MP_WXS_*>&offset=<组数>`，头为 Web Cookie/UA/Origin/Referer，已有 ticket 时可附 `x-wr-ticket`，缺 ticket 不挡请求。`get_Articles` [只接受已知 `MP_WXS_*`](https://github.com/rachelos/we-mp-rss/blob/126993c81a00466e9a6bbab041eef34ab27abe9c/core/wx/model/weread_mp.py#L460-L475)，[按顶层 `reviews` 组数推进 offset、遇已入库文章停止](https://github.com/rachelos/we-mp-rss/blob/126993c81a00466e9a6bbab041eef34ab27abe9c/core/wx/model/weread_mp.py#L376-L429)。其[字段映射](https://github.com/rachelos/we-mp-rss/blob/126993c81a00466e9a6bbab041eef34ab27abe9c/core/wx/model/weread_mp.py#L76-L107)把 `reviewId` 作稳定候选键，`mpInfo.originalId` 用来生成原文链接，`mpInfo.time` 优先于 `review.createTime/group.createTime`；这些时间仍需原文 `ct` 校验。[2026-09-04 维护提交](https://github.com/rachelos/we-mp-rss/commit/c0dc66e9ab)称列表“实测可用”且改为增量主路径，2026-09-16 issue #467 是另一使用者取得真实 `reviewId` 的反馈；该提交中的列表用例是 Mock，并未公开本账号/目标号成功回包。

本账号目标旧官方 Reader 已在同一 `/web/mp/articles?bookId=MP_WXS_3895431412&offset=0` 得 `-2041`，旧脱敏记录没有保存是否带新鲜票据。最新 fork **没有不同的列表端点或起始参数**；它的手工保存 Cookie 与可选 ticket 未证明能解释旧失败。目标本来就在本人书架，fork 的“先加书架”也不构成差别。故不能只换这份代码或重复首屏来试；这仅反证“该端点全球永久关闭”。若未来一手证据明确该账号旧失败缺失的合法认证条件，才另审一次低频只读条件；目前不建议重发。列表与封面/正文的访问控制和返回能力必须分别判定。

## 本机可用身份种子与安全边界

只读 `mode=ro`、`query_only=ON` 查询生产 SQLite 的**结构计数**：目标号 194 行，0 行 ID 直接是完整 `MP_WXS_3895431412_...`；38 行含数字后缀形，但与可用的 14 个短链 URL 对照，简单取后缀并把 `~` 还原 `_` 的一致数为 0。本轮检查的 `private-data` JSON/HTML 未检出已保存的 `reviewId` 字段。因此不能从旧 ID、`MP_WXS_*`、搜索 `docID` 或 `doc_url` 猜造 `/web/mp/content` 的 `reviewId`。本机[搜索 URL 诊断](SEARCH_RESULT_URL_IDENTITY_DIAGNOSTIC.md)只保存索引主张；[单篇核验](SEARCH_CANDIDATE_ARTICLE_PROBE.md)没有形成可接收的新原文身份，公开页面的验证路径已停测。

**可交总控复审的唯一新首步**：以现有经私有恢复文件保存的新 mobile token，按已审正常 Web init 在隔离 Cookie jar 换取 Web 会话，核 `wr_vid` 与本人账号一致且无业务/验证错误；随后最多一次 `GET https://weread.qq.com/web/mp/cover?bookId=MP_WXS_3895431412`。选择 `/web/mp/cover` 是 ShelfSignal 正常 BrowserContext 的真实封面路径，与受限 `/web/mp/articles`、旧 `/book/articles` 以及另一个 `/api/mp/cover` 不同。先原子写独立私有 marker；无代理/调试、自动跳转、重试、翻页或原文请求，超时及响应大小有界。输出仅 HTTP/受控业务码、账号名精确匹配布尔、`reviewId` 是否以目标 `bookId_` 开头、标题/图片字段存在性及停止类别；若账号名与目标不符、`reviewId` 不合形、验证码、`-2014/-2041/-2012` 或 HTTP 限制，立即停止。符合门禁才把**原始 `reviewId` 与最小来源身份**在固定私有目录原子保存、公开日志只给摘要；不写生产库，不存 Cookie，不自动接续 `/web/mp/content`。

封面若给可信 `reviewId`，再独立复审最多一次正常 Cookie 下的 `/web/mp/content?reviewId=`。先检查私有封面来源、账号与 marker；只接受腾讯域名和确切参数，限制正文体积，核原文 `biz/mid/idx/sn`、字面 `ct`、`#js_content` 非空、图片引用允许域名；原始 HTML 如需用于离线审查仅私有原子保存，不打印正文或 URL。图片字节要另定逐张有界请求与导出验收。即使封面与正文都成功，也**最多证明目标当前一篇**；必须另有可持续多篇来源才能满足订阅目标。

### 封面单次探针的离线实现

新增 [`probe-weread-web-mp-cover.cjs`](../../scripts/research/probe-weread-web-mp-cover.cjs)。它沿用已审的私有新 mobile token 恢复门禁：正常 Refresh marker、原始生产库与一致性备份/副本的账号和凭据关系；另外以 `readOnly/query_only` 在三份 SQLite 核目标 `MP_WXS_3895431412` 恰一活跃 Feed、准确号名一致。只接受生产库旁固定且由 `.gitignore` 忽略的 `private-data/mobile-refresh-*` 凭据目录；封面哨兵和候选永久写在该项目 `private-data` **根目录**，更换 runDir 不能绕过。预检扫描根目录和既有恢复目录中的同名历史文件，发现任一个便在联网前停止。不会把唯一原始 ID 或已试标记放入 `%TEMP%`。

在线形状固定为隔离无旧 Cookie 的浏览器上下文 `POST /web/login/session/init`（复用旧成功的 `vid/pf=0/skey=accessToken/rt=refreshToken`）至多一次，再在成功业务状态、`wr_vid` 与同账号一致且 `wr_skey/wr_rt/wr_pf/wr_ql` 五 Cookie 均有作用域时，`GET /web/mp/cover?bookId=MP_WXS_3895431412` 至多一次。两个请求都禁自动跳转/重试、代理与调试环境，10 秒超时，JSON 读取上限 64 KiB；无页面导航、列表、正文或图片请求。请求前在固定私有目录用 `wx` 独占创建并 `fsync` 哨兵。HTTP 非 200、验证页、`-2014` 限流、`-2041` 限制、`-2012` 会话错误、非 JSON 立即停止，不换认证或端点再试。若 HTTP 200 返回有界 JSON 且无验证/限制/业务错误，先把**完整原始 JSON** 原子且不可覆盖地存于固定 `private-data/weread-web-mp-cover-target-response.json`，再判定目标号名和 `reviewId` 前缀；未知字段结构同样保留供离线审查，不能因一次解析器不认识就浪费已试请求。只有合法候选才额外把原始 `reviewId`、目标 `bookId`、账号 `vid`、号名与最小标题原子私存。任一写盘失败仅在当前进程保留响应并重试**本地持久化**，不重发腾讯请求；哨兵和原始 JSON 同时纳入后续联网前历史门禁。标准输出只含状态/布尔/计数，不含 Cookie、令牌、`reviewId`、原文 URL、标题或完整 JSON。

`--plan`、`--self-test`、`node --check` 均通过，假网络覆盖成功路径、初始化 401、封面 `-2014`、恰好一次 init+cover、候选和原始 JSON 原子文件不覆盖、HTTP 200 未知结构先私存后停止、原始 JSON 首次写入失败后仅本地重试及日志不含假秘密。以现有生产库和私有恢复文件执行 `--preflight` 得 `preflight_ready/sourceAndBackupMatched=true/targetFeedMatched=true/existingCoverHistory=false/networkRequests=0/productionWrites=0`。**尚未执行线上模式**；总控复审后才决定是否发这一次。执行参数必须是绝对路径：

```powershell
node scripts/research/probe-weread-web-mp-cover.cjs --preflight --db <生产 SQLite> --run-dir <既有 private-data/mobile-refresh-* 目录>
node scripts/research/probe-weread-web-mp-cover.cjs --execute --db <生产 SQLite> --run-dir <同一私有目录> --playwright-core <已审 playwright-core 路径> --browser <Edge/Chrome 可执行文件路径> --approved-online
```

## 检索边界

已核上述三个固定 GitHub 实现、KOReader 验证脚本、ShelfSignal canary 与 we-mp-rss 提交/使用者 issue；另核本仓已有官方 Gateway 能力记录。官方 Gateway 的书籍章节 shard 与个人 `/review/single` 不能在现有证据下当成任意公众号原文接口；封面、搜索与书架也均不返回账号完整正文列表。未发现可把仅有 `bookId` 或搜索 `docID` 直接、可靠地变成正文和图片的当前腾讯一手请求。这个边界不排除后续出现新的正常客户端实现或可复核成功样本。

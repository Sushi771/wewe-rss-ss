# 目标旧文章单张图片字节与离线附件专项（2026-09-30）

## 选择与门禁

只读打开生产 SQLite，`quick_check=ok`，仍为 12 个订阅、1447 篇文章。目标号有 20 篇同时具备已核验完整原文链接和缓存正文；本专项选择其中一篇正文仅含一张允许的腾讯 HTTPS 图片的旧文章。文章四字段摘要为 `175910fb92f9e063`，图片 URL SHA-256 前 16 位为 `862f10b2324802c9`。它与此前 2026-09-30 的已请求原文摘要不同；图片未在其余 19 篇核验长链的缓存正文或本机 12 份已保存目标 HTML 中复用，对应尝试哨兵此前不存在。这只界定本机可查材料，不能证明所有历史环境从未访问该图片。

[`probe-target-image-byte.cjs`](../../scripts/research/probe-target-image-byte.cjs) 在联网前重新核对唯一目标号、官方原文四字段摘要、单张图片摘要、允许域名、SQLite 一致性和历史哨兵。`--dry-run` 仅读数据；`--self-test` 用合成小 PNG 在 SQLite 一致性副本跑完整归档和导出，外部请求为零。两项均通过后才运行 `--online`。探针限定一次匿名 HTTPS `GET`、不使用代理、Cookie 或授权头、不跟随跳转、不重试，10 秒和 10 MB 上限；先原子写入仅有摘要的私有尝试哨兵。完整 URL、文章标题、正文、凭据及原始图片均未写入日志或 Git。

## 真实图片结果

唯一一次 GET 返回 HTTP 200、`image/jpeg`，完整接收 **530,349 字节**；响应 `Content-Length` 与接收量相等，JPEG 开始和结束标志均有效。图片字节仅在进程内持有，并在临时一致性副本及临时附件中参加演练；进程结束删除临时库、附件和 ZIP。尝试哨兵保留，以阻止同一 URL 重发。未请求这篇的当前原文页面，缓存正文是此前保存的数据。

## 副本归档与导出

使用 SQLite `backup` 建立一致性副本，且仅在副本应用生产库尚未应用的既有 `provider_refresh_attempt_time` 迁移。把刚取得的真实图片字节以离线 `fetch` 注入现有 `archiveProviderImages`，实测只发生一次该函数内部图片读取，得到内嵌 `data:image/jpeg` 的正文；随后的导出阶段全部禁网。只更新副本中这篇的 `content_html`，其他旧文章正文不动。

副本演练验证：1447 篇文章仍在，除目标篇允许的图片归档正文变化外，所有文章字段的排序摘要完全一致；目标篇 ID、可信发布时间、来源、已核验来源、封面、阅读/点赞与完整指标均未变，`quick_check=ok`。现有 `saveToObsidian` 生成相对路径 `attachments/` 引用，附件字节与真实响应相等。为避免对目标号其他尚未归档图片发请求，在**第二份临时副本**仅保留目标单篇用于 `buildOfflineFeedDirectory`；它报告 1 篇完整、0 篇未完整。使用控制器同款 `ZipArchive` 打包并以 Python `zipfile` 校验压缩包、Markdown 相对路径及附件 SHA-256，均通过。

这证明**一张已缓存旧文章图片**的完整字节和该篇的 Obsidian/限定单篇 ZIP 离线附件可用。它不证明其他 125 个旧图片引用、其他文章正文、整个公众号 ZIP、HTTP 下载/私人登录、当前原文获取、自然增量或全号订阅恢复。生产 SQLite 没有写入，也没有启用生产采集。

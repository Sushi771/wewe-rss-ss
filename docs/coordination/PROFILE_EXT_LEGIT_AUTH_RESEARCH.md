# `profile_ext?action=getmsg` 合法认证签发链核查（2026-09-30）

## 问题与证据门槛

本轮只问：本人通过正常网页登录、微信授权或公开页面，能否**合法、可续期地**取得 `mp.weixin.qq.com/mp/profile_ext?action=getmsg` 当前所需的个人微信读者会话。旧实现有 `uin/key` 与 `appmsg_token` 等不同参数组合，本轮不预设四者必须同时出现。`uin`、`key`、`pass_ticket`、`appmsg_token` 同名字段出现在页面或另一产品中，不等于该产品签发了可供 `getmsg` 使用的整套会话。须同时追到签发或读取代码、真实腾讯请求、续期和近期带凭据成功回包，才值得设计一次隔离探针。本轮仅审公开源码与一手说明，未读取私人凭据、未请求 `getmsg` 或猜测字段值。

## 近期实证与当前决策

[2026-08 fork 的未结 issue #15](https://github.com/vmxmy/wechat-article-exporter/issues/15)只确认**无凭据** `getmsg` 返回 `ret:-3/no session`，把“带有效个人凭据是否返回 `general_msg_list`”列为待验证，并明确说其计划的凭据路径是客户端流量。另一个 [2026-09 的实现者 spec](https://github.com/joimjnbg/wechat-downloader/issues/23)也把自动历史列举记为受个人微信会话门槛所限，转做用户提供文章 URL 的列表。这是各实现的范围内观测，不是证明该接口永久失效。

本轮**未找到**符合当前项目边界、能从正常网页登录／授权持续签发完整个人读者历史会话的一手链，亦无 2026 年合法浏览器会话带凭据的目标或其他号成功回包。因此不设计 `getmsg` Probe，也不要求用户交出已有私有凭据。排除范围仅为上表具体实现、令牌转换和采集方式；后续若出现腾讯第一方正常登录返回所需字段的公开源码，或近期 fork 公开了合法续期与真实 `general_msg_list/next_offset` 回包，可复审一次低频、只读、隔离请求。字段不完整、旧网页微信仅签部分票据、公开页面导航或 `ret:-3` 本身均不足以触发请求。

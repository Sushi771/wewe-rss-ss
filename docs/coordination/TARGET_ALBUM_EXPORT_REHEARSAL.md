# 目标合集正文与离线导出：SQLite 副本演练（2026-09-30）

## 输入和边界

本轮沿用[目标合集首屏与原文身份核验](TARGET_ALBUM_PROBE.md)、[既有列表副本演练](TARGET_ALBUM_REHEARSAL.md)及现有[隔离导出测试](../../apps/server/src/collection/collection.service.spec.ts)，只补它们之间尚未实测的六篇**真实旧原文**导出路径。输入是 2026-09-27 保存的“复旦数学营”官方 10+9 条 JSON、六份与该合集身份/原文时间精确匹配的旧 HTML，以及生产 SQLite 的**只读一致性副本**。旧 JSON 的 19 个排序文章键摘要与 2026-09-30 在线两页记录一致；这里仍是旧响应回放，**没有再次请求腾讯**。源库及副本复制前、演练后 `quick_check` 均为 `ok`。临时库、导出文件和 ZIP 只在系统临时目录创建并在进程结束时删除；没有输出或提交原文、标题、完整 URL、图片链接、凭据、数据库或私有路径。

隔离运行将 `axios.get` 限定为内存中的两页旧合集 JSON，所有其他 Axios 请求直接拒绝；`fetch` 一律拒绝，阻止图片字节下载。演练实际模拟了 **2 次合集页读取、0 次原文 GET、0 次外部网络请求**。它调用当前构建的 `CollectionService.collectPublicAlbums`、`FeedsService.renderFeed`、真实 tRPC Markdown/Obsidian 导出、`buildOfflineFeedDirectory` 与同款 ZIP 打包器，检查的是应用路径，不是仅将 HTML 拼成演示字符串。没有启动服务或调用 ZIP HTTP 控制器。

## 结果

| 环节            | 离线副本结果                                                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 列表采集        | 2 页、19 个不同键；新增 0、更新 19、合并 0；全库仍为 12 个订阅、1447 篇文章                                                                           |
| 旧数据保护      | 原有文章 ID 缺失 0；非空正文变更 0；已核验原文时间/来源变更 0；完整 metrics 与阅读/点赞字段变更均 0                                                   |
| 六篇旧原文      | 6/6 HTML 与合集稳定身份、标题、`sn` 和原文时间核对通过；采集后 6/6 对应记录已有缓存正文，**本轮没有新填正文**                                         |
| RSS             | 限定六篇的真实全文章渲染产生 6 个 item；6/6 `guid` 对应已存来源、6/6 有正文，正文内含 28 个腾讯图片**引用**                                           |
| 浏览器 Markdown | 6/6 有正文；28 个图片引用转成应用图片代理链接，浏览器后续读取仍依赖图片来源或代理可用                                                                 |
| Obsidian        | 无图的 1 篇可保存；有图的 5 篇在禁网时因缺图片字节正确报未完成；没有把远程 URL 当作本地附件成功                                                       |
| ZIP             | 仅在副本中把目标号其余文章排除，限定此合集 19 篇后，离线目录完整 1、未完整 18；ZIP 有 51 个条目，`README.md` 存在、压缩包校验通过，未完整文章明确标记 |

ZIP 的 18 篇未完整包括已有正文但图片字节未归档者，以及尚无缓存正文者；禁网期间图片抓取被拒绝的尝试共 28 次，**没有一次实际外部图片请求**。真实产品的 `/download/feed/:id.zip` 按整个公众号 `mpId` 打包，当前没有按合集筛选；本轮为了测这 19 篇，才在**第二阶段副本**里排除该号的其他文章。ZIP 文件结构通过不等于图片可离线阅读，也不等于现行 HTTP 控制器或私人线上认证链路已验收。

六条对应记录保留旧短链文章 ID，`verified_source_url` 均为空；当前 `bodyRetryAvailability` 对它们 **6/6 拒绝显式原文重试**。这符合现有“旧 ID 必须有独立已核验绑定才能重试”的安全门禁；因六篇已有缓存正文，本轮未放宽门禁、未伪造绑定。合集列表采集只写列表元数据，并不会自动把这六份旧 HTML 或未来新文章的正文写库。若未来需补回这些旧 ID 的正文，应先设计可审计的原文身份绑定与副本回归；不能因标题或合集 `create_time` 接近就放行。

## 验收范围

本结果证明：对已保存且有缓存正文的六篇目标旧文章，现有 RSS 和浏览器 Markdown 能输出正文与图片引用，采集回放未覆盖旧 ID、正文、可信时间和指标；没有图片字节时，Obsidian 与 ZIP 会保持明确的未完成状态。它**不证明** 28 张图片今天可完整下载、其他 13 篇有正文、未来新文章会自动补正文、第二合集或全号历史已覆盖、持续更新可用，也没有用旧 HTML 充当 2026-09-30 新取回文章。后续在线验证须先在合法授权下取得单篇原文及图片，再按身份与原文时间核验，并在副本中重跑相应导出；遇官方验证或限制即停。

# 其他目标旧文短路径的离线排重门禁（2026-09-30）

本轮网络请求 **0**、生产 SQLite 写入 **0**。结论：**没有一篇能够独立证明短路径尚未请求的唯一旧文候选；本轮停止，不生成或运行原文探针。** 这只是当前请求历史的证据缺口，不是官方短路径或公开合集发现能力失败。

## 只读候选范围

用 Python `sqlite3` 的 `file:…?mode=ro` 与 `PRAGMA query_only=ON` 读取生产 `articles` 中目标号 `id/source_url/verified_source_url/publish_time`，`PRAGMA quick_check=ok`。仅计数，不输出文章身份、标题、URL 或时间原值。每条候选须满足：原存 `source_url` 为官方 HTTPS `/s/<22 字符 token>`，无 query/fragment；`verified_source_url` 为官方 HTTPS `/s`，查询恰有各一次 `__biz/mid/idx/sn`，账号与目标相符；旧规范文章 ID 的消息/次条与长链一致；旧 `publish_time` 为非空、合理秒值。结果如下：

| 严格短/长身份配对且有旧时间的行 | 14 |

| 余下“未见已提交短路径请求”的配对旧行 | 11 |

14 行的旧时间是库内既存可信时间**对照值**，本轮没有重新取得当前页面字面 `ct`；不能拿它或已缓存正文证明今天可读。先前官方两合集旧 JSON 已丢，本轮也不能重新计算这些 14 行与任何合集的成员交集。生产库中其他旧行可能有短路径但缺严格长身份，均未纳入候选。

已提交 [`PUBLIC_PAGE_DISCOVERY.md`](PUBLIC_PAGE_DISCOVERY.md) 逐次记录三篇不同旧文的短路径 HTTP 200 与四字段、短 canonical、字面 `ct`、正文闭环；其中一篇后来由官方首屏证明属于第三合集。最近一次的私有持久哨兵仍在，另两次原来的 `%TEMP%` 尝试标记已丢。此次检查系统 `%TEMP%` 顶层相关文章尝试标记为 **0**，私有持久短路径标记为 **1**；因此仅靠目录现状会把已知请求误判为“从未尝试”。这也表明对余下 11 行，**没有哨兵不是排重证据**。

现存报告能证明三条已经请求，不能为余下每条提供覆盖整个项目历史的未请求证明。对 11 条排序、挑最新日期、或挑一个没有文档摘要的旧行，只会形成“未找到记录”的候选；无法满足本任务要求的“独立证实短形状尚未尝试”。已保存目标旧原文曾有页面内官方合集标签，但不能据此推断这 11 篇任一篇今天仍有标签，也不能把它们算新发表文章。

## 放行所需的不同证据

在新增 `public-old-shortpath-album-discovery.cjs` 前，须先有**该具体短路径**的正面排重依据：恢复原始、覆盖对应时期且可核完整性的私有请求账本/哨兵，或取得另一条能证明该 URL 首次出现于已知请求窗口之后的合法一手记录；再用 URL 摘要及短/长形状与全部已提交请求记录逐项比对。单纯恢复空目录、仅有旧库配对、或只检查某一个现存工作区均不足。此条件目前没有满足，故没有唯一可审候选，也没有制作可误放行的在线脚本。已有独立的带签名合集原文入口研究仍可继续，见 [`THIRD_ALBUM_LONG_URL_COMPARISON.md`](THIRD_ALBUM_LONG_URL_COMPARISON.md)。

若后续获得上述排重证据，再按用户门禁设计一次性脚本：只读复核生产库与一致性备份、唯一旧身份及 `publish_time`；先在 Git 忽略持久目录排他并同步保存不含 URL 的尝试记录；仅对**旧库存原样短路径**发一次匿名、无代理/Cookie/跳转/重试的 HTTPS GET，限时限量，3xx、验证、403/429 即停。HTTP 200 的有界 HTML 应先不可覆盖地私存，再核当前 `biz/mid/idx/sn`、短 canonical、字面 `ct`、严格正文和图片；只有当前原文身份闭环，才静态解析页面自身明确声明且同号的官方合集标签，并把精确标签及原始 HTML 留在私有持久目录。输出仅布尔、计数与摘要。即使成功，也只验证一篇**旧文**是否可作为发现来源；合集列表、五篇新样本与持续更新须另验。

# Web renewal `-2013` 的公开源码核查（2026-09-30）

## 结论与实验边界

本轮只匿名读取腾讯公开 HTML/JS、GitHub 固定源码与提交记录；未读取私有凭据、数据库或原始实验文件，未发送目标号、登录或续期请求，未计算签名。实验事实引用已提交的 [单次 Probe](WEREAD_RENEWAL_TICKET_PROBE.md)：mobile→Web init 下发五项同号 Cookie，随后唯一固定 `ql=false` renewal 返回 HTTP 200、`errCode=-2013`，没有 Set-Cookie、`x-wr-ticket` 或 `x-wrpa-0`。`succ` 未记录，不能补成 0。

**当前公开第一方 Web JS 没有把 `-2013` 列入通用请求自动续期的触发码。** 它确实在微信平台的页面错误及退出处理里将该码与 `-2010/-2012` 并列，但这不是 renewal 服务端错误定义。开源 K4 fork 有“有替换 skey 为 stale、无替换 skey 为 expired”的实现和模拟测试；其“官方”来源描述未提供本轮可核的腾讯原始代码，不能升级为官方语义。本次失败不证明全部会话永久失效，也不证明所有自建路径失效。

## 第一方资源版本和真实调用

`-2041` 验证码分支与上述 renewal 分支独立：本人完成腾讯验证后才获得 ticket；`x-wrpa-0` 是请求时第一方 JS 调用产物，详见 [生命周期](WEREAD_WEB_TICKET_LIFECYCLE.md)。本轮未发现 renewal 响应签发这两个头的第一方代码或成功实测证据，不能以 Cookie 续期替代票据生命周期。

## 开源源码交叉核对：哪些是实现，哪些是实测

1. [finlater 固定提交 `dfdc200` 的 client.lua:555–584](https://github.com/finlater/weread.koplugin/blob/dfdc200cbf4ceaca0a72c8c14763aaec80ec386f/weread/lib/client.lua#L555-L584)实际 POST renewal，固定 `rq=%2Fweb%2Fbook%2Fread, ql=false`；先检查成功响应，再合并 Cookie，有头才保存 ticket/WPA。本轮重新读取这些行，与本项目唯一 Probe 形状相符，没有独立 `-2013` 修复链。已有 [专项证据](WEREAD_RENEWAL_TICKET_EVIDENCE.md)中的 issue #62 和 weread-bot #44 仍只分别说明 Cookie 续期后 MP 可被挑战、HTTP 200 可无新 skey，不能解释本次 `-2013`。
2. 本轮核定 [dororo42/weread_K4.koplugin HEAD `16f6050`](https://github.com/dororo42/weread_K4.koplugin/tree/16f6050c6807992b46313543e93834b2c170c711)。[client.lua:526–619](https://github.com/dororo42/weread_K4.koplugin/blob/16f6050c6807992b46313543e93834b2c170c711/weread/lib/client.lua#L526-L619)仍发同一固定 renewal 形状。注释声称借鉴 reMarkable 官方客户端四态；实现对 HTTP 成功但业务拒绝检查 Set-Cookie 是否包含 `wr_skey=`：有则先存新键、判 stale，无则判 expired。**该实际 else 分支没有限定必须为 `-2013`**，因此它是客户端分类策略，不能当所有业务码的腾讯定义。
3. [引入分类的提交 `c7699f9`](https://github.com/dororo42/weread_K4.koplugin/commit/c7699f928b00ff53d9ac99df9047e24cbf1af644)提交说明明确描述上述条件。[模拟测试:174–240](https://github.com/dororo42/weread_K4.koplugin/blob/16f6050c6807992b46313543e93834b2c170c711/spec/remarkable_borrow_p1_spec.lua#L174-L240)人为构造 `errCode=-2013` 的带键与不带键响应，没有真实腾讯回包。它只验证 fork 按作者策略运行。本次无 Set-Cookie 会被该实现判 expired，**这不是本次服务器明确说明“登录过期”**。
4. [该版本 README:164–190](https://github.com/dororo42/weread_K4.koplugin/blob/16f6050c6807992b46313543e93834b2c170c711/README.md#L164-L190)称依据根目录《K4*remarkable官方v1.0.0*网络通信与时长统计借鉴评估》v2/v3，并区分原生 accessToken 通道与 Web 通道。首次公开递归 tree 中按 remarkable/official/borrow 只定位模拟测试；后续扩大文件名查询触发 GitHub 匿名 API 速率限制，停止 API 查询，未以私有 token 绕过。未取得该评估及所引腾讯代码的可核版本、真实发送行和成功续期日志。因此保留来源待核，不复刻设备标识、UA、签名或探测原生续期。

网页检索 `github weread "-2013" renewal`、`"STALE_SESSION_RESPONSE" weread` 与 remarkable 客户端来源，定位上述 K4 作者说明，未定位腾讯对 Web renewal `-2013` 的正式错误码文档。检索覆盖有限；搜索结果中“官方客户端借鉴”的标题不改变源码归属。此处不作“没有官方文档所以无解”的推断。

**当前没有足够新证据授权另一次手工 renewal 请求。** 换 `ql/rq`、恢复目录、Cookie 子集或客户端仍属无依据变体，同形哨兵保留。若后续公开第一方代码/维护者可核成功记录明确展示一种正常签发条件、其续期真实请求与成功字段，且能在本项目不监听、不重放签名的边界下取得本人新会话，才由总控另行设计一次隔离只读验证。验证仅记录 HTTP、受控业务码、明确 success/succ、Cookie 名与头存在性；遇拒绝立即停，不写生产库。

要提出“可持续认证路径”，还需要跨自然过期周期的正常低频续期证据、凭据轮换及失效停止规则，并独立完成五篇目标真文章、身份、发布时间、分页、正文、图片和更新验收。第一方请求条件与开源模拟测试都不能代替这些真实结果。本轮结论仅缩小 `-2013` 的可解释范围，保留其他独立公开来源研究。

# 微信读书 Web 续期 `-2013`：第一方调用链与证据边界（2026-09-30）

## 范围与结论

本次只读腾讯公开静态客户端和本仓库已脱敏的[单次续期记录](WEREAD_RENEWAL_TICKET_PROBE.md)；没有读取私有凭据，也没有发出登录、续期或目标列表请求。当前**找不到腾讯对 `/web/login/renewal` 返回 `-2013` 的公开精确定义**。第一方客户端将同一个数值与若干登录相关错误并列处理，但这不能区分 Cookie 生命周期、登录方式、参数、设备环境或服务端策略。

真正新增的可验证差异是：腾讯 Web 客户端在普通请求遇 `-2012` 或 `-2010` 后才自动续期，续期参数 `rq` 来自**出错的原请求路径**，`ql` 来自 Cookie `wr_ql` 是否等于字符串 `1`。官方快速微信登录回调用 `ql=1` 初始化会话，另一登录分支用 `ql=0`。本仓库此前移动凭据恢复实验在 Web init 时**省略 `ql`**，接着独立向固定 `rq=/web/book/read` 发 `ql=false`；脱敏结果只记录 `wr_ql` 这个 Cookie **存在**，没有记录其值。因此该 `-2013` 只属于这次会话与请求形状，不覆盖腾讯快速微信登录会话或第一方自然触发的续期。不要在旧会话上仅翻转 `ql` 重发。

## 与已做实验的逐项对照

| 条件       | 第一方可见路径                              | 已做隔离实验                                                                                                                                    |
| ---------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Web 初始化 | 登录结果含显式 `ql=0` 或快速微信登录 `ql=1` | 本人既有移动恢复凭据映射后 `POST /web/login/session/init`，体含 `vid/pf/skey/rt`，**未传 `ql`**。服务端返回五种 Cookie 名；私有值未记录在文档。 |
| 续期触发   | 原 GET/POST 先返回 `-2012/-2010`            | 完成 init 后直接独立续期，没有先执行并失败的原业务请求。                                                                                        |
| `rq`       | 实际失败请求的路径                          | 固定编码值 `rq=%2Fweb%2Fbook%2Fread`；该实验没有发 `/web/book/read`。                                                                           |
| `ql`       | 取 `wr_ql==='1'`                            | 固定 `false`；脱敏结果不包含 `wr_ql` 值，无法证明与服务端 Cookie 相符。                                                                         |
| 结果       | `succ=1` 或特殊 `-12013` 才重试原请求       | HTTP 200、业务 `errCode=-2013`、无 Set-Cookie、无两种候选票据响应头；`succ` 未记录；目标列表 0 请求。                                           |

上表“`rq`”在 JSON 中实际是编码后的 `%2Fweb%2Fbook%2Fread`，不是把 URL 整体当成要访问的地址。实验的限界是**移动恢复→Web init→独立固定续期这一形状本次没有成功**；不能扩大成腾讯 Web 续期永久不可用或目标公众号列表不支持。反过来，第一方有不同调用链也**不能**预测另一次请求一定成功。

## 下一次验证的证据门槛

1. 仅当本人通过腾讯正常页面完成所需扫码、验证码或新账号登录，且有新的合法 Web 会话时，才考虑另一次隔离只读验证。先确定该会话是快速微信登录 `ql=1` 还是其他 `ql=0` 路径，并仅保留 `wr_ql` 是否与客户端续期布尔值一致的**布尔结果**；不保存 Cookie 值或请求票据。
2. 按第一方自然流程，选择一条有合法访问权的非目标普通 Web 请求作为触发上下文；只有它自身出现 `-2012/-2010`，才由第一方逻辑考虑续期。不得为制造错误而损坏 Cookie、猜参数，亦不得绕过验证码。记录 HTTP 状态、脱敏业务码、`succ` 是否出现及值、Set-Cookie 名称；如果自然请求本来成功，停止续期实验。
3. `-2013` 的精确服务端含义在源码与公开一手样本均未证实；要明确它，需要腾讯官方定义或带原始端点、登录路径、请求形状和脱敏返回的可复核成功/失败对照。旧移动恢复会话的同形哨兵继续有效，不改参数重试。
4. 即使不同会话的续期成功，仍只证明 Cookie 延续。目标 `/web/mp/articles` 的身份、五篇真实文章、可信发布时间、分页、正文图片、无人值守持续更新都需各自验收；人工验证码票据不能直接当长期后台凭据。

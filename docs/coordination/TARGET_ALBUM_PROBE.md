# 目标号公开合集首屏隔离探测（2026-09-30）

## 已有身份依据与本轮边界

2026-09-27 的一手记录已从目标号真实原文找到“复旦数学营”的官方合集，并将文章原文、目标 `__biz` 与该合集对应起来，见 [公开合集验证与短长链核验](../CHANNEL_INVESTIGATION.md)。因此旧 [公开来源研究](RESEARCH_WECHAT_PUBLIC.md)中“目标没有 `album_id`”及相应状态文字已过时。本轮只验证该已知合集的当前首屏；旧 32 篇列表和旧 HTML 不计入本轮新样本。

在独立工作树从本机 `main` 的 `06e2e5e` 建立 `codex/target-album-probe`，原 `codex/probe-runtime` 分支及提交保留。只进行一次无 Cookie、无 Key 的目标官方合集 JSON GET：请求级禁用代理、禁止跳转、无自动重试，未改变系统代理。没有请求下一页、原文或第二合集，也没有访问或写入生产 SQLite。未保存原始响应、文章标题、正文、完整 URL 或凭据。

静态检查本机 2026-09-27 首屏 JSON 的**字段结构**发现业务码位于顶层 `base_resp.ret`，旧样本该值为 `0`；本轮探针误先取缺失的 `getalbum_resp.base_resp`，没有回退到顶层。旧值不能替代本轮状态。旧样本还表明 `getalbum_resp` 可含 `verify_status`，但本轮未提取其值。本轮进程只留下上述聚合统计，没有留下 10 个稳定文章键的摘要或末项游标，因此不能把本轮 10 条与旧首屏逐篇精确比对，也不能从数量和时间范围推断两次列表相同。

## 可判别的下一步

首屏提供了当前目标号至少 10 个不同列表身份和目标 `__biz` 匹配证据，但 `create_time` 仍只是合集字段。2026-09-27 已发现它与原文时间可相差数十秒；逐篇**原文发布时间**尚未核对，不能将本轮称为五篇发表时间验收完成、全号历史覆盖或持续订阅恢复。

总控复审后，如需判断首屏状态与旧首屏是否完全相同、并准备安全翻页，应另做一次低频首屏探测，正确提取顶层业务码与业务验证字段，只保存排序后的 `(msgid,itemidx)` 集合摘要及末项分页游标等脱敏信息；再按独立步骤核对原文发表时间和分页。遇明确验证或限制立即停止。

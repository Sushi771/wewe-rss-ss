# 已受理订阅的缓存接续

提交订阅和同步缓存分别计数。已有受理回执的接续只读取对应缓存，不重复添加，也不强制更新。缓存任务串行执行；五分钟读取窗口从该任务首次执行开始，排队时间不消耗窗口。首次执行时间持久保存，重启不延长窗口，最多十次读取。

读取失败保留固定安全分类，区分供应商读取、本地数据库引擎、数据库超时、旧正文图片身份冲突和未核图片。原始错误、SQL、路径和凭据不返回前端。成功后清除上一次失败分类，避免显示已经过期的错误。

供应商返回正文并不证明图片完整。没有源地址的图片标签不能当作已保存图片，也不能仅凭类名认定为空占位图。正文可靠而媒体未确认时，保留订阅与已核正文，返回 `CACHE_IMAGES_PENDING`（正文已同步；媒体完整性未确认）及未核项数量。该数量不等于已证实丢失图片数，不把整条订阅报为添加失败。原正文和编辑保留；图片取得失败时保留可核验的原图片地址，后续仅精确匹配补图，不覆盖正文文字。

媒体未确认的正文持久标记为 `images-pending`。可靠正文及可取得的有效图片仍可保存；Markdown 与保存回执明确说明媒体完整性未确认（`mediaComplete:false`），不把已保存文件称为原篇全部媒体归档。原始缓存证据保留，无源标签不计入已保存图片数。仅当失败图片的真实字节已补回且没有未知缺图标记时解除；不能以清理标签后的图片数量冒充原篇完整。部分正文或图片未通过时不推进完整同步时间。旧文章身份未核实仍保持隔离，不按标题或顺序合并。

如供应商原缓存没有图片地址，当前工程无法补出真实图片。需要供应商提供完整原缓存，或用户核实后接受该篇的实际缺失范围；不能将缺失标签当作成功，不能自动从其他正文渠道补抓。

## 本地缺图补齐

后台继续使用现有独立媒体队列，列表同步不等待图片下载。`WECHAT2RSS_CACHE_MEDIA=0` 是媒体暂停开关；恢复为 `1` 后，正常白天缓存任务可继续补图。北京时间 00:00–06:00 不开始媒体请求，等待限速间隔后也会重新检查时段。服务重启后从已订阅缓存重新建立任务，不重新添加订阅。

补齐只使用原文章身份及精确图片来源匹配，只请求已保存正文中仍缺失的图片。现有内嵌图片和用户正文、样式、指标保留。单轮共享来源只请求一次；部分成功字节可保存，下一轮仅重试剩余来源。无法匹配的文章保持隔离；无来源的未知缺图标记继续显示，不清状态伪造完成。写前备份与原有条件写入守卫继续生效；用户已修改后清空的正文不自动填回。

图片 CDN 返回 401、403 或 429 时停止整个后台媒体队列，列表同步继续。SQLite 同目录的私有 `.wechat2rss-media-blocked.json` 保存停止原因和时间，跨服务重启保持；它不含图片地址或凭据，不提交 Git。仅在人工核实限制解除后才可移除停止标记并重启；不自动过期，不通过更换请求方式绕过。

完成状态结合已保存正文中的实际远程图片/缺图标记；上游图片受限数量、历史状态和本地未完成文章数分别解释。离线测试和构建通过不代表真实图片已经下载；真实补齐须在允许时段验收。

同一上游内容指纹不再代表本地媒体完整。每次正常缓存复核先只读 SQLite 的正文/逐个图片标签标记；已内嵌图片的旧 `data-src` 不计缺图，未嵌入的 `data-src` 仍计待补。只有三个完成计数明确为零才报告 `synced-cache`，缺字段继续待补；健康缓存不重复下载或写入列表。

风控结果先于快照替换判断生效。归档遇到限制时立即设置共享停止状态并持久保存，再进入文章事务；事务失败不能恢复媒体请求。每次请求前检查操作暂停、跨工作器停止标记及夜间时段。停止存储不可用仅关闭媒体，列表缓存继续。保存正文的条件更新及用户编辑保护仍生效。

人工批准的一次修复可通过内部离线维护入口传入 `nightMediaUntil`，有效期最多 30 分钟；普通 HTTP 刷新和定时队列不接受此参数。它不能解除操作暂停或风控停止，也不改变 00:00–06:00 默认规则。维护必须停止已核验的服务进程、验证一致性备份并持有批次锁，只使用已核实文章身份与原图片地址。无来源占位及来源冲突继续报告未完成；终态订阅任务不作为图片已齐的证据。私有清单、备份和运行日志不得公开。

# 微信读书自建订阅：证据缺口与首个验证（2026-09-29）

## 目标与证据级别

目标是让本项目拥有可审查、可自行构建部署的订阅核心，运行时只与微信读书或文章原站交互，不依赖第三方开发者的闭源中转或授权服务。现有 Provider、私人登录、SQLite 保护、正文图片和 ZIP 导出继续保留。**下列公开项目的成功案例不是本账号、本目标号的验收**；本地历史实验以 [完整客户端审计](WEREAD_CLIENT_FLOW_AUDIT.md)及其引用的脱敏记录为准。

### 下一条源码线索：`/book/articles`，认证来源待核验

[固定源码 `WeBook.get_urls`](https://github.com/wnma3mz/wechat_articles_spider/blob/f8b31196e88045d079901812ea064ad4953d62a6/wechatarticles/ArticlesUrls.py#L654-L718) 对 `MP_WXS_*` 调用 `GET i.weread.qq.com/book/articles`：传入数字后缀 `3895431412`，源码组装 `bookId=MP_WXS_3895431412`、`count=20`、`offset=0`、秒级当前时间 `synckey`，并取 `reviews[].review`。源码发送自定义 `skey`、`vid` 头，但仓库没有获取这两个凭据的登录代码或调用示例；`Cookies` 是复数头，不能视为标准 `Cookie`。源码中的 WeBook 实现始于 2021 年，不能把项目 README 截至 2023-03 的说明当作该实现近期维护。[固定版 Eink 2.1.2 端点目录](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/docs/endpoints.md#L319-L324)仍将 `/book/articles` 列在 ArticleService，与旧 `/mp/chapters` 的 MPListService 不同，但 SDK 标为未使用，也没有给出当前认证或成功回包。路径和服务类差异足以继续调查；**不要求先找到别人近期成功五篇回包才允许实验**。

认证不能混用：官方 Gateway 用 `wrk-` Key；本机生产账户保存的 `wr_skey` 与 `accessToken` 值相同，来自现有 Web 登录代码的赋值；旧客户端使用移动登录返回的 `vid/accessToken`；WeBook 旧实现要求 `skey/vid` 自定义头。现有源码未证明前三者能作为 WeBook 的 `skey`。2026 年[客户端登录解析](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/src/auth/token.ts#L913-L994)与[请求头](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/src/profile.ts#L294-L307)也只明确 `accessToken`，没有给出旧 `skey` 的转换依据。只有核对到本人合法取得、适用于该接口的 `skey/vid` 来源，才用源码已给的请求形状做一次低频隔离只读验证；先只看是否有真实 `reviews` 条目及字段名。若发生认证拒绝、验证码或频控，立即停止该流程，不轮换或猜头。

[we-mp-rss 的 `/api/mp/cover` 兜底实现](https://github.com/rachelos/we-mp-rss/blob/main/core/wx/model/weread_mp.py#L1565)只读最新一篇，且[入库逻辑](https://github.com/rachelos/we-mp-rss/blob/main/core/wx/model/weread_mp.py#L1706)将 `create_time/update_time` 设为抓取时刻，不能作为文章真实发布时间，也不能满足五篇门槛。

## 已验证候选：官方 `/book/chapterinfo`

**具体假设**：官方 Gateway 的 `/book/chapterinfo` 对目标 `MP_WXS_3895431412` 返回至少五条 `isMPChapter=1`、不同 `chapterUid` 的真实文章目录。支持依据是官方文档明列公众号章节标志；反对依据是文档没有给 `MP_WXS_*` 成功样本，且章节目录可能对公众号不开放。这个实验与旧 `/mp/chapters`、`/web/mp/articles` 的入口和认证模型均不同，能够检验官方 Gateway 对本账号/目标号的目录能力；失败只能排除这一候选在当前条件下的目录假设。

隔离探针 `scripts/probe-weread-gateway.cjs` 从本机私有 `.env.weread-gateway` 或进程环境读取本人官方 Key；没有 Key 时零网络请求。先至多一次只读 `/book/chapterinfo`；若有足够候选条目，再至多一次 `/book/info` 核对号身份。请求超时、业务错误、验证提示或版本变更即停，不自动重试、不保存原始响应、凭据或生产数据。只记录脱敏状态、条目数、去重结果及字段存在性。用户自行正常登录/领取 Key，绝不在聊天发送 Key。

**2026-09-29 本人授权实测**：用户将官方 Key 放入 Git 忽略的私有文件。第一次在受限网络中于传输层失败，没有 HTTP/业务响应；DNS 可解析但本机受限环境无法连接 443。随后在允许联网的隔离进程中执行一次正式 `/book/chapterinfo`：业务无错误、回包 `bookId` 与目标一致、`chapters` 是空数组，`distinctTitledUidCount=0`、`isMPChapterOneCount=0`。探针据此停止，未请求 `/book/info`，未写任何 SQLite。这个结果排除“本账号/本目标号在当前官方目录接口一次可列五篇”的假设；不能推断全部公众号、其他账号或其他接口不可用。

**同日第二个独立假设实测**：探针的 `--search` 模式按官方文档对目标号准确名称、`scope=4` 只发一次 `/store/search`，收到 HTTP 499；没有成功 JSON 或文章条目，立即停止、没有重试。当时探针在非 200 时未读取错误正文，因此已有记录无法还原业务码或提示，不能臆测 HTTP 499 的内部原因。搜索请求和目录请求使用官方 Gateway，不是旧 Web 列表端点；此结果仍只覆盖本账号、该关键词、该时点的单次请求，不能证明全部搜索词或所有账号都失败。两个入口均未达到五篇门槛，暂不接 Provider 或写生产库。

**官方 skill 与能力发现核验**：运行腾讯 README 指定的 `npx skills add Tencent/WeChatReading -g`，安装器报告 Codex 已复制 `weread-skills` 到用户级 skills 目录；当前会话直接读取了 `SKILL.md`、`book.md`、`search.md`，三文件的 Git blob 与腾讯仓库 HEAD `315698a8da1810fab0bbf24a52b38a6960e54cdc` 一致，版本 `1.0.4`。现有探针的 Bearer Key、业务参数平铺和版本号与官方规范相符；**旧失败不是缺少 skill 导致**。修复探针后先通过 19 项本地模拟测试，非 200 错误正文读取上限 64 KiB，只输出 HTTP 状态、业务码、错误类别和受控版本提示，不打印原文或凭据；没有为补日志重放 `--search`。再按官方 `SKILL.md` 对 `/_list` **只发一次**只读请求，成功列出 17 个操作，包括 `/book/chapterinfo`、`/store/search`，**不包括 `/book/articles`**。不能把后者臆造为 Gateway 的 `api_name`。

探针现要求显式 `--chapters`、`--search` 或 `--list` 才能发起请求；直接运行脚本会以零请求退出。前两种真实请求已做过，不因补诊断重放；`--list` 已完成一次能力发现，不重复轮询。

下一项继续核实 `/book/articles` 在当前客户端版本的认证来源，或寻找另一条真正不同、可审查的合法取文路径。近期成功案例只是支持证据，不是实验前置门槛；当前缺的是**能用于该端点且来源可核验的本人认证条件**，不是五篇现成回包。满足后做一次隔离只读首屏，先回答能否取得真实文章条目及有哪些字段；取得条目后再核对号身份、稳定文章 ID、原文链接和**发布时间**，缺字段则找合法补充来源，不伪造。五篇是接入前验收样本，不是研究门槛或订阅上限。达标后才查分页、正文、图片和持续新增；章节 `updateTime` 不能冒充原文发表时间。所有实验不写生产库。

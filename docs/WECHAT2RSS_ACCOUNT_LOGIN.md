# Wechat2RSS 项目内账号登录

账号页主入口使用已配置的 Wechat2RSS 私有实例。点击“添加微信账号”才获取二维码，扫码与官方确认由用户自行完成。点击“刷新账号状态”才读取实例账号列表，登录成功会额外读取一次；没有页面加载或后台自动查询。旧本地账号仅在折叠区展开时读取，主入口不再创建旧微信读书登录，旧数据库记录保持不变。旧组件保留为 `legacy-accounts.tsx`，未增加其路由入口。

依据 [官方 API 文档](https://wechat2rss.xlab.app/deploy/api)：`GET /login/new` 创建登录，响应 Cookie 必须由服务端保存，并携带该 Cookie 再请求同一接口查询状态；响应数据为 `isLogin` 和 PNG data URI `qrcode`。`GET /login/list` 提供账号名、可用状态、`needCheck` 与 `waitTime`。本实现不猜测其他轮询端点。文档虽然列出 `POST /login/code`，但未说明提交字段或挑战状态结构，因此验证码提交未实现；上游拒绝时安全停止，由用户按官方提示处理。

2026-10-10 复核当前私有实例提供的官方静态客户端：成功响应允许省略或置空 `err`；创建时读取可选 `qrcode`，轮询只在 `isLogin=true` 时完成。因此代理接受只有二维码的初始数据，以及省略等待标志的响应；已有二维码和 Cookie 保留，继续同一会话。无 Cookie 的等待响应仍停止，不能靠再次请求创建另一登录。该复核没有创建登录；新增回归均为合成响应，不冒充用户失败时的真实响应。

失败提示区分“二维码获取停止”与“登录状态查询停止”，并区分请求失败、响应结构、二维码格式、会话缺失及失效。服务端仅记录阶段、HTTP 状态、内容类型类别、字段类型、布尔标志、二维码长度/格式类别和 Cookie 头是否存在；不记录二维码内容、会话标识、Cookie、token、URL或原始错误。账号可用列表与一次二维码登录状态分别验收。当前合同没有单独的“已扫码待确认”或“官方验证”字段证据，等待提示合并为扫码或确认，上游拒绝不自动认定风控。如果修复后用户一次点击仍失败，可根据上述脱敏诊断定位，不要求用户提供 Cookie、HAR 或原始响应。

代理仅使用现有 `WECHAT2RSS_ENABLED`、`WECHAT2RSS_BASE_URL`、`WECHAT2RSS_TOKEN`，复用私有主机校验，不开放浏览器配置任意实例。token 仅进入服务端到实例的官方 `k` 参数；Cookie 只存进程内存。前端仅得到二维码、经过筛选的账号状态和短期随机会话标识。开始/轮询/关闭均经现有 `protectedProcedure` 的 POST mutation，会话标识不进入浏览器 URL。上游原始错误、URL、Cookie、token、账号 ID 均不返回，也不写日志。

每次轮询最少间隔三秒，本地登录期限三分钟、最多六十轮；取消、成功、错误、过期停止，失败不自动重试、不自动重新创建登录。关闭仅停止本项目轮询并清除内存 Cookie，不声称撤销已经创建的上游二维码或登出已经成功的账号。实例仍可能保留其自身登录状态，服务端进程重启后需重新获取二维码。多个窗口同时开始会返回“已有登录正在进行”。没有自动刷新风控标志、删除上游账号或同步账号至本地数据库的操作。

## 离线回归与验收边界

运行 `pnpm --dir apps/server exec jest --runInBand wechat2rss-account.spec.ts`、`node --test scripts/wechat2rss-login-ui.test.cjs scripts/account-login-ui.test.cjs`，以及前后端类型/lint/构建检查。测试使用注入 fetch、合成 PNG 头、虚拟时钟和实际 TSX 的离线 hooks，覆盖 Cookie 轮换、二维码校验、秘密不外泄、重复提交、迟到响应、关闭/卸载/过期/成功停止及旧登录回归。

这些测试不访问微信、不创建真实实例登录、不扫描二维码，也不能证明扫码后实际账号可用。2026-10-10 本轮用户电脑 CUA 工具启动报进程退出及 kernel reset，未完成实机点击。集成负责人统一发布后，由用户测试二维码与官方确认，人工刷新账号状态；遇风控或其他官方验证立即停止。真实浏览器点击、真实二维码有效性与扫码成功仍须单独验收。

## 后续小红书接入原则

小红书后续同样在项目内提供订阅、账号状态和下载入口，常用操作优先显示，技术说明和日志默认折叠。桌面启动只检查选定来源真正需要的服务；来源失败明确展示原因，不隐性切换来源。账号登录须以小红书供应商实际公开能力为依据，由用户亲自完成授权，不复用或假定微信二维码、Cookie 轮询合同。本轮仅记录这些可复用原则，不新增小红书真实请求、凭据配置或部署。

集成回归补充：上游在等待状态清空 Cookie，或通过 Max-Age/Expires 使 Cookie 失效时，立即停止本次登录，不继续请求 /login/new 以免创建另一会话；已明确返回 isLogin=true 时允许正常清 Cookie 并结束为成功。四种失效输入已先复现，补丁后与成功清理分开回归。

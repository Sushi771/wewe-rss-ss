# 交互与交付检查单

## 用户路径
- 分别验证列表数量与分页、正文完整性、图片可用性、归档内容与持久性；报告各层状态，不能用其中一层代替其余层。
- 验证选中状态在分页、刷新、筛选和异步完成后仍与操作目标一致；提交时确认目标集，避免陈旧选择。
- 验证弹窗打开/关闭/取消、重复提示去重、失败后的再操作和重操作期间的禁用/进度/取消行为。
- 对重操作明确成本和进度，不让一次重复点击启动多份任务；前端防重与后端幂等共同工作。

## 性能与进程诊断
- 先记录输入规模、准确版本、环境与基线，再分开测网络获取、解析、数据库、文件/图片、归档、界面渲染与启动。
- 优先修复已证实瓶颈；不要在没有测量时引入缓存、复杂并行或额外后台工具。
- Windows 启动检查解释器/运行时、依赖、工作目录、配置、端口、实际 PID 和就绪信号；启动命令返回不等于应用就绪。
- 进程退出收集退出码、信号、日志时间线、父子进程关系和运行版本；健康检查超时区分检查方式、端口/路径、进程生存与业务就绪。证据未闭合时不要猜根因。
- 用合成环境重现故障，不把修复后的测试结果追溯成旧生产退出的根因证明。

## 协作与发布
- 多窗口各自隔离分支/工作区、数据库、输出目录、端口和进程；共享生产状态只允许一个明确写者。
- 记录待发布准确 SHA，拒绝用浮动分支名或“最新代码”代替版本。独立复核真实失败反例、覆盖范围和失败边界。
- 分别标注代码、测试、部署、验收状态；没有部署证据就写未部署，部署了但未跑用户路径就写未验收。
- 发布最小变更集合，明确停止/启动顺序、数据兼容性、恢复点与回退条件；回退代码前检查旧版本能否读取新数据。
- 交付非敏感代码、测试与文档，说明如何验证和仍未知的情况。遵从当次授权，不从本技能继承推送、发布、账号访问或数据分享权限。
- 达到预定验收且剩余风险已明示后停止扩建；避免为“证明绝对安全”持续制造工具和无限审计。

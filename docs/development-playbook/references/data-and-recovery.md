# 数据与恢复检查单

## 小写入与备份
- 普通小写入采用事务、幂等键、唯一约束和去重；不要每次写入前做全库备份。大规模迁移或破坏性操作单独评估恢复点需求。
- 为定时备份定义数量与总容量预算、保留策略、失败行为和受保护恢复点；预算耗尽且不能安全清理时报告，不能默默删除保护点。
- 用实际可恢复的数据范围证明备份：表、主键、索引、约束、触发器、生成列及生成表达式、必要元数据。区分生成列定义与值的恢复；不要只用普通列枚举宣称全量覆盖。
- 清理决策绑定对象身份和版本，执行前原子复核：不能“按名称检查旧对象，随后删除同名新对象”。标记更改、文件替换与清理之间的竞争必须有反例测试。
- 恢复在事务或等价原子切换中完成，并保留恢复前可回退状态；注入任一步中断，验证不会留下部分可见状态。

## 同目录增量归档
- 维护稳定对象身份、内容版本和逐项清单；列表、正文、图片与最终归档分别记录完成条件。
- 续跑同一目录只补缺失或已验证损坏项；支持断点恢复，不重建整个输出目录或覆盖有效文件。
- 以临时文件加原子落盘处理单项写入，验证后再标完成；重启核对文件与清单，不能只看目录存在。

## 持久任务与外部回执
- 持久化任务及每一项的状态、尝试、错误、来源和请求标识；区分排队、运行、部分完成、已完成、失败与未知等业务状态。
- 为排队和运行租约设计过期释放与所有者校验，防止永久占坑或旧执行者覆写新执行者；限制并发，隔离单项失败，允许安全续跑。
- 外部副作用提交前持久化请求身份；收到有效响应凭据后尽早可靠落盘，绑定原请求、目标、来源与必要校验信息，再推进业务完成状态。
- 在“请求已发送、响应已到但未落盘、凭据已落盘但业务未提交”等边界注入崩溃。使用可核验凭据原子恢复；重放本地恢复应幂等，不能重新触发远端副作用。
- 对未知结果先查询已有凭据、官方状态或幂等请求结果；没有可靠依据就保留未知并给出安全下一步，不把 HTTP 200 或另一份缓存同步成功当作原请求成功。
- 不保留访问令牌等秘密作为审计材料；日志和凭据记录采用最小必要字段，按项目的数据保护要求存储。

## 最小合成测试矩阵
- 正常写入、重复写入、约束失败、事务回滚。
- 生成列恢复、受保护恢复点、容量上限、同名对象替换竞争。
- 部分归档、同目录重启补缺、失败项不阻断其他项。
- 排队过期、租约更替、旧执行者回写、有界并发。
- 各提交边界崩溃、凭据错绑来源/请求、恢复中断、重复恢复、缺凭据历史未知项。

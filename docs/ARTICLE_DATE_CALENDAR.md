# 原文日期日历点选

日期筛选栏的单日、开始日期、结束日期均提供带图标和“日历”文字的按钮。点击后在中文日历中选日；上个月、下个月按钮用于翻月。无需输入日期文本，也不依赖浏览器原生日期图标。鼠标、触控和键盘均由现有 NextUI Calendar/Popover 处理。

范围通过两个端点各自点选；只选一端仍按原有开放范围筛选。点选日期立即生效，翻月或按 Esc 关闭不会提交新日期；清除恢复全部日期。“今天”“近7天（含今天）”“本月（截至今天）”仍在原下拉菜单中。日期错误仍由页面原校验显示，倒置范围不提交查询。

日历输出 `YYYY-MM-DD` 日历标签，没有经宿主时区转换。原查询 `dateStart/dateEnd`、上海日期边界、sessionStorage 恢复、快捷日期重算、清除及选中文章重置沿用原流程。本补丁不修改 feeds 页面、数据库、刷新调度或下载服务。

## 依赖与集成

复用锁定的 `@nextui-org/react` 2.6.11（其 Calendar 2.2.9）。直接声明 `@internationalized/date` 3.6.0，与已安装 Calendar 依赖一致；锁文件只新增 web importer 的声明，未升级已有依赖。CalendarDate 虽出现在聚合包类型声明中，但不是该聚合包实际 ESM 导出，因此直接从日期库导入。中文 `NextUIProvider` 仅包裹弹层内日历，避免改变全站语言。

`ArticleDateFilter` 的 `value/onChange/error` 接口保持不变。各端点的 Calendar 独立挂载，未选结束日期时默认显示开始日期所在月。Popover 使用现有 portal、碰撞翻转及焦点/Esc 行为，面板限定视口宽高并可滚动。顶部按钮允许换行，窄屏不强制铺开日历。

旧日期文档和浏览器测试只证明原生日期输入值/筛选合同，不能证明用户点击打开日历成功；此前把它称为日历验收过度。新回归使用本机 Chrome 的真实鼠标及触控坐标事件点击可见按钮、翻月和日期格，不使用日期 fill 或注入日期 change 事件。合成页使用实际组件及 NextUI 主题，完全隔离应用 API 和上游。

# 文件夹批量分类

公众号文件夹的更多菜单提供“添加订阅”。弹窗可搜索已有订阅、逐项勾选或选择本页，并一次添加最多 100 项。每页显示 50 项，搜索与翻页保留选择。已在目标文件夹的订阅显示“已在文件夹”，不能重复选择；其他文件夹的订阅会移动到目标文件夹。该操作使用既有 `feed.moveFeeds` 原子接口，不新增上游订阅，也不启动采集。

保存失败时弹窗保留选择并显示错误。接口确认保存后立即更新分类缓存，关闭弹窗并释放操作锁；随后列表读取失败会单独提示“分类已保存，列表刷新失败”，不会把成功写入误报成失败或重放请求。正在写入时分类变更互斥，但仍可浏览文件夹、公众号和手机导航，并显示保存进度。

明确的“SQLite 一致性备份超时，本次未写入”属于保存失败：界面保持旧分类、还原拖动预览、保留批量选择，显示原错误并解除操作锁。它与“分类已保存，列表刷新失败”的成功写入分支分别有代码及浏览器回归断言。

## 原因与实现

原有 `onMove` 在写入成功后仍等待 `refetchFeedList`，而 `ManagementFolders.run` 在整个回调完成前保持导航禁用。离线回归将该读取替换成永不结束的 Promise，旧代码无法释放操作锁。修复根据 mutation 返回的去重 ID 和目标分类更新查询缓存，将后续读取与保存确认分开。失败时不会发布分类变更，拖动预览还原为原始顺序。

批量弹窗只渲染当前页，按 ID 去重，选择数遵守服务端既有 100 项限制。侧栏同时保留原始索引，避免每行再次遍历完整订阅列表。当前弹窗使用页面已有订阅快照，遵循现有订阅列表接口的分页范围。

公共 SQLite 备份仍是分类写入的前置条件，当前实现有 60 秒超时。本改动不修改备份、数据库读写基础层或生产启动流程；慢备份的处理速度属于公共数据库任务。界面会明确显示保存中，不把等待或未知结果当成成功。网络中断时用户应先刷新核对保存结果，不能从前端异常推断数据库一定回滚。

## 验证

- `scripts/folder-move-ui.test.cjs` 执行真实页面分类回调，覆盖保存确认后读取挂起、读取失败提示、保存拒绝时保持原分类与选择、不重放。
- `scripts/folder-member-picker.test.cjs` 执行真实选择组件，覆盖 2000 条合成订阅、50 项渲染上限、100 项批量上限、跨页搜索保留选择、失败与重复 ID。
- `scripts/folder-subscriptions-browser.test.cjs` 使用安装的 React、NextUI、真实分类组件和页面回调，在隔离 headless Chromium 中验证原生拖放、批量失败重试、合成 localStorage 刷新持久化、重复添加及大列表搜索。合成回调不等于生产接口实测。
- `apps/server/src/trpc/management-groups.spec.ts` 在新建临时 SQLite 上运行真实分类接口。100 项一次保存、新客户端读取、重复添加、事务提交失败回滚、缺失 ID 原子拒绝，以及既有文章、元数据和本地目录保护均有断言。

专用公开 CI：`.github/workflows/folder-classification-ci.yml`。本轮没有修改生产分类、复制生产数据库或媒体，没有启动上游采集、部署或合并。

## 连续操作与旧响应

新一轮分类写入前会取消现有 `feed.list` 读取；已取消读取即使在网络层晚返回，也不得覆盖较新的分类缓存。`scripts/folder-move-ui.test.cjs` 使用实际安装的 TanStack QueryClient / QueryObserver，执行两次真实页面分类回调，故意让旧读取忽略 AbortSignal 并最后返回，检查缓存和订阅者仍保留第二次已确认分类。普通文件夹切换只改变本地筛选，不把其他文件夹的响应写成分类结果。

共享分类组件的提取式测试 `xiaohongshu-ui.spec.ts` 同时覆盖新增保存状态 hook；专用 CI 纳入这套回归，完整项目 CI 仍须通过后才视为全量验收完成。

## 文件夹顺序保存

文件夹排序也根据 `reorderGroups` 成功返回的完整 ID 顺序更新缓存，立即释放操作锁，后续分组读取独立执行。刷新失败显示“文件夹排序已保存，列表刷新失败”，不回滚已提交顺序。保存拒绝保留原顺序与原错误，不再在 `finally` 中等待可能挂起的第二次读取。

`scripts/folder-reorder-ui.test.cjs` 执行实际页面排序回调，覆盖成功后的刷新挂起、刷新失败与保存拒绝，并用实际 TanStack QueryObserver 检验连续两次排序后旧响应最后返回不能覆盖新顺序。`scripts/folder-reorder-browser.test.cjs` 在真实 React / NextUI 隔离浏览器中检查排序菜单、刷新挂起时 UI 锁释放、成功后刷新错误单独提示，以及保存失败仍保留原顺序并可以浏览。

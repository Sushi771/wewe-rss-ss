# 普通写与受保护操作的备份边界

普通增量操作依靠 SQLite 事务、去重、实际连接的耐久校验、磁盘准入与已有 SQL 回执；不按按钮、条目或通用写包装请求整库备份。定期快照独立运行。升级、迁移、删除、凭据替换和需要私有来源发布/回滚删除的显式激活继续走独立保护。

## 防止再次引入通用全备

`docs/backup-call-policy.json` 是逐函数清单。`maxCalls` 是静态调用点上限，不是新建文件数，也不是运行时次数。普通入口列零；高风险调用点上限一。未登记的新调用、导入重命名、命名空间调用、重复调用、将备份能力传给其他包装，以及无理由或无限预算规则都会让 CI 失败。不得通过给通用 writer 登记一个默认全备规则绕过普通操作零备份原则。

AST 扫描只读生产 TypeScript 源码，不导入应用、不连接数据库、不发网络请求。它覆盖应用保护函数及现有删除保护包装。它是工程回归检查，并非任意 JavaScript 间接调用的安全沙箱；运行时条件分支、循环次数和事务正确性仍由合成 SQLite 故障/并发测试证明。新增合法保护入口必须更新精确函数、理由和运行时矩阵，不能按整文件放行。

守卫跟踪备份模块的 namespace、CommonJS `require`、动态 `import` 及 import-equals 来源。点访问、字符串字面量和无插值模板的直接已知调用按预算登记；namespace 的常量键、插值模板、动态键、解构/函数提取、别名传递、反射和重新导出一律作为待审核引用拒绝。它不把无法静态解析的调用当作零次，也不推测运行时键值；审核后应改为可定位的直接调用并按精确函数登记。无关模块的动态访问、纯类型导入与未使用导入不受此规则影响。

```sh
node --test scripts/check-backup-policy.test.cjs
node scripts/check-backup-policy.cjs
node scripts/check-backup-policy.cjs --inventory
```

## 保留的应用边界

- 显式离线重放/一次性补录：四个 replay/backfill 方法、目录导入。
- 真实来源切换：mp2rss channel 变化、public-album channel 或规范化合集绑定变化；未变化的普通采集零调用。
- 显式 native 私有来源激活、已审核批次激活：保留发布和回滚删除所需保护。
- 账号新增、凭据/session 替换、账号/订阅/空分组/单篇删除：保留保护。
- 订阅单删/批删与单篇删除经同一独占边界；批删不逐条调用备份。

保护调用可以复用满足保护证明且源数据库未变化的近期快照，因此一次调用不一定新建一次快照。已提交写入改变源身份/指纹后不得把旧文件冒充当前保护点。普通入口删除全备调用后，不再因为复制整库超时阻断整批；增量空间或耐久校验失败仍应明确拒绝，不回退全备。

升级/迁移和发布 CLI 的保护、定时快照 owner、SQLite 服务准入与启动钩子继续按各自工具协议工作，未包含在应用 AST 的静态调用数内；完整链路和线上/候选差异见本次备份审计及 PR39 工具文档。

## 验证与已知限制

普通分组、名称/状态编辑、采集状态、补抓和正文缓存分别有零调用矩阵；高风险条件/删除有单次门禁、备份失败不写、晚期 SQL 故障回滚与独立连接回归。SQL 回执用于确认应用写入结果，不能替代升级、迁移和删除的灾难恢复点。

共享 `incremental-write.ts` 保持 PR39 原接口及 64 MiB 单事务 payload 上限。超界应在写入前明确失败，不隐式全备或拆散原子事务。本文不表示已上线；上线版本与工具候选必须按最终精确 SHA 独立验收。

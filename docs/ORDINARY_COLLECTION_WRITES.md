# Ordinary collection writes

Development baseline: PR39 `d3f4af046accbd2453bf403691338c9592f938c6`. This change extends its existing `incrementalWrite`, transaction durability checks and receipt table; it adds no migration, backup owner or alternative admission mechanism.

The previous generic `recordCollectionResult` copied the database before writing a small running/failed result. Owner-search and owner-WeRead collection then copied it again internally. A subscription's identity and metadata continuation also took fresh snapshots. Every committed progress update invalidated snapshot reuse, so ordinary work could repeatedly wait for a complete copy or fail because a recovery-copy quota was full.

## Ordinary boundaries

| Entry                                                          | Atomic protection and retry behavior                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generic collection progress/final/error                        | Bounded incremental transaction; compare the prior result before writing. A later cache SQL result wins over the outer status, including a lost commit acknowledgement. Each source still fails independently in a batch.                                                                                                                                                                                 |
| Owner search, owner WeRead and verified publisher continuation | One transaction for identity-preserving article merges, feed timing and a deterministic `cache_refresh_commits` row. Recheck active source inside the transaction. Receipt existence never skips current row checks.                                                                                                                                                                                      |
| Single original-body retry                                     | Check local disk/durability before transport; release admission during transport. Persist body, identity and `lastBodyRetry` together. Only transport/validation failures may produce a separate failure result. SQL or acknowledgement failures propagate as incomplete and never run a second failure transaction or another HTTP request.                                                              |
| Wechat2RSS article/body/image cache and avatar                 | Retain PR39 cache transaction and SQL receipt; avatar fill uses the same incremental admission and conditional update. No ordinary cache stage requests a full snapshot.                                                                                                                                                                                                                                  |
| Wechat2RSS registration and identity/metadata continuation     | Prove the actual Prisma SQLite path and durability without copying it. Preserve the existing exclusive, fsynced one-shot add claim, accepted receipt and task history. A claim with no confirmed feed path blocks resubmission. Background continuation only resolves identity and reads existing cache; it never calls `/addurl` again. Feed creation/binding is atomic under the same incremental lock. |
| Already bound public albums / Mp2RSS                           | Fetch and validate outside the transaction; recheck feed identity/source before atomic merge and feed timing. No routine snapshot.                                                                                                                                                                                                                                                                        |
| XHS pending creator, pause/resume and verified archive save    | Use existing incrementally admitted transactions. Recheck creator identity and enabled state before note writes, retain stable note IDs and complete existing archives. Source reads are never automatically replayed. Tests inject a synthetic source; no real XHS request is authorized.                                                                                                                |

All SQLite writes retain PR39's physical free-space margin, actual database identity check, cross-client lock and transaction connection durability validation. The shared 64 MiB expected-payload bound remains unchanged. Larger atomic collection payloads fail before a write rather than silently taking a snapshot or splitting the write set. SQLITE_FULL and I/O failures cannot claim a successful result. No transport runs under a database transaction or an incremental admission lock.

## Independent recovery protection remains

`CollectionService.replayWereadDirectory`, `replayVerifiedSearch`, `replayBrowserDomUpdate` and `importVerifiedSearchBackfill` remain explicit protected replay/backfill operations. Directory/history import and merges are unchanged.

`collectMp2RssRecent20` takes one independent verified backup only when the saved source is not `mp2rss`. `collectPublicAlbums` takes one only when the saved source is not `public-album` or its normalized album-ID set changes. An ordinary refresh of the same saved binding takes zero. A failed source-change backup prevents transport and writes; source/version changes during preparation abort the transaction.

Native subscription activation/repair retains the supplied backup callback in `addSubscriptionFromArticle` / `repairExistingSubscription`: that workflow publishes a private source binding and can delete an inactive staged feed on rollback. It is not the cache-only continuation above. Account session replacement, actual deletion, migrations, upgrades, formal maintenance and periodic recovery snapshots retain their own protection. This change does not weaken or relabel those boundaries.

## Offline verification and regression prevention

`ordinary-collection-write.spec.ts` uses newly created synthetic SQLite databases and mocked transports. It covers outer and inner ordinary zero-snapshot saves with a failing backup provider, source-change one-snapshot gates, deterministic receipts, late SQL failure, lost commit acknowledgement, independent concurrent clients, low-disk rejection before an original-body request, and XHS deduplication/pause behavior. It checks SQLite integrity and foreign keys. Existing body retry and source-selection tests now assert zero snapshots instead of waiting for a removed backup call.

Run the related Jest suites with `--runInBand`, TypeScript `--noEmit`, and ESLint on changed source/tests. `ordinary-collection-call-sites.spec.ts` rejects reintroducing direct snapshot dependencies into the ordinary wrappers and continuations. The repository-wide protection manifest and CI boundary policy are maintained by the integration owner. These checks prove isolated code behavior, not live platform access or deployment. No production database, history, configuration or release directory is changed.

The collection commit was validated on Windows with the already installed dependencies: TypeScript and changed-file ESLint exited 0; 19 related Jest suites passed all 353 tests. Run Jest from `apps/server`, so the existing offline ZIP child bridge resolves that package's TypeScript dependency. The suite set covers ordinary collection/call sites, body retry, incremental refresh, collection service, XHS service/video, public albums, native subscription registration/selection/validation/flow, owner search/WeRead, manual/scheduled refresh, wave preparation and Wechat2RSS preflight. All transports were mocked; backup tests used only small synthetic databases. No dependencies were installed.

# 持久新增与自动入库

本次候选将新增改为持久串行任务；实际发布版本、CI、运行包和真实平台结果见集成负责人的私有回执。离线回归不能代替用户扫码、自然更新或逐篇图文验收。

## 用户操作

在公众号页添加入口粘贴文章链接，每行一条，最多20条。页面只使用已配置的 Wechat2RSS；一次提交会先保存全部输入，再串行受理。关闭弹窗、刷新页面或重启服务后，已保存队列仍可查看和接续，不需要再次提交。旧版本弹窗中尚未发出的输入没有持久记录，无法从哈希回执恢复，需在新版本重新粘贴这些尚未发出的链接。

| 进度         | 含义                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 等待处理     | 链接已保存，本条尚未发送                                                 |
| 已受理       | 原请求已有回执，随后只读取对应缓存，不重复新增                           |
| 列表已入库   | 真实文章身份、标题和发布时间已保存；正文与图片仍可未完成                 |
| 正文图片就绪 | 当前缓存正文及图片归档检查通过，不证明全历史或任意历史文章覆盖           |
| 信息待补全   | 数字公众号身份已由回执确认，实例名称仍空；不编造名称，不阻止已核文章展示 |
| 暂停         | 账号不可用、响应不明或读取失败；后续未发送项保持，处理原因后可显式继续   |
| 停止剩余     | 只取消尚未发送的链接，已受理的订阅不会被声称已撤销                       |

格式无效的链接在本地标记失败，其他有效项继续；相同公开链接跳过。不同未知短链接不能预先认定属于同一公众号。已有有效来源和暂停状态不自动更改，旧正文、图片、真实指标及本机编辑笔记保持。

## 时间与恢复边界

队列时钟每5秒检查本地状态；不同新增请求间隔至少30秒。已经受理的缓存接续最多十轮，间隔30秒，起始窗口五分钟。限制、认证或读取错误立即停止自动接续，不换账号、端点或重放新增。超时后可显式继续读取原回执对应缓存。正常单号刷新和既有日更新仍只读缓存；新号不自动进入日更新白名单。

收到合法 `/feed/<数字>.xml` 回执后，先以该真实ID建立 Wechat2RSS 绑定。名称尚空时保留空字段供界面显示信息待补全，已有非空名称不覆盖。先消费对应 JSON Feed 的已核身份与发布时间，将文章列表事务入库；这一步不等待图片网络归档，不推进成功缓存同步时间。正文和图片在后台按原保护规则补齐。名称随后仅通过同实例、同回执的精确名单记录补全。

## 备份与迁移

除一致性 SQLite 备份外，数据库旁的 `.wechat2rss-add`、`.wechat2rss-subscription-tasks`、`.wechat2rss-subscription-batches` 和 `.wechat2rss-single-downloads` 必须一起保留。任务含用户提供的公开文章链接及已确认的保存目录，仍属于私人运行资料，不能提交到Git。配置凭据不写入任务，实例指纹用于阻止跨实例恢复。新增前和发布前的备份目录也保存这四组任务快照。

回滚数据库不删除或用旧快照覆盖活动任务与一次性回执；尤其不能删除响应不明的占位后重新发送。受理前写占位、受理后写路径，在进程中断时以原回执判断结果。只有状态明确的已受理任务可自动读取缓存；结果不明暂停，不凭标题、位置或其他账号猜测。

单篇下载复用同一队列时钟，单篇模块另外保存已确认目录与精确目标状态。必要时整号订阅须属于用户点击的明确授权；是否能取得具体文章仍取决于供应商实际缓存及精确短链映射。详情见 [单篇工具说明](ARTICLE_DOWNLOAD_TOOL.md)。

# 缓存预检与前台读取竞争

基线为生产 `c80d240`，整合基线使用直接继承它的 PR62 `e6600122d64aaa541dc92a4b97491601537135cd`，保留冻结的 `coverPreparation` 修复。PR63 是 main 抽取线；运行时补丁只需新增 `feeds/cache-body-media-flags.ts` 并替换 `syncCachedWechat2RssPage` 内的标志读取，不整文件覆盖其他窗口代码。

## 机制与最小改动

旧预检先读取公众号身份元数据，再对该号全部保存正文执行递归 CTE。每个图片标签都会复制/截取剩余 HTML，并重新寻找边界；长 inline Base64 会放大这项成本。配置为单连接时，RSS 已经排除了正文投影也仍会等待这个后台查询释放连接。外层“Cache transaction”计时还可能包含取得连接前的等待，不能据此推断写事务回调本身一直运行。

新 helper 只读取本页已匹配的保存 ID，仍用一个 SQL 语句取得一致快照。常见的 inline 正文只返回小标志，不返回正文，不做递归。疑似 HTTP 图片属性在线性扫描中判断：保留旧谓词的大小写、单双引号、逐标签和 inline/src 与 data-src 优先规则；JavaScript 检查在 SQL 返回、连接释放后执行。旧身份冲突检测、写前重检、CAS、增量事务和写协调均保持不变。

疑难 HTML 的传输/检查合计最多 8,000,000 字节；单篇超过该值或超过本次预算的疑难项保守返回 pending，不能误报完整。这个上限可能让少见的大批保留 data-src 的旧正文继续显示待核；它不推断新的图片来源，也不解除既有安全停闸。正文缺失和未知媒体仍与已保存字节分开报告。没有新增缓存或修改列表缓存的 WAL/journal/revision 规则。

不增加连接、第二个客户端、连接池、超时或生产配置，不拆分写事务，不把后台事务放到启动保护之外。长事务本身仍会占用唯一连接；本修复去除的是已复现的递归预检长占用，不能保证任意磁盘/维护负载下的绝对时限。

旧列表 1 次在原 15 秒准入上限返回 P2028，其余 4 次成功；该失败时长仍计入旧列表请求统计，不能当作成功响应时延。旧写入在原 2 秒准入上限失败，没有提高阈值。新写入回调实际约 5–14ms，其余是连接排队。所有新 RSS/list 均返回 20 项，RSS 均低于原 2.5 秒门槛；目标页的旧/新标志摘要相同。机器仍有其他正常工作负载，未建立独占性能环境；这些结果证明该机制和修复，不是生产验收，也不从 35MB 外推整库全部路径。

最终探针使用单次索引推进，避免大量未闭合标签导致正则回扫，并覆盖该坏标签反例。另以固定 Node/DLL 对真实 `TrpcService.syncCachedWechat2RssPage` 的完整无写入路径测 5 次，纳入身份元数据读取：最终复核预检 P50/P95 为 346/359ms，同期实际 RSS 为 390/407ms，列表为 355/366ms。每次均返回 20 项、预检无创建/更新且 mediaReady 为真；没有上游请求或整库备份。这一轮用 25 篇同尺寸 inline 正文验证最终服务封装，区分于上表首次候选的旧/新标志查询对照。

## 复现与验收

`apps/server/scripts/benchmark-cache-preflight.ts` 总是新建自己的临时数据库，不接受数据库路径。由 `apps/server` 执行：

```sh
node -r ./test/fixtures/cache-benchmark-runtime.cjs -r ts-node/register/transpile-only -r tsconfig-paths/register scripts/benchmark-cache-preflight.ts
```

可选 `CACHE_BENCHMARK_CLIENT_ENTRY` 与 `PRISMA_QUERY_ENGINE_LIBRARY` 仅固定这个合成子进程的客户端/引擎；脚本在实例化之前将 DATABASE_URL 设为自身临时库。不要给脚本增加生产数据库入口。原始本机报告保留在忽略的 output，不上传运行审计、正文或私人数据。

回归覆盖旧谓词等价、准确页面范围、健康大 inline 正文不传输、预算超限不假报完成，以及实际后台预检同时运行 RSS/列表的 2.5 秒门槛。原缓存/身份/CAS/停闸及 PR62 占用测试继续运行。

仅交付开发候选，不操作生产 PID、配置或历史抓取。唯一生产窗口统一发布后，保持原 2.5 秒 RSS 门槛复测后台运行时的 RSS/列表和预检；仍需区分连接等待、SQL、写回调及外部 I/O。不能把 ready/writesAllowed 或合成通过称为实际用户路径通过。

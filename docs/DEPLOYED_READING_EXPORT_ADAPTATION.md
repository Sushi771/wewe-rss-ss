# 部署源码上的缓存与增量导出适配

本分支直接基于 `8a3141c43b1b09e92ebd75780f26c58939557906`，对应远程基线 `codex/a5-export-title-source-20261018`。只逐段移植 PR70 的有界缓存与导出优化；没有合并 main，没有替换运行文件、停止服务、部署或读取真实数据库。

## 实现边界

- 保留部署版分组、日期筛选、阅读界面、标题与原文链接去重、来源路由及导出范围。语法树测试固定原界面结构和全部旧路由，文件指纹固定阅读器、标题处理、启动、写入协调、备份与自动媒体修复代码。
- store 使用部署版 `ArticleDownloadError`，没有替换为 main 分支的错误类型。新增批次最多64个稳定身份，持有原有文件锁后建立一次有界目录索引；逐篇回执、笔记、图片及发布校验保留。索引超过2048目录或1 MiB逻辑预算时完整回退，不跨批次缓存校验成功结果。
- 服务端先查轻量成员，再每8篇读取正文。没有在文件检查期间持有数据库事务，没有复制、备份或修改数据库；ZIP仍先完成暂存再传输。
- 保留部署版单篇失败后继续的行为，新增、跳过、补齐、失败分别计数；日期待核、保留旧位置与编辑的提示仍聚合显示。单篇旧接口及当前筛选全量ID快照保留。
- 停止、切换筛选和离开页面取消传输与后续提交。服务端完成当前原子项后释放整批锁。响应丢失时只保留已确认批次计数，明确提示当前批次回执未确认，停止后续提交，不自动重试；不能把丢失响应当作全部失败或全部成功。
- 列表、统计和正文保留60秒的会话缓存；只对未观察的阅读查询施加4 MiB估算数据、12页、12查询预算。活动视图不被裁剪，`staleTime`、缓存版本失效、筛选隔离和后台复验保持。没有持久化浏览器查询数据。媒体内容分析只缓存派生事实，限制512项/512 KiB，实际文件始终重新核实。

## 并发保证与兼容

同一受信任文章/来源/公众号身份的 early 和 late 准备均遵守原根目录锁。Wechat 单篇控制器在 `withExportSource` 中提供该身份；本地批量和ZIP使用缓存文章的可信Feed身份。XHS原有兼容路径保留，但本批次并发保证不推广到任意无来源身份或旧版本writer。发布仍须保持单一活动版本，不允许不遵守协议的历史writer混写相同目标。

## 独立的首屏与首次正文工作

本范围没有修改列表查询算法、统计启动顺序、正文查询或阅读器。它们的精确部署版代码被边界测试固定，后续优化应独立提交并更新相应范围声明。

| 工作           | 可独立认领的文件或成员                                                                                           | 共享边界                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 首屏查询与复验 | `article-list-page.ts`、`article-list-cache.ts`、`article-list-read-timing.ts`；router 的 `article.list/summary` | 不修改导出成员、鉴权、Prisma准入、单连接和revision token语义 |
| 首次已缓存正文 | router 的 `article.byId`；`ArticleReader.tsx`、`article-reader-find.ts`                                          | 分开测HTTP/传输、Blob与iframe解析；不启动上游抓取            |
| 列表前端调度   | `feeds/list.tsx` 的 list/summary/byId 查询片段、`use-article-list-position.ts`                                   | 同文件只能按片段协调，不能将其整文件分给两个窗口             |

`provider/trpc.tsx` 和 `feeds/index.tsx` 的批量导出处理函数由本适配窗口持有。首次正文的本地缓存读取与未缓存正文重试是两条不同路径，不混合测量，也不为了首屏速度放宽安全门禁。

## 合成测量方法

两个导出脚本旧版固定为精确 `8a3141c` 并解析其本地依赖图，保留同款错误类；旧、新分别在独立child中只加载一份运行图。每规模交替运行3对，P95在n=3时是最大值。记录进程基线RSS/heap、采样峰值及增量、正文读取数量、根发现次数、输出字节与内容哈希。

ZIP目录阶段为32/128/512篇，每篇约32 KiB正文及一个有效合成PNG；增量store为16/64/128篇、8个订阅目录，并按64成员切批。两组与主窗口测试共享宿主I/O，不能当作独占机器延时保证。目录阶段不包含ZIP压缩、浏览器传输或生产HTTP等待。

每个child只创建一个直属临时目录，清理前验证绝对父路径与自建前缀，finally覆盖构造和旧源码加载失败。循环不保留历史fixture，不接受生产库或用户目录作为输入。列表浏览器另扩至200订阅、6000篇32 KiB合成文章，只访问本地应用；每轮关闭并清理自建profile和合成库。

### 6000篇本地列表扩展

200订阅、6000篇合成文章，旧8a/新适配各n=3，P95为最大值；顺序运行，宿主同时执行其他合成测试。页面和HTTP直接记录，SQL事件区间可能混入并发请求，不能当作严格单请求SQL归因。此夹具使用独立PrismaClient，并未覆盖生产PrismaService准入或现场连接占用。

| 阶段，ms                  | 旧 P50/P95      | 新 P50/P95      |
| ------------------------- | --------------- | --------------- |
| 首屏20篇                  | 271.10 / 286.05 | 280.42 / 337.70 |
| 下一页                    | 134.85 / 134.99 | 120.94 / 178.17 |
| 返回缓存列表可见          | 147.15 / 317.05 | 89.15 / 123.06  |
| 返回后台复验完成          | 179.36 / 348.28 | 208.05 / 229.53 |
| 首次已缓存正文iframe load | 177.19 / 200.77 | 166.74 / 183.08 |
| 同正文再次打开            | 123.10 / 131.72 | 111.63 / 118.26 |
| 两页刷新完成              | 50.23 / 57.93   | 54.83 / 56.90   |

每次返回仍有2个列表请求；缓存可见不代表后台复验完成。回收后JS堆旧6.69–6.70、新7.32–7.34 MiB，WebStorage估算均840B。缓存提升返回可见速度，首屏没有改善，首屏与首次正文P95仍未达150ms；n=3不足以推导所有机器的稳定上限。未把本轮与不同基线的PR70小规模夹具拼成增长结论。

导出的32/128/512与16/64/128篇配对趋势、精确SHA及最终CI记录列在本开发分支的Draft PR交付说明；源码、方法和合成回归随提交保留，机器运行审计留在私有输出。本源码未部署，不能称为生产路径已验收。

# 文件夹改名的响应与持久保存

点击保存后，已有文件夹立即显示待保存的新名称并关闭编辑框。侧栏继续显示“正在保存分类，请等待确认”；此时只改变显示，尚不能视为数据库已保存。服务器确认后才更新分组缓存并解除修改保护。失败恢复上次确认的名称，明确提示“未确认保存”，需要刷新核对，避免把响应丢失误判为数据库一定没有提交。

保存期间可以继续浏览文件夹，但不能再次提交改名、移动或排序。同一点击的重复处理也由同步保护拒绝；完成后可以连续改名。取消和 Esc 在提交前关闭编辑框，不发送请求；提交后的保存状态不提供虚假的取消按钮。名称会去除首尾空白，保留原来 1–80 字符和禁止控制字符的校验。同名文件夹仍是各自独立的 ID；没有新增唯一性限制，也不修改磁盘目录或文章身份。

## 最小持久化路径

旧路径为：一致性整库备份 → 分组事务 → HTTP 返回 → 全量读取分组 → 显示新名称。分组改名没有读取正文，但每次备份会随整库大小增加开销；分组修改锁也一直被占用。

新路径仅对带 `id` 的已有分组改名取消逐次整库快照，复用 PR39 `d3f4af046accbd2453bf403691338c9592f938c6` 的原样 `incremental-write.ts`。保护仍包括：

- 实际 Prisma 数据库路径、文件身份和源卷物理余量检查；有限余量使用原有增量写入策略。
- 同主机增量写锁、原分组修改锁、`sqliteWrites` 写入准入；进入引擎前重新检查，不重放事务。
- 在实际事务连接上检查同步等级 FULL/EXTRA 和安全的 journal 模式，随后复核平台归属并原子更新名称。
- 低磁盘余量、不安全耐久模式、数据库身份变化和 SQL 故障明确失败；事务不改变其他分组、顺序、订阅、正文或媒体。

周期备份保持原配置。新建、删除、排序、移动等路径仍使用各自原有保护。本改动不改变日志模式、生产配置或数据库 schema，不新增迁移。`incremental-write.ts` 与 PR39 使用同一路径和内容，集成时应保持单份实现。发布前需按现行升级流程准备受保护的恢复点；开发测试不操作生产数据。

前端使用 mutation 返回的已提交行按 ID 更新缓存，不再为改名重新读取分组、公众号或小红书博主列表。保存前及安装返回行前取消旧分组读取；已经取消的旧响应不会覆盖确认后的名称。只读失败不会把已提交的改名伪装成写入失败。新建分组也用服务器返回的 ID 和顺序插入缓存。

## 回归与三阶段测量

```powershell
node --test scripts/folder-rename-ui.test.cjs scripts/folder-navigation-ui.test.cjs
pnpm --filter server exec jest --runInBand src/trpc/management-groups.spec.ts src/prisma/sqlite-write-admission.spec.ts src/collection/sqlite-write-coordinator.spec.ts
$env:RENAME_BENCHMARK_FULL_PAGE='true'
$env:RENAME_BENCHMARK_SAMPLES='30'
node --test scripts/folder-rename-browser.test.cjs
pnpm --filter web build
pnpm --filter server build
```

浏览器回归使用已安装的独立 headless Chrome/Edge、临时配置及仅回环 HTTP。不会访问外部平台或生产服务。整页模式挂载实际 Feeds、侧栏组件、240 个合成订阅和正式样式；分组读取及保存走原受保护 tRPC 路由、实际 PrismaService 和约 100 KiB 合成 SQLite，其他业务读取使用合成夹具。确认使用本机浏览器鼠标事件。它是工程自动化回归，不替代受支持的交互浏览器工具验收，也不是生产数据性能测量。

每轮分别记录样本数及 P50/P95：

| 阶段   | 测量边界                                                                               |
| ------ | -------------------------------------------------------------------------------------- |
| 界面   | 确认 click 事件到 DOM 新名称出现后的下一动画帧；是绘制机会的上界近似，不是屏幕像素采样 |
| HTTP   | 同一 click 到 mutation HTTP 响应头到达；不把后续列表读取计入接口时间                   |
| 数据库 | 同一 click 到实际 `$transaction` Promise 成功返回；随后独立 PrismaClient 再读验证名称  |

跨进程使用同一主机的 epoch 加单调时钟近似对齐，汇总按毫秒报告，不声称亚毫秒精度。首个冷样本保留在分位数中。组件模式可单独定位开销；它与整页模式不能当作完全同条件对照。原始计时、测试数据库和运行审计仅保存在本地忽略目录，不提交。

界面目标为 150 ms 内响应，持久提交单独验收。备份/写入队列、锁竞争、磁盘 fsync、浏览器渲染、冷启动及机器负载均可能使接口和提交超过 150 ms；不能保证所有机器或每次操作绝对达标。CI 验证行为与数据一致性，不用偶然的计时阈值决定业务正确性。测试覆盖待保存状态、失败回退、重复确认、旧响应晚到、同名及无效名称、取消/Esc、重进文件夹和刷新后的持久化。

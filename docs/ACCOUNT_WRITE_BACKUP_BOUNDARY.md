# 账号编辑的备份边界

`account.edit` 原来无论编辑什么字段都先请求整库备份。现在本地名称、启停状态以及空编辑复用 PR39 `incrementalWrite`，在实际 SQLite 事务连接检查空间与耐久设置后原子提交，不请求快照，也不回退到全备。

输入包含 `token` 时仍先请求一次已验证备份，再执行原账号更新；名称和凭据一起编辑也属于该保护分支。账号新增、删除、扫码 session 替换保持原有保护。此改动不加强或改写这些高风险流程的并发协议。

返回字段仍仅为 ID、名称、状态和时间，不返回凭据。缺失账号保留 Prisma 原有失败语义。MySQL 的普通编辑保留原兼容行为。

`ordinary-account-write.spec.ts` 用原 PrismaService、临时小型合成 SQLite 与禁止网络的 mock 验证：四种普通编辑零备份、独立连接读回、SQL 故障回滚、空间/耐久拒绝、凭据更新备份失败不写、凭据更新只请求一次保护。与原账号测试共 17 项通过。没有读取、复制或修改生产数据库。

开发基线：PR39 `d3f4af046accbd2453bf403691338c9592f938c6`。共享准入、增量策略和备份接口不改；本改动与分组、采集分支分别提交后整合。

# 恢复暂停期间的本地未发送结算

`WECHAT2RSS_RECOVERY_HOLD=1` 继续暂停微信后台任务、缓存同步和来源操作，小红书定时器也检查同一暂停开关。暂停不会因本地结算而撤销。

恢复期间仅允许下列本机同源请求进入原处理链路：

| 请求                                               | 方法 | 目的                       |
| -------------------------------------------------- | ---- | -------------------------- |
| `/startup-status`                                  | GET  | 读取启动/写入门禁状态      |
| `xiaohongshu.prepareRefreshBatchLocalCancellation` | GET  | 原正式未发送结算预览       |
| `xiaohongshu.confirmRefreshBatchLocalCancellation` | POST | 原正式本地结算             |
| `xiaohongshu.refreshBatchStatus`                   | GET  | 读取指定批次持久终态       |
| `xiaohongshu.connectionStatus`                     | GET  | 读取本地来源保护及请求计数 |

tRPC 路径固定为 `/trpc/` 加上表中过程名。HTTP和tRPC两层使用同一份精确过程/类型白名单；混合批处理路径、编码分隔符、其他路径、方法、外部连接及跨域请求继续拒绝。GET可按原本机状态查询约定省略Origin，POST必须有明确同源Origin。鉴权失败仍拒绝，原本机访问、参数校验、启动写入门禁及受保护备份事务没有旁路。

允许一个正式本地过程通过恢复暂停不等于批准其取消证据。确认仍须重新验证预览摘要、可靠未发送证据、空闲状态、真实来源限制及一致性备份；缺失、变化、unknown/started或事务失败继续保留保护。确认只写原取消审计及条目终态，读取本地风险后刷新展示，不恢复会话或发送来源请求。历史unknown不变，原operation仍不能恢复执行。

其他HTTP和来源操作保持暂停，包括普通刷新、批次推进、订阅、会话恢复、图片代理和下载。普通页面及RSS健康合同也继续受到暂停，因此不能把本地维护请求可用称为整个应用恢复可用。后台微信队列的捕获暂停、init及runDue不变；不得为访问本地结算而解除它。

隔离回归覆盖真实Prisma/SQLite、原tRPC鉴权/校验和备份事务、含8个queued项的running定时微信批次、未知记录保留、来源调用0及混合/跨域请求拒绝。不以测试通过或取消成功宣称采集恢复。生产先核当前备份，再以现有受管发布及审批流程安装；保留旧恢复点和唯一服务实例。

# 恢复暂停期间的本地未发送结算

`WECHAT2RSS_RECOVERY_HOLD=1` 继续暂停微信后台任务、缓存同步和来源操作，小红书定时器也检查同一暂停开关。暂停不会因本地结算而撤销。

恢复期间仅允许下列本机同源请求进入原处理链路：

| 请求 | 方法 | 目的 |
|---|---|---|
| `/startup-status` | GET | 读取启动/写入门禁状态 |
| `xiaohongshu.prepareRefreshBatchLocalCancellation` | GET | 原正式未发送结算预览 |
| `xiaohongshu.confirmRefreshBatchLocalCancellation` | POST | 原正式本地结算 |
| `xiaohongshu.refreshBatchStatus` | GET | 读取指定批次持久终态 |
| `xiaohongshu.connectionStatus` | GET | 读取本地来源保护及请求计数 |

tRPC 路径固定为 `/trpc/` 加上表中过程名。HTTP和tRPC两层使用同一份精确过程/类型白名单；混合批处理路径、编码分隔符、其他路径、方法、外部连接及跨域请求继续拒绝。GET可按原本机状态查询约定省略Origin，POST必须有明确同源Origin。鉴权失败仍拒绝，原本机访问、参数校验、启动写入门禁及受保护备份事务没有旁路。

允许一个正式本地过程通过恢复暂停不等于批准其取消证据。确认仍须重新验证预览摘要、可靠未发送证据、空闲状态、真实来源限制及一致性备份；缺失、变化、unknown/started或事务失败继续保留保护。确认只写原取消审计及条目终态，读取本地风险后刷新展示，不恢复会话或发送来源请求。历史unknown不变，原operation仍不能恢复执行。

其他HTTP和来源操作保持暂停，包括普通刷新、批次推进、订阅、会话恢复、图片代理和下载。普通页面及RSS健康合同也继续受到暂停，因此不能把本地维护请求可用称为整个应用恢复可用。后台微信队列的捕获暂停、init及runDue不变；不得为访问本地结算而解除它。

隔离回归覆盖真实Prisma/SQLite、原tRPC鉴权/校验和备份事务、含8个queued项的running定时微信批次、未知记录保留、来源调用0及混合/跨域请求拒绝。不以测试通过或取消成功宣称采集恢复。生产先核当前备份，再以现有受管发布及审批流程安装；保留旧恢复点和唯一服务实例。


## 安装确认后的验收顺序

此顺序只描述验收门槛，不是生产执行回执。运行证据、批次ID、数据库和备份路径保持在私有交接中，不提交源码。由唯一安装线程完成激活并给出真实活动版本后再执行；安装进行中不并行重启、改指针或确认批次。

1. 核活动版本、清单摘要和唯一实例与获准候选一致，恢复hold仍为1，后台微信队列及小红书定时器保持暂停。只调用已列出的本机状态入口，不能用普通刷新、会话恢复、代理图片或外部来源请求“试探”。
2. 记录 `/startup-status` 的实际状态、写入门禁及 `connectionStatus` 的来源计数基线；核微信旧queued项和历史unknown/账号隔离与保留基线一致。风险行clear、会话存在或HTTP200不能替代这些检查，也不证明平台认证有效。
3. 使用原正式只读机制重新核验当前全schema和typed rows的一致性备份证明，保留旧恢复点。证明只覆盖当次快照；如数据改变，由既有备份流程在原数量/容量授权内处理，不能凑数量删旧点或用历史文章数相等冒充当前副本。
4. 对**获派的旧批次**重新调用正式预览，核batch/creator/operation及取消范围与授权一致、摘要为本次产生。`reviewable`才可进入确认判断；`cancelled`只核已有审计，不再新写。HTTP错误、tRPC error、412/503、未知/已发送证据、摘要变化、真实来源限制或审批拒绝均停止。
5. 仅在既有授权及正常审批允许时，使用刚取得的摘要和原确认入口执行获派本地结算。POST必须本机同源，鉴权、严格参数、写前备份及同事务重检必须保留。不得直接写库或调用内部服务绕过HTTP/过程保护。
6. 若响应丢失、浏览器超时或结果不明，先读取该批次正式状态与审计，不重发确认、不改判成功。仅当明确证据及正式幂等路径允许时再判断后续；自动审批拒绝后不得换入口、实例、端口或参数重试。
7. 确认已知成功后，读取原批次条目终态和审计，核旧task/job历史仍保留，来源计数未增加、unknown及微信旧queued未变，备份仍保留。本地取消成功不授予来源请求或恢复原operation的权限。
8. 再对**新批次做只读预览**。旧批次写入已改变数据库，不能沿用之前的摘要或把旧备份复用证明自动延用到下一次写入。本阶段不自动确认新批次，不创建下一批采集；任何后续动作继续核对其具体授权和审批。

响应按实际Content-Type/正文解析：恢复暂停可能返回纯文本503，不能强行JSON解析后把解析异常误报成业务故障。HTTP200也须检查tRPC结果和业务状态。若任一维护查询使来源计数发生增量，停止后续确认并保留脱敏证据。

完成回执至少区分“固定包已构建”“已旁置”“受管激活已确认”“旧批次已正式结算”“新批次只读预览结果”“真实来源更新仍未执行”。原拒绝证据或unknown不会因候选测试通过、代码安装或本地结算而消失。


## 安装健康证明的阶段边界

正式只读预提交的 `ctx.readOnly=true` 不是普通页面可用性检查：原控制器有意跳过通用waitReady，独立核对原生进程身份和事务、版本、清单、数据库及readOnly=true证明。这个阶段不能要求业务写入开放，也不能用一个HTTP200替代精确证明。

正常启动或提交后的本地管理就绪是另一合同：恢复暂停仍保持，读取本机管理健康及startup状态，核对预期版本、清单摘要、数据库和真实写入门禁。页面/RSS仍可保持冻结，不需要为烟测解除后台保护。独立健康修复只用于这个阶段；它不发放安装信任、writer租约、鉴权豁免或备份授权，也不替代正式适配器的预提交/恢复证明。

隔离控制器测试中的原生观察均明确为合成，不得转为生产回执。必须由可信构建者固定宿主、控制器及工具闭包，并完成真实原生安装验收后，才可把候选称为正式安装交付。

## 隔离安装适配器验收的实际边界

`scripts/local-release/updater/installer/installed-adapter.test.cjs` 联合实际宿主、控制器和更新引擎，使用 SQLite backup API 对全新临时数据库执行备份与恢复。测试固定清单只授权本测试自己创建的合成文件；其 node.exe、runtime 和原生进程观察都是不可执行的合成材料，不能用于任何真实安装。覆盖重复、并发、独立更新器共享启动锁、回滚、提交后失败、快照篡改和不完整 writer 观察；临时 queued/unknown 文档逐字节保留且禁止网络访问。

现有构建仅复制 updater 核心，正式接线仍需构建所有者提供独立固定信任、完整受审工具闭包及真实维护授权。只读预提交健康、提交后暂停期管理健康、真实生产安装、本地结算及外部采集分别验收，任何一个阶段成功都不能替代后续阶段。

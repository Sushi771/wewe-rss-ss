# 订阅页浏览记忆：实现与整合

基线：`3dafadec63524257aa67498b5279559b2d3cc24f`；目标分支：`codex/manual-refresh-download-integration`。本实现作为独立补丁交付，由主任务与布局变更统一整合、发布。未修改开发交接文档或运行中的产品数据。

## 数据与生命周期

`feed-browse-state.ts` 定义带版本号的筛选与位置结构、严格校验和无异常存储读写；复用现有日期映射、上海快捷日期及 React Router。无新增依赖。存储键为 `wewe.feed-browse.filters` 和 `wewe.feed-browse.positions`，均使用 `sessionStorage`，与认证存储隔离。筛选最多2000字符关键词、200字符分组；30天的防御性过期检查不代表跨会话保留。版本不兼容、损坏、过期和存储异常均安全回到默认值。筛选结构不接受／保存任意额外字段，不含文章正文、勾选或阅读弹窗状态。

`use-feed-browse-state.ts` 管理筛选 setter 与会话保存。路由变更在查询渲染前应用范围，显式公众号清除旧分组；有显式查询时以默认筛选为起点解析 `search`（兼容 `q`）、`group`、`dateStart`、`dateEnd`、`dateMode`、`dateShortcut`、`sort` 和 `direction`。无任意路由或源 ID 持久化。清除按钮先重置本地 article.list 查询缓存，防止同查询键仍沿用多页缓存，再移除当前查询串，避免刷新重新应用已清除条件。相对日期以 `shortcut` 标记保存，重新挂载、focus、visibilitychange 和一分钟检查重算；手动日期清除此标记。

`use-article-list-position.ts` 只管理实际文章列表滚动容器。检查点键含公众号、关键词、日期／分组、排序与顺序。保存首个可见文章 ID、相对偏移、像素位置和已加载页数。刷新／返回时逐页调用既有 `fetchNextPage`；最多10页并同步认领分页，遇错误、无下一页或空列表停止。最多8种视图，8小时过期。等分页渲染后用动画帧恢复锚点，失效锚点使用有界像素位置；用户滚轮、触摸、指针或滚动键会停止待恢复动作。

阅读打开前保存内存检查点，弹窗期间暂停列表位置记录，关闭时重新应用检查点。该内存保护在存储不可用时也生效。没有记忆正文位置，不改变 `ArticleReader` 和空 `sandbox`。保存检查点仅触发本地列表读取，不触发更新、下载、正文重试或登录。

## 与并行布局的接入点

- `feeds/index.tsx`：替换原筛选状态声明；缺失分组／源降级；选择清零依赖增加排序；列表 key 加入排序、顺序及清除代次；传入排序 props；日期筛选上方增加可见的一键清除行。布局窗口可移动此行，但保留 handler、可见性和窄屏换行。
- `feeds/list.tsx`：排序提升到父级；指标不可用时等待 summary 成功再降级；调用位置 hook；**实际滚动容器**绑定 ref 和 onScroll；行绑定 `data-article-id`；标题点击及 Modal 关闭绑定检查点。合并布局时保持容器约束及这些属性，勿将 ref 绑定到不实际滚动的父容器。
- `ArticleDateFilter.tsx`／`article-date-selection.ts`：快捷标记及手动编辑清除标记；不改查询字段。
- 刷新 VM 测试夹具新增 hook stub；真实 hook 的刷新／路由／存储由新增浏览器回归验证。既有日期浏览器测试增加快捷标记期望。

所有接入沿用原有组件、筛选接口、查询缓存及分页按钮。服务端、数据库、私人配置、下载流程与桌面启动脚本均无变更。发布前由主任务在统一后的布局再次执行浏览器检查和原有相关回归。

新增状态单元测试接入现有 CI 的离线前端回归步骤。浏览器完整页检查依赖现有 Playwright runtime；不新增 CI 浏览器安装或依赖。

# Wechat2RSS 本机填写与接入检查

本地 Provider、来源选择、缓存读取和原刷新入口已实现。安装软件、配置一致、任务受理及合成测试均不证明真实订阅成功。真实授权、账号登录、目标号列表、正文和图片仍需分别验收。

## 明天由用户填写的入口

在项目根目录打开已有 `.env.wechat2rss`，只修改以下字段，保留其余配置。实际文件与 `.wechat2rss-data` 均被 Git 忽略；不要用模板覆盖已有私有文件。

| 字段        | 本机填写内容                                             |
| ----------- | -------------------------------------------------------- |
| `LIC_EMAIL` | 用户的授权邮箱，使用小写                                 |
| `LIC_CODE`  | 用户获得的激活码                                         |
| `RSS_TOKEN` | 经持久连接批准后设置的独立本机服务密码；不使用激活码代替 |
| `RSS_HOST`  | 本机实例对外生成链接的地址，现有模板为 `127.0.0.1:18080` |

另在已有 `apps/server/.env.local` 中填写 `WECHAT2RSS_BASE_URL` 与 `WECHAT2RSS_TOKEN`。地址应为 `http://127.0.0.1:18080/`，密码须与实例的 `RSS_TOKEN` 相同。不要覆盖原有登录码、其他来源或保存设置。`WECHAT2RSS_ENABLED` 和原有订阅的 `WECHAT2RSS_FEED_IDS` 保持现状；来源启用、目标绑定及受控重启在授权和实测后单独处理，不猜目标 ID。

激活码和服务密码仅在本机输入，不粘贴到聊天、命令参数、截图或 GitHub。避免输出会展开 `env_file` 的 `docker compose config`，也不要分享完整 `docker inspect`、环境文件或启动日志。检查工具只输出字段存在性、布尔结果和固定安全码。

## 填写后的纯配置检查

在项目根目录执行：

```powershell
node scripts/acceptance-wechat2rss.cjs --deployment-config
```

这个模式读取两端已有本机配置，复用当前 Provider 地址与密码格式检查，核对必填字段、邮箱小写、两端服务密码及生成链接地址的一致性，并拒绝把激活码作为服务密码。它不生成密码、不写配置、不启用采集、不启动服务、不联网。不能与 `--execute` 混用。

`DEPLOYMENT_CONFIG_CONSISTENT` 只表示这些本机配置互相一致。缺字段、密码不同、地址/协议不同或邮箱大小写错误会返回对应固定安全码和退出码1；缺少与当前源码对应的后台构建会返回 `SERVER_BUILD_REQUIRED`。这不验证激活码真伪、许可、账号、额度或图文。原无参数预检仍只检查 WeWe 配置，不读取实例授权文件。

## 实例、数据与媒体边界

现有 `docker-compose.wechat2rss.yml` 只有一个 `wechat2rss` 服务，固定监听 `127.0.0.1:18080:8080`，持久绑定 `./.wechat2rss-data:/wechat2rss`。Docker 程序和虚拟磁盘在 E 盘，不会使这个相对绑定目录自动迁移到 E 盘；若要把实例数据也放到 E 盘，先核已有目录，在批准后明确设置新路径，保留原数据。

`RSS_HOST` 影响生成的 Feed 与媒体链接，不改变实际监听地址。现有 compose 使用 `RSS_PROXY_DISABLE_IMG=1`，保留原微信图片地址；Provider 与保存器已有图片校验通路，真实图片字节及离线保存仍待实测，不能用地址一致或 HTTP200代替验收。授权和这些参数的含义以[官方配置说明](https://wechat2rss.xlab.app/deploy/config)为准。

模板使用此前核对的固定镜像 digest，不能把它称为当前最新版本。获得私有实例启动及持久连接批准后，再核镜像、启动、由用户完成登录。今天推迟密钥输入时，不执行启动或激活命令。

## 仍待真实验收

1. 本机激活、服务密码认证、用户正常登录；遇认证或平台限制即停。
2. 一个已确认公众号的稳定号身份、不同文章 ID、真实发表时间及最新十篇列表。
3. 十篇完整正文、实际图片数量/顺序/字节与同篇本机归档，断网可打开。
4. 原刷新入口再次更新新增0、旧正文和图片不被空值覆盖；持续更新与订阅前历史分别记录。

活动生产包可能早于本地候选包。接入前重新核对重启后的进程身份、实际版本和数据库，完成一致性备份及副本演练后再按授权受控部署或重启；不能沿用重启前 PID。纯配置检查与离线回归不写生产库，也不替代这些验收。

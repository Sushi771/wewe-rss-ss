# 未来导出的文章标题与原文链接

重复原文链接来自两个应用模板的叠加：`exportSourceMarkdown` 在来源信息区写入“原文链接”，`buildArticleMarkdown` 调用的指标模板又在标题下写入“原文”。已部署来源 `a5e8f2544f7836df503794d684f5b607cccc071e` 和本补丁基线 main `f8954127ea55d29f4a6edd7d2688f87c27397ed2` 都有这条路径。正文里的作者引用不是这一重复项。

按用户指定目录只读抽样的两篇 Markdown，各有一个与文件名相同的模板 H1，没有两个正文文章标题；各有两条指向同一 URL 的平台来源行。Obsidian 的 [Show inline title](https://help.obsidian.md/settings#Appearance) 会把文件名显示为正文上方的可编辑标题，不会把这一标题写进笔记。这里处理文件名标题与导出器 H1 的重复，不按文字猜测或删除文章中的标题。

未来通过缓存文章入口保存到 Obsidian（单篇、并行保存、整号离线目录）时：

- 保留文章文件名作为 Obsidian 标题，不再额外生成 Markdown H1；缺正文的提示文件也使用文件名标题。
- 保留来源信息区的公众号、分组、发布日期和唯一一条“原文链接”；标题下不再重复生成“原文”。没有原文 URL 时保留“未记录”，不伪造地址。
- 正文的正常引用（包括指回同一篇文章的作者链接）、小标题、引用内标题、图片和指标保持原有转换与校验。

浏览器 Markdown 导出仍保留一个文章 H1和来源信息区的一条原文链接。直接调用正文渲染器的其他入口默认行为不变，仍能取得原有标题和原文链接。新渲染参数仅是内部模板选择，不是新增 RPC 输入，不改变图片完整性、回执或保存准入。

本补丁不修改 Obsidian 设置，不扫描迁移旧笔记，也不改已有文件名。既有完整笔记再次导出仍复用旧文件；包括旧重复标题、重复原文链接和用户修改在内的内容与回执保持原样。所有本地回归使用临时目录和合成文章，图片为内嵌 PNG，网络被拒绝；没有读取或复制生产数据库，没有新增整库备份。

定向回归覆盖浏览器、单篇及并行 Obsidian 保存、整号目录、缺 URL、缺正文提示、直接渲染器默认值、正文引用/小标题/引用标题、图片字节以及旧文件/回执保留。main 来源边界清单只更新本次实际修改的 `getArticleMarkdown` 和 `buildOfflineFeedDirectory` 两个成员哈希，其他边界保持原值。

main 已将导出指标模板独立为 `article-export-metrics.ts`；a5 仍从 `collection/collection-format.ts` 导入共享模板。向 a5 回移时应进行函数级适配，保持共享报告的默认输出，不能整文件覆盖或把本补丁假称已部署。此开发 PR 不包含部署或合并授权。

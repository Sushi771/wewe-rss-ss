# 文件夹内订阅选择与添加弹窗

文件夹中的订阅被点击后，页面保持该文件夹选择，同时选中订阅并按订阅 ID 请求文章。桌面侧栏和手机选择框都把站内点击的文件夹上下文传给路由；直接进入单源 URL 时，仍不继承无关的历史文件夹限制。文件夹已删除时沿用已有的回退行为。

原有浏览状态 hook 在进入任何单源路由时都会把文件夹设为“全部”。隔离浏览器挂载实际 Feeds、ArticleList、Router 和状态 hook 后，复现了点击源时路由与文章请求仍指向该源，但侧栏文件夹选择被重置的问题。修复只接受与当前源 ID 匹配的站内导航上下文，不用单独的选择状态覆盖路由。

文件夹的“添加订阅”弹窗明确挂载到 body，复用现有订阅对话框的高层级和正文滚动样式。原有 NextUI 包装层为 `z-index:50`，应用粘性工具栏为 `100`；真实生产样式下，弹窗标题的点击命中工具栏。修复后包装层位于工具栏上方，标题、正文和底部操作在短屏上仍可访问。

## 验收

`scripts/folder-selection-overlay-browser.test.cjs` 使用真实组件、Router、TanStack Query、Tailwind / NextUI 配置与生产样式；只有后端数据和分类保存回调使用合成数据。

1. 在正常浏览模式拖一个订阅到文件夹，打开该文件夹，再点击订阅名称。路由、选中行、文件夹选择和文章查询范围必须一致。
2. 打开文件夹更多菜单中的“添加订阅”。在桌面、390×500 手机短屏和667×375横屏下，标题及底部按钮的命中目标须在弹窗内，弹窗不得超出视口；复选框能实际点击。
3. 直接访问另一个单源 URL，应显示该源，不继承前一个文件夹造成空列表。

## 已打开页面的后台更新

现有自动更新链路保持不变。后台缓存事务提交新建或更新的文章后，递增进程内缓存版本；`feed.cacheRevision` 只读取该版本，不读取数据库或调用平台接口。已打开的文章页面在可见、聚焦且联网时每秒检查版本，版本变化才使当前文章、摘要和订阅查询失效并重新读取本地缓存。采集完成但没有数据变化时，不重复刷新文章列表。

页面隐藏、失焦或离线时暂停检查，恢复后补查最新版本。更新前捕获可见文章和位置，更新后恢复滚动锚点；当前订阅、文件夹和查询筛选不会重置。此行为依赖页面仍然打开且前台服务可达。

同一浏览器测试文件中的独立自动更新用例挂载真实 `useCacheRevision`、Feeds、ArticleList 和 TanStack Query。合成后端只模拟提交后版本通知与本地文章响应，验证新文章自动出现、路由和完整查询参数保持、可见文章锚点偏移保持在两像素内、无数据变化不重读文章、隐藏期间不轮询，以及恢复可见后补更新。既有 `cache-revision-watch.test.cjs` 另覆盖通知合并、失败退避和失败重试。

本轮不修改数据库分类、后台采集或生产配置。浏览器验收为隔离合成数据测试，不能据此声称已在生产页面实测；公开 CI 核对最终提交后再由生产窗口整合验收。

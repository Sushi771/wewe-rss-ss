# Windows 冷启动身份查询续测（2026-10-05）

在 PR18 的不可变 compact 包上，仅优化既有 C# 身份工具：已知 PID 时，直接读取对应的 `Win32_Process` 实例，省去 WQL 查询与结果枚举。使用 [微软定义的 Handle 主键](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process)及 [ManagementObject.Get](https://learn.microsoft.com/en-us/dotnet/api/system.management.managementobject.get)。这里的 WMI Handle 是 PID 字符串，与一直持有的 OS 进程句柄不同。

保留 OS 句柄、创建时间交叉核对、可执行文件和完整命令行、前后 IPv4/IPv6 监听归属、退出检查及 Stop 的全部预期身份匹配；新增 WMI 主键显式匹配。异常继续拒绝操作。身份工具仍按源码 SHA 编译，并在每次调用前核对缓存 receipt 与可执行文件 SHA。没有更换身份工具选择机制或 PowerShell 回退路径，也没有更改 ExecutionPolicy。

## 同包冷启动对照

两组各按旧、新、新、旧、旧、新顺序运行。每次应用均已停止，使用独立端口及事先准备的一致 SQLite 副本；未清除 OS 文件缓存，也未重启机器。计时包含首次空端口 Discover、包与 receipt 校验、启动前新建一致性备份和全字段保护、迁移检查、真实 Nest/Prisma 启动、匿名 RSS 拒绝、临时私有登录、授权 RSS 和最终完整身份及指针校验。已有同包完整验收 receipt，每次日常冷启动仍检查一篇真实 RSS；初次安装/更新的 20 篇合同不变。

| Controller 总耗时，秒 | 对照组一 | 对照组二 |
| --------------------- | -------: | -------: |
| 旧查询，第 1 次       |    2.923 |    2.977 |
| 直接读取，第 1 次     |    2.757 |    2.703 |
| 直接读取，第 2 次     |    2.712 |    2.808 |
| 旧查询，第 2 次       |    2.778 |    2.736 |
| 旧查询，第 3 次       |    2.725 |    2.713 |
| 直接读取，第 3 次     |    3.172 |    2.836 |

合并六次的身份 Snapshot 中位数从 **0.422 秒降到 0.350 秒**；含空端口检测的身份工具总耗时中位数从 0.767 秒降到 0.733 秒。另一个仅身份工具的交替测试，中位数为 0.385→0.349 秒。每次对同一仍存活的测试进程分别调用旧、新工具，返回的完整身份对象完全相等。

**总耗时没有得到稳定改善：** 两组 controller 中位数分别为旧 2.778/新 2.757 秒、旧 2.736/新 2.808 秒；合并中位数旧 2.757/新 2.783 秒。身份查询的局部节省不足以压过其余步骤波动，不能把本补丁写成整体冷启动加速或稳定三秒完成。

## 仍然消耗时间的步骤

第二组加了低开销 controller 分段计时，没有给子进程注入 profiler。各行是该组六次的范围：

| 步骤                                    | 秒的范围    |
| --------------------------------------- | ----------- |
| 首次包 guard 加 controller receipt 校验 | 0.053–0.059 |
| 全字段基线、一致性备份及副本独立值比对  | 0.788–0.845 |
| 子进程启动及完整私有 HTTP/RSS 就绪验收  | 0.980–1.064 |
| 完整进程身份 Snapshot，直接读取后三次   | 0.347–0.385 |

此外仍包含空端口探测、准备副本 marker/SHA 核对、最终指针核对和文件操作。已有 compact 包的探活间隔是 50 毫秒。本轮未重测浏览器、WSH/根 Node 进程启动或整机断电后的文件缓存；controller 的数字不能当成点击到页面可操作的时间。先前 [实际页面测量](WINDOWS_COMPACT_COLD_START.md)的稳定三秒目标仍未完成，也没有证据把这些耗时称为 Windows、磁盘或 Nest 的固定下限。

尝试在不改变摘要格式的前提下逐行流式计算相同 JSON SHA：三次对照完整摘要一致，但只有约 0.01 秒局部节省，因此未纳入补丁。没有以删备份、弱化完整字段检查、少校验身份或跳过迁移来换时间。

## 验证和整合边界

相关 Windows 测试 **27 项通过**：IPv4/IPv6、闭端口、已建立连接排除、外来 PID 拒绝、精确 Stop 及每个身份字段不匹配拒绝、原 PowerShell 身份等价、编译缓存篡改和启动 guard。十二次真实私有冷启动的测试库与新备份都由独立 Python 检查器再次对全字段基线核对，通过；offline guard 的外部网络和子进程拦截计数都为零。没有执行刷新、取文、登录腾讯、修改用户账号或配置。

源码修改只有 `process-identity.cs`；CI 增加 PR18 分支作为 stacked PR 的目标分支，确保这一续测有自己的 Windows 和其他工作流结果。原始时间、身份和数据库证据只放在忽略的本地输出目录，公开文档不包含真实数据库规模、数据、私有路径或运行身份。

整合由唯一 owner 审查本补丁及对应 SHA 的 CI 后执行。新源码会产生新的身份工具缓存，首次编译不包含在上述稳态日常冷启动时间内；整合演练应包含这一步。此前运行包的 payload 未变，不能把旧包的源码 provenance 写成已包含本补丁。没有操作主工作区或生产端口，亦没有正式部署。

# 工具 → 文章下载

## 当前来源约束（2026-10-10）

公众号单篇下载**仅使用 Wechat2RSS**，不采用优先加兜底模式。2026-10-10 用户已明确授权必要时订阅整号来执行单篇下载。已有精确缓存时立即保存；否则持久保存目标与本次目录，通过现有订阅批次队列按需受理公众号，精确正文就绪后自动落盘。按需订阅是后台既有行为，不需要另外点击订阅；界面仅保留简短进度与结果，来源说明记在本文。实际服务缓存不含短链接映射时，整号订阅也不能确定目标，必须停止并由用户在工具页内明确选择已缓存文章后直接保存；不需要手动复制长链接，不能保证任意短链接无操作下载。不会抓取微信原文页面、调用停服旧中转或其他正文服务，不复用 SQLite 中来源不明的旧正文。浏览器回送的其他渠道正文不能绕过唯一来源约束；旧浏览器任务仍可查询和取消。

已重新完整核对 [Wechat2RSS 官方 API](https://wechat2rss.xlab.app/deploy/api)、[使用说明](https://wechat2rss.xlab.app/deploy/guide)、[常见问题](https://wechat2rss.xlab.app/deploy/qa)及当前实例已取得的官方静态前端。`/api/query` 仅支持 bid、before、after、content，没有按文章 URL 查询或解析的合同；静态前端的文章链接按钮只调用 `/addurl`，用于订阅。`/addurl` 等同添加公众号并触发更新，不能作为无副作用的单篇解析接口。官方历史说明只抓取最新20篇，不主动抓取历史；新增整号也不能保证给定旧文章可取得。

长链接复用 GET /list 和对应 `/feed/:id.json`；普通短链接先查官方 `/feed/all.json` 合集缓存，在同一 JSON Feed 条目的 url、external_url、id 中核对精确短链接及稳定原文链接。按需订阅受理后，使用已核公众号 ID 定位该号的原始 JSON Feed，仍执行同样的精确映射。`/addurl` 返回的公众号 ID 不代表输入文章 ID；整号订阅后若仍没有短链接映射，不能按标题、最新一篇或文章顺序猜目标。输出数量、合集静态模式及安全大小限制都可能影响读取。此能力仍不保证任意短链接或所有历史文章可取得。

## 使用

2026-10-10 用户最新确认的公众号导出规则为 `YYYY-MM-DD_分组/公众号/文章标题.md`，图片位于公众号目录下的 `image/`。日期取可信原文 `publishTime` 在 `Asia/Shanghai`（上海时区）的日期，不能使用下载时间、缓存时间或当前日期。例如：`2026-10-05_上海教育垂类/科斯的自留地/前滩音乐节归来！很嗨！.md`。无可信原文发布日期时使用“日期待核”前缀，并提示原因，不猜日期；无分组使用“未分组”。重名、路径字符及去重规则见 [文章离线目录](OFFLINE_ARTICLE_LAYOUT.md)。新规则由导出负责人接入并验证，本文更新不代表已部署。

不立即迁移旧笔记；同篇重下载继续保护已有笔记及用户编辑。任务沿用已确认的保存根，分组变更不移动磁盘上的已有文件，也不改变进行中任务保存位置。前端保持简短结果与必要的日期待核提示，不恢复常驻目录教程。

工具页保留文章链接、保存位置和下载按钮，保存位置旁的「更改」仍调用本机目录选择器。「下载设置」默认折叠，展开可调整「每次下载询问路径」；折叠不改变已记住的偏好。来源、缓存限制与保存布局记录在本文及离线目录文档，前端不再展示常驻技术说明或长帮助。前端不再一刀切拦截普通短链接或要求用户手动提取长参数。

在运行服务的 Windows 电脑上进入「工具 → 文章下载」，直接粘贴 HTTPS 微信公众号文章链接，确认本机目录，再点击「下载正文和图片」。已有缓存直接保存；未就绪时返回任务回执，后台按需订阅并继续等待。关闭页面或重启后保留任务；再次打开查看结果，可取消尚未保存的下载。取消不会撤销已受理的公众号订阅，正在落盘时等待保存结果。风控或订阅失败会停止，处理账号后可继续原请求，不重发已有回执。Wechat2RSS 必须已启用且私有配置有效；凭据仅在后台配置中读取，不返回浏览器或日志。真实命中及保存仍由用户实测。

单篇任务由 `Wechat2RssSingleTasks` 持久保存于 SQLite 同目录的私有 `.wechat2rss-single-downloads`，只接入既有 `TrpcService.registerSubscriptionConsumer`，不创建独立定时器。订阅受理复用 `addSingleDownloadBatch([url])` 的原回执与幂等保护。缓存检查至少间隔30秒、最多10次，整体自动等待最多15分钟；到期仍无目标则明确失败，保留已有订阅和旧笔记。整号缓存已就绪却没有短链接映射时，当次停止，不再当作正文尚未就绪而重复等待。任务绑定访问密码归属及原生目录选择时的目录，后续路径偏好修改不会重定向任务。状态查询仅读本地记录和已有批次回执，修订号防止迟到状态复活已取消任务。风控失败处理后可显式「继续原下载」；缺短链映射时提供该号已缓存文章列表入口。

新规则接入后，成功保存沿用已确认的保存根，由可信原文发布日期及 Feed/分组身份生成日期\_分组→公众号→标题.md 和该号 image/；不创建每篇文章子目录。正常名称纯可读，同名或清洗冲突时才加稳定 ID 后缀，见[统一离线目录](OFFLINE_ARTICLE_LAYOUT.md)。目录选择、路径记忆、每次询问的一次性许可、同源/访问密码检查和排他保存继续保留。旧同篇笔记及用户编辑不覆盖；旧任务不会被当前路径偏好重定向。来源元数据缺失时清晰停止，不按标题猜公众号或分组；发布日期缺失按“日期待核”规则处理。

正文来源与媒体请求分别判断：正文只取 Wechat2RSS；该正文中必要的微信 CDN 图片使用原共享图片归档器下载、校验真实字节并落盘，这不是原文页面抓取。缓存中无源或未核图片项不能证明原篇媒体齐全；可靠正文和有效图片仍可保存，正文及回执明确标记“媒体完整性未确认”（mediaComplete:false），不把未知项当成已归档图片。已知图片地址的字节校验失败、非法媒体地址以及无可靠归档合同的公众号视频/音频仍停止保存并保留旧笔记。普通 iframe 沿用原安全清理策略。小红书独立路径已有视频字节、容器校验和 video/ 保存不受影响。

## 本轮验证与发布边界

已受理的单篇请求可能关联暂停或停止的采集批次。此前单篇在 paused/stopped/blocked 分支提前退出；“继续”还删除停止批次 ID，导致回到原停止回执，候选按钮只对 failed 展示。已有缓存不应因此被阻断；是否有精确短链接身份映射仍须独立判断，不能自动猜选目标。

修复后“继续原下载”仅重新检查原单篇已有缓存，保留原批次及原确认根，不恢复停止的采集批次、不重复新增或强制更新。已核原 URL 哈希及公众号身份的 paused/stopped 回执也能读精确缓存；无短链映射时立即停止并提供候选，不继续假等待。blocked/failed 都可在工具内打开候选，仍核归属、实例、原回执和稳定文章身份。候选读取不再以采集账号登录状态作为缓存权限门槛；缓存 GET 失败报告缓存读取错误，不伪造账号风控。用户选择后只读重新核验目标缓存，再使用统一导出出口；程序不替用户选择。任务状态只读派生原批次状态和 updatedAt，未增设持久恢复标志。

- 接口：`POST /download/article`，JSON`{ "url": "..." }`；成功返回保存路径JSON，错误返回中文`message`和脱敏诊断。开启每次询问时另需本次原生选择产生的一次性`pickToken`，不能通过浏览器JSON指定任意写入路径。设置读写及目录选择为`/download/article/settings`和`/download/article/directory`，沿用访问密码，限制回环Host/连接与同源操作，远程/私人线上模式拒绝本地保存。
- `article-export.ts` 是从 `TrpcRouter.getArticleMarkdown` / `downloadImage` 抽出的既有正文与图片导出代码。原 Markdown、Obsidian 和公众号 ZIP 仍调用相同方法；默认图片下载逻辑不变。
- `offline-archive.ts` 抽出原 `OfflineExportController` 的 ZIP 打包代码，公众号 ZIP 与工具共用。
- `article-download.ts` 只连接单篇 URL 与上述导出方法，复用 `articleIdentity`、`articleContentHtml`、`publicArticleRequestUrl`、`allowedImageUrl`、`decodeInlineImage`。离线 HTML 使用导出方法已本地化的同一正文。
- `article-download-cache.ts`只读查询精确身份，复用`bodyRetryTarget`、`decodeInlineImage`及原Markdown导出器；不写文章数据库，不调用平台或续期。缓存分支拒绝外部图片，并沿用原单篇HTML清理和本地发布流程。
- 工具偏好独立保存在SQLite文件旁的已忽略`.article-download-settings.json`，不改订阅或既有Obsidian配置。文件先在所选日期目录的临时子目录完整准备，最终目录以排他创建保留，文件写入不覆盖。失败只回滚本次创建的文件，既有笔记不删除；完整标记写入后才返回成功。

`article-export.ts`新增受限的图片目录选项，旧调用仍默认`attachments`，工具选`image`；不复制转换或媒体保存实现。路径必须是普通本机绝对目录，拒绝磁盘根目录、UNC和链接目录；已存在同名无标记笔记目录用新名字，已有完整同篇笔记直接返回已保存，不覆盖正文。

安全边界：只接受 HTTPS 微信文章 URL；只保留文章身份和内容签名参数；不传递微信 Cookie、账号令牌或用户输入的会话参数。文章与图片均禁止自动重定向、代理和重试，网络连接时校验并固定 DNS 地址，拒绝内网及保留地址。远程正文上限 5 MB，图片最多 60 张、单张 10 MB、总计 20 MB，复用已有图片容器校验。清除执行型 HTML、正文外链与动态属性，离线 HTML 使用限制性 CSP。现有 `WEWE_ACCEPTANCE_MODE=1` 会阻止工具保存。

一次只允许一个工具下载请求；并行请求返回 409。工具不调用订阅 Provider、微信读书账号或 Obsidian 配置目录；文章库查询为只读。用户已提供的单篇短链接曾返回匿名HTTP302验证跳转，保留停止且未重试；最新订阅目录及10篇正文也未提供该短链的可信身份映射。该URL的真实直接保存Obsidian仍待正常页面的可靠依据，不能造reviewId、转用读书Cookie或用ZIP/人工HTML替代。[订阅10篇正文图片验收](LATEST_TEN_IMAGE_ACCEPTANCE.md)是独立结果，不证明该受阻短链接已恢复。

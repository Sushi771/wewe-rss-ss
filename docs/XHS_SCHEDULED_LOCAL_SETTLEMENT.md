# 调度列表的正式未发送结算

普通停止与未发送结算是不同操作。普通停止中断后续处理并保留记录，不能把未知请求改成未发送，也不能生成成功采集回执。现有任务不应再被当成旧式来源 job 建立 stopped 占位；已存在的 stopped 占位仍完整保留。

本扩展复用“核查并取消未发送的旧批次”的只读预览、显式确认、真实一致性备份门禁和同事务审计。保留原 v1 证明，同时为两种严格调度形态生成 v2 证明：

- 纯列表 basic 调度任务在上下文准备前停止，具有匹配的 `XHS_ACCESS_CONTEXT_EXPIRED / prepare / dispatched=false`，没有上下文尝试或来源证据。
- 纯列表任务在调度准入构造器中被写为 `XHS_SCHEDULE_SOURCE_BLOCKED`，尚未进入队列；必须具有精确的原调度审核绑定、完全未使用的专属请求预算、初始任务结构及零来源账本。仅凭账本缺失不能通过。

源端错误、结果未知、运行中、任何来源请求账本、已使用预算、任务绑定变化、关联恢复任务或不能证明的字段均维持保护。原调度审核必须通过既有策略/基线只读证明，真实限流和认证状态仍会阻止确认。

对先前普通停止生成的遗留 job，只接受精确匹配本次已证实未发送任务的 stopped/null-outcome 记录，且时间顺序一致。审计包含原批次/子项、任务、审核、预算和该停止记录的摘要。确认不会删除或改写遗留 job，不会伪造 complete；来源围栏仅承接这份完整且仍匹配的局部结算证明。任一证据变化都会重新关闭围栏。未知账号、未知请求、真实限制及其他暂停项不受豁免。

已确认结算不会因后续会话轮换或策略撤销而被当成未结算；它也不授权新的来源操作。原 operation 继续不可恢复。后续列表更新必须是另一个明确批准、重新准入的批次，并精确排除尚未解决的历史未知账号。

对于“已停止的准备失败”和“因此受阻的新调度项”同时存在的情况，应先预览并结算前者，再重新预览后者。确认之前按真实备份门禁重新核验；不能以业务表相等冒充全库快照可复用，不能擅自增加长期备份数或删除受保护恢复点。不得普通停止后不断创建新批次。

该变更不自动确认生产结算，不恢复暂停批次，也不发出来源请求。隔离回归使用真实 Prisma/SQLite、真实备份副本及合成来源，验证并发、重复确认、回滚、正反证据、前端解析和结算后的独立新批次准入；不能把这些结果称为真实更新已经恢复。

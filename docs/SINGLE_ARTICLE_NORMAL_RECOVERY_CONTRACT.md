# 单篇链接：正常验证后接回现有保存器的契约（2026-10-05）

续办从已提交 `5b77e440ced3a2e6ce395affe2b62fba6964207c` 建立独立 worktree / `codex/single-article-verified-adapter`。下载侧现已实现正常取文结果到原保存器的内部适配，当前缓存保存也复用其导出代码。不新增 HTTP 正文上传入口，不部署，不改账号验证后端。目标短链的真实正文来源及浏览器内容传输仍未取得。

## 已实现的服务内部调用

主 owner 的正常取文流程完成现有正文核验及 `archiveProviderImages` 后，可在用户单篇保存的原有本机授权请求内调用：

```ts
return app.get(ArticleDownloadController).saveVerifiedArticle(
  archivedArticle, // 服务内部已核验、图片已归档的 ProviderArticle
  { url: requestedUrl, pickToken: originalPickToken },
  req,
  res,
);
```

方法没有路由装饰器，不接受页面 JSON 中的 HTML、文章对象、图片缓存或保存路径；不查询 / 写入数据库，也不请求平台。正常验证完成不代替本机保存请求的 AUTH_CODE、Origin、loopback 及目录选择授权。调用方应保留原始单篇请求及选目录令牌，不转发验证码接口的整个请求体，不把外部 JSON 标为已核验结果。

`prepareVerifiedProviderDownload` 复用 `assertProviderPage`，要求 canonical ID / 公众号 / 标题 / 可信时间有效，短链与结果 `shortUrl` 精确匹配，长链与结果 canonical 一致；再要求完整正文、全部内联图片字节、60 张 / 20 MB 图片预算及 5 MB 非内联正文预算。已内联 HTML 上限 35 MB。成功生成不可变内容快照，经共享导出器和 `LocalArticleStore.save` 发布为 `正文.md` 与 `image/`。返回 `contentSource: verified-provider`。错误返回固定诊断，不退回匿名取文、不发布成品。

该调用共用原控制器的设置 / 选目录 / 保存锁，保留“每次询问”及一次性选目录令牌，不覆盖旧笔记。缓存下载继续精确查找已有记录，并经同一个完整内容导出器发布；历史文章 ID 保持不变。`/download/article/verified` 不存在，原 `/download/article` 仍拒绝外部正文对象。

接口所有权：本分支负责下载侧验证、发布和内部方法；主 owner 负责正常验证与真实内容来源，仅在其既有流程取得目标结果后接入上述方法。本分支没有替主 owner 新增账号验证、目录 / 正文网络请求或授权状态。

## 用户现在只需做的一步

> 请在 Edge 直接打开原文章链接，亲自完成微信官方验证；能看到完整正文和图片后，只回复“能打开”即可。

当前用户尚未确认这一步成功。无需先采集标题、长链接参数、Cookie、票据或 HTML。回复“能打开”只证明本人浏览器可读，不能表示 WeWe 已取到正文或下载完成。账号正常腾讯验证由主 owner 协调，不增加扫码或重试。

## 当前可用能力与边界

| 条件                                                       | 当前原有下载入口的真实行为                                                                                                               |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 输入 URL 精确命中本机唯一已核验文章，正文和图片字节完整    | `findCachedDownloadArticle` → `buildCachedArticleDownload` → `LocalArticleStore.save`；返回 `contentSource: saved-article`，不请求平台。 |
| 本机有匹配记录，但身份、正文、图片、可信时间或唯一性不通过 | 返回 `CACHED_ARTICLE_UNAVAILABLE`，不退回取文。                                                                                          |
| 本机无匹配文章                                             | 使用原有独立匿名 HTTP 下载器；没有 Edge Cookie，不跟随重定向、不自动重试。                                                               |
| 用户在 Edge 完成原文验证                                   | 当前没有从该已打开标签页到 WeWe 的受支持正文 / 图片字节传输，不能自动恢复后台下载。                                                      |

本轮只读 SQLite 核验为 2 个账号、12 个订阅、1450 篇文章，`quick_check=ok`；目标短链在文章 ID、原始 URL、核验 URL、正文中均未匹配。此前已保存目录的 40 条真实列表映射也没有目标 `originalId`。不能据此猜公众号、长链参数或 `reviewId`，也不能拿其他已下载文章的成功替代本条链接验收。本轮没有请求受挑战链接、操作验证或写生产数据库。

localhost 页面用 `window.open` / iframe 打开原文，并不取得跨源页面 DOM 的读取权限；CORS 也需要上游配合。见 [MDN 同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)。所以“打开页面 → 点已验证 → 重试后台”的按钮不能补齐会话通路。

此前候选源码结论见 [单篇下载会话研究](SINGLE_ARTICLE_DOWNLOAD_SESSION.md)，不重复把匿名 fetch、已停维 exporter 或目录转换当作新方案。官方 Obsidian Clipper 能处理当前页，但 [官方说明](https://obsidian.md/help/web-clipper/capture) 明确图片仍为远程 URL；所核源码也未提供 WeWe 可调用的本机正文传输接口。它目前不满足本任务的自动直存正文及实际本地图片，未安装或运行。

## 主 owner 可以交付的最小内容契约

服务内部已核验 ProviderArticle 的保存适配现已实现；以下浏览器读取 / 传输仍是前置条件，**没有新增 HTTP 正文接收 API**。不要求用户手动保存 HTML、导入文件或发送一堆字段。

### 路径 A：真实取文结果已经由现有订阅通路保存

主 owner 若取得目标的实际目录映射和正文，应沿现有 `parseWereadDirectory` / `verifyWereadArticleBody` / `archiveProviderImages` 路径核验并保存，遵守备份与副本演练要求。必须保留目标短链与实际 canonical 文章身份的可核验关联，使输入短链精确命中 `sourceUrl` 或 `verifiedSourceUrl`，并保留对应的可靠长链身份。正文图片必须已经是已校验内联字节，不能仅有外链。

原下载入口可直接复用该记录，无需增加传输端点、放开原有鉴权或修改保存器。不得按标题匹配、猜 `reviewId`，也不应为了本条链接扩大刷新到其他订阅。

### 路径 B：受支持、获授权的当前页读取器提供内容

先由主 owner 确认具体读取工具、合法授权及其内容传输能力；工具拒绝网址或安全停止时停止，不改用 CDP、浏览器秘密或自定义 UI 自动化绕过。读取器只传本次文章内容及图片，不传 Cookie、浏览器存储、请求认证头或验证票据，不新增未经授权的扩展安装或永久密钥。

服务内部现有 `buildArticleDownload(raw, directory, request, options)` 的 `request(url, maxBytes)` 注入点可以复用；它不是公开 HTTP 接口，也不是已有浏览器适配器。适配器需一次性提供以下真实结果：

| 数据     | 必须满足的条件                                                                                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 请求绑定 | 绑定用户输入且经 `downloadArticleUrl` 规范化的单条 URL；短链要与页面真实 canonical 一致。                                                                                                                                         |
| 正文     | 实际可读完整正文、标题及公开文章身份元数据，足以让 `articleIdentity` / `articleContentHtml` 原有解析器核验；不得把只有可见段落的 DOM 快照、标题或口头确认伪装成完整页面。只提取解析所需公开元数据，不执行页面脚本，不传无关秘密。 |
| 响应     | 回调返回真实取得结果的 `{ bytes: Buffer, type: string, status: number }`，遵守传入 `maxBytes`；不得把失败响应改成 200，或为没有取得的内容生成样本。                                                                               |
| 图片     | 每个原有正文图片 URL 对应实际取得且 MIME / 文件签名一致的字节；或使用原有校验器接受的内联图片。只看到图片、获得 URL 或获得 Markdown 都不足以保证本地保存。                                                                        |
| 失败     | 验证页、拒绝读取、身份冲突、缺正文、缺图片立即失败，不回落到新匿名请求，不自动刷新标签页或验证。                                                                                                                                  |

现有构建器继续承担短链 / 长链身份检查、验证页识别、5 MB 正文、60 张图片、单图请求 10 MB、图片总量 20 MB 的边界，以及脚本清理和原有 Markdown / 图片导出。适配器不能为通过检查而放宽这些边界。当前工具目录没有受支持的 Browser Use、`node_repl` 或 CDP 会话，所以本轮无法实现并验收路径 B。

最终仍使用 `LocalArticleStore.save`：下载日目录 / 每篇独立文件夹 / `正文.md` 与 `image/`，图片相对路径，记忆原生选目录，默认不每次询问。保持 loopback、原有授权及 Origin 限制，HTTP JSON 不得指定任意目录。构建器写的是临时 `index.md`，保存器发布为 `正文.md`；构建失败不发布成品。重名及重存复用原有不覆盖旧笔记策略，不删除用户文件。

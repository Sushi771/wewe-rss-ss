# 未归属旧请求的限定新轮次

旧请求结果无法证明时，保留原 owner、原始风险快照、历史任务及预算，不声称旧请求未发送或成功。只有本机受保护接口接收明确确认、完成既有停写备份及状态摘要核对后，才建立新的审查记录。

入口依次为 `prepareUnboundThreePageRound`、`confirmUnboundThreePageRound`、`executeUnboundThreePageRound`。预览和确认绑定三个现有且启用的账号 ID 及来源作者 ID。执行只请求每号的资料和第一页目录，各物理请求独立计数、记账；不翻页、不续旧任务、不自动启动以后轮次。当前实现保存目录条目，不下载正文和媒体。

started 和原有总预算、账号预算预留在独立事务中提交后才进入来源传输。已批准保留的旧预算标记须逐字段匹配原快照；不删除、不退款。目录保存、成功回执和风险释放同事务提交。传输或提交结果不明时保留 pending/unknown 并停止余下账号；平台限制写入原风险状态，缺少新轮次上下文的其他来源入口继续拒绝。

验证覆盖：完整服务端 noEmit 编译、改动文件 lint、新增真实 Prisma/SQLite 保存回归，以及既有风险、会话和旧审查回归。旧审查测试同步已准备的契约修正：未归属 unknown 必须继续挡住未经新审查的其他账号。另以合成传输验证原一次性许可消费器、六次物理请求、三份目录保存、未知结果全轮次停止及预算回滚。

这些验证不等于生产采集成功。生产结果须以安装版本、请求回执和实际数据库保存数量另行报告。

# 分离文章列表的实际服务等待

仅在诊断启动时设置 `ARTICLE_LIST_READ_TIMING=1`。由唯一生产操作窗口通过既有受控启动流程设置，复用实际进程、单连接和原库；不另启服务、复制数据库或扩大连接池。关闭时取消该变量或设为 `0` 后正常启动，不注册原生 query 日志，读取与安全门禁保持原路径。启用不自动发送请求或改变数据。

诊断只向进程现有日志输出 `[ARTICLE_LIST_READ_TIMING]` JSON。使用原有私有日志目录，不发布原始运行日志。每进程最多记录前32次列表读取和2048条事件，模块加载10分钟后不再建立观察。它不是常驻追踪系统，也不添加 HTTP 接口、任务或新存储。读取失败或日志输出失败不会触发读取重试，日志失败也不能改变业务结果。

`read` 事件的 `read` 是进程内序号，`cache` 明确区分 `hit`、`miss`、`bypass` 与合并等待的 `coalesced`。它记录 helper 总耗时、前后数据库身份/100字节头校验阶段及快照阶段，不记录文件路径或修订值。命中及合并等待没有本次数据库事务时，相应事务段为 `null`，不能当作零耗时 SQL。

| 字段                            | 对应实际边界                                        | 可作出的判断                                            |
| ------------------------------- | --------------------------------------------------- | ------------------------------------------------------- |
| `coordinatorWaitMs`             | `$transaction` 被请求至 `sqliteWrites` 调用底层事务 | 协调门禁/备份准入等待；不绕开原门禁                     |
| `connectionBeginWaitMs`         | 已准入至事务 callback 进入                          | 连接池及 BEGIN/引擎请求等待；不是精确的纯连接池耗时     |
| `callbackMs`                    | callback 进入至退出                                 | 当前快照内的查询、结果处理及其他 callback 工作          |
| `commitReturnMs`                | callback 退出至原事务 promise 返回                  | COMMIT/引擎返回阶段；失败时也保留原异常                 |
| `phasesMs.revisionBefore/After` | 原修订令牌函数调用前后                              | 主文件头与 stat/journal 检查的实际异步等待；无全库 hash |

`transaction` 事件记录同一 PrismaService 客户端的请求、准入、callback 进入/退出和返回。非列表事务的 `read` 为 `null`；如果列表等候时其他事务正在结束，可以从同一时间窗看到它的阶段与持续时间。事务 callback 仍只调用一次，数组形式事务、嵌套写准入和原单连接配置均保留。

`native-query-window` 只记录正在观察列表时同一客户端原生引擎报告的操作类型和引擎耗时。**其 `read` 始终为 `null`**：原生 query 事件可能跨异步上下文返回，不能凭 ALS 将它归给某次 HTTP 请求，也不能把同窗其他统计或后台 SQL 相加成列表耗时。只用客户端和时间线辅助分离真实 SQL 与 callback 其他工作。既不输出 SQL，也不生成语句或参数派生的指纹；不包含参数、正文、URL、凭证、文章或批次标识；错误只记录成功/失败布尔值。

部署后先记录准确 SHA、运行实例和窗口，再发实际缓存未命中的首屏与下一页，并验证已加载多页的只读刷新/返回。逐次对齐浏览器操作→行显示、HTTP 和上述服务端时间；保留并发负载信息。热缓存、合成组件或独立只读连接的成绩不能替代实际服务验收。如果 HTTP 仍需多秒，应由最大实际等待段决定下一项最小修复，不能仅凭 `maxWait=15000` 推断存在固定休眠，也不能通过跳过锁、备份保护或重发旧请求来追求速度。

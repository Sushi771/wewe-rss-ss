# 文章列表快照读取期限

文章列表使用一次交互事务，先按完整筛选、排序和游标选出当前页 ID，再仅针对这些主键读取元数据及正文是否存在。没有将归档正文或内联图片传入列表响应；三次文章查询仍处于同一快照，保留分页、排序、筛选和正文存在性的一致性。按 ID 集合取回的元数据必须恢复为第一步的顺序。详见[列表等待与分页修复](ARTICLE_LIST_LATENCY.md)。

大正文的数据页读取、冷启动及其他缓存查询会增加磁盘和单连接池竞争。投影不返回正文不等于底层不访问存放正文的数据库页；正文存在性条件及正文之后的列仍可能需要访问溢出页。默认两秒连接等待或五秒交互事务会在合法慢读完成前报错，页面因此显示列表读取失败。

本修复给文章列表读取设置十五秒连接等待和三十秒事务期限。保持有限等待及原有事务回滚，不自动重放读取，不调整其他写入事务、数据库连接数量或备份预算，也不清理缓存或修改数据。独立慢读回归使用真实 SQLite 事务，覆盖超过旧五秒期限的读取，并核对查询次数、分页语义和不返回正文。

同一数据库客户端的相同分页查询复用最多三十秒的轻量元数据，并合并同代并发请求。每次请求只读取 SQLite 文件头的提交变化计数器和文件身份，同时核对现有缓存修订通知；文章更新、正文补全及分类写入提交后立即失效。构建页面前后修订不一致时不缓存结果，读取失败不会回退到旧页面。内存最多五十页、四 MiB，不持久化正文或页数据。WAL、正在写入的回滚日志、相对数据库路径或不能证明的文件状态均绕过复用，执行原有新读取。

这些期限和页复用不解决备份重复复制或后台缓存读取的整体吞吐瓶颈。备份准备失败后的持久恢复及批次内复用另行验收；不能将本修复视为所有订阅更新完成。生产发布包含列表读取、轻量页缓存及其路由接线三个运行时文件和必要构建产物，需单独确认。

# 主动更新调度与离线验收

上海时间每日 **09:15、14:00、17:30** 形成主动更新轮次。每轮从当前有效订阅动态选取 Wechat2RSS 来源，不使用固定公众号名单；后续新订阅在下一轮纳入。原有 `SCHEDULED_MP_IDS`、`CRON_EXPRESSION` 不决定此模式的范围或时点。

## 启用与迁移

私有运行环境设置 `WECHAT2RSS_ACTIVE_SCHEDULE=1`、`ENABLE_SCHEDULED_UPDATES=1`、`WECHAT2RSS_ENABLED=1`，且 `DISABLE_SCHEDULED_UPDATES` 不能为 `1`。首次启用在数据库旁保存私有激活水位 `.wechat2rss-active-schedule.json`，只安排下一计划时点；17:30 后部署不会立即批量补跑，首次计划为次日 09:15。配置、激活文件、队列及数据库不进入 Git。

新模式开启时，原 17:35 单号缓存 cron 和启动补跑入口均直接退出，避免双跑。部署方同步停用旧的外部自动任务（若存在）；本模块不会调用外部任务平台。既有持久任务和已受理工作不删除。

## 执行合同

- `ActiveRefreshScheduler.tick(now)` 由 FeedsService 的每分钟 cron 及启动审计成功后驱动。使用上海日期/时点生成 SHA-256 轮次键，最终由现有持久批次队列保存。重启、休眠恢复只考虑当天最新可执行轮次，不遍历所有漏轮。17:30 所在分钟之后不补起新轮。
- `TrpcService.beginScheduledRefreshAll(intentKey)` 为内部接口；复用 `Wechat2RssSubscriptionBatches.enqueueRefresh(ids, intentKey, 'scheduled-refresh')` 和现有手动提交回调，实际运行调用原 Provider `/add/:id`。本模块不增加另一个上游执行器。
- `purpose: 'scheduled-refresh'` 区分自动轮次；前端可在原 `subscriptionBatchList(true)` 中显示。默认订阅新增任务列表仍不包含刷新批次。与已有刷新重叠的号记录为跳过；未覆盖的新号保留在同一串行队列中，不能丢掉新号。
- 执行前重新核对本地启用、来源和存在性；删除、禁用、来源变化、同号 15 分钟冷却以及上游明确 `paused: true` 的记录不提交。不会修改用户启用状态或上游 paused 状态。上游非布尔 paused 字段使列表校验失败，安全停止；本次没有真实查询上游字段。
- 接受和执行使用同一文件互斥，限制同机共享数据库目录的多实例竞争；既有单号数据库条件更新负责同号冷却。各刷新批次之间也检查全局提交水位，保持至少 30 秒串行间隔。间隔和每日三轮不代表官方安全额度，不能将 42 次视为平台额度。
- 未知受理、提交途中中断、账号验证/风控使原轮次暂停。未知项保留持久标记，即使停止原轮次，也不能通过下一轮重新提交该号。已有安全恢复只检查已确认受理的缓存，不把暂停状态自动改回运行。账号风控等待优先于时刻表；不会自动登录、验证或更换参数绕过。
- 17:30 已开始轮次允许晚间串行尾部；**00:00–06:00 禁止自动提交**，执行器及 Provider 在发出请求前再检查。到上海午夜取消尚未提交的自动项，只保留已确认受理的缓存检查；隔日不恢复这些旧待提交项，由下一正常轮次重新发现有效订阅。此处理有意替代旧的无限补跑逻辑。手动及新增订阅任务不受自动时刻表控制。

## 验收及限制

测试使用伪时钟、合成数据库文件和 Mock Provider，无真实 `/add`、新增、登录、下载或生产写库。覆盖上海三时点、进程时区差异、首次晚间启用、多日重启、午夜尾部、17:30 后不补起、双实例、手动重叠、新号、删号/禁用、冷却、风控和未知受理。

独立临时副本已通过 10 个相关 Jest 测试集、105 项测试；检查范围包括旧手动刷新、普通新增持久队列及旧缓存 cron，均使用离线 fixture。服务端 TypeScript 构建检查在同一临时副本进行。

应在统一集成后运行相关 Jest、服务端构建与前端检查，再用只读现存缓存核对界面。通过 Mock 不代表真实订阅更新成功。首个真实轮次为配置启用后的下一计划；其实际受理/正文/图片结果须由部署方按既有产品入口观察。

同机互斥依赖可写、可信的本地数据库目录；有效死进程 PID 的锁可恢复。损坏/空锁、无法证明进程已退出或恢复锁异常时保守停止，需核对工作进程后处理，不能按过期秒数盲目移除正在执行的锁。多主机共享目录不在验收范围。持久批次仍沿用原有记录容量上限，未新增清理策略。

本补丁不修改 `docs/DEVELOPMENT_HANDOFF.md`、生产配置、笔记、数据库或部署；统一集成者负责其更新与 GitHub 同步。

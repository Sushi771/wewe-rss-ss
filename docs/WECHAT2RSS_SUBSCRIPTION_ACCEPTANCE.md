## 用户操作（待用户测试）

先由负责人完成一致性备份、SQLite 副本演练和受控部署，确认实际运行的是待验版本，保存目录已设置。账号正常登录由用户在私有实例处理；配置核对见 [本机接入说明](WECHAT2RSS_LOCAL_SETUP.md)。不要把服务密码、授权码、原始响应或私人路径贴到公开报告。

1. 打开本机 [公众号页面](http://127.0.0.1:4000/dash/feeds)，在原“添加公众号源”入口选择 **Wechat2RSS**，粘贴用户确认的一篇公开文章链接，提交一次。只验这一个公众号。负责人独占已授权链接的一次真实验证，其余真实测试由用户进行。
2. 分别看新增回执与内容状态：**已受理**只证明新增任务接收；**身份待确认**暂不能认定 Feed 已建立；**缓存待就绪**保留订阅，稍后用本号原“更新”按钮。不要删除重加、反复点击或改来源。原来源保留意味着已有订阅复用，并未改绑。
3. 原列表中核公众号身份、最新十篇不同文章及真实发表时间，打开每篇检查正文头尾、图片数量和顺序。少于十篇或正文/图片缺失应逐项记为未通过；“缓存读取成功”可以成立，但不能称十篇完整同步或全历史覆盖。
4. 用原保存入口将这十篇保存到选定目录，确认每篇正文文件和实际图片文件存在；断网从保存目录打开正文及图片，不能只看浏览器缓存、图片地址或下载受理提示。
5. 同一缓存下再用本号原“更新”按钮一次：新增应为 0，旧文章 ID、可信发表时间、正文和图片保持；其他订阅及个人笔记保持。可以补齐缺失内容，不得用上游内容覆盖用户已编辑正文。保存已编辑的旧笔记再重复保存，手写内容必须保留。
6. 日更新与启动补跑在上述通过后由负责人按授权启用。用户观察一个应运行时段及一次关机漏跑后的启动：只同步选定的启用订阅，最多消费一次当前缓存；再次启动已同步时段不重复补跑。不通过重新新增或强制上游更新实现补跑。

遇账号受限、认证失败、风控或响应不明即停止，保留脱敏提示，由用户在正常实例入口处理。账号恢复不自动重放新增。不要为验收故意触发风控、登录失败或额外订阅。

### 新增返回与身份核对的时间边界

官方 `/addurl` 与 `/add` 的返回是订阅地址；文章更新是独立任务，官方说明通常 1–3 秒，但遇风控会延后，并未承诺该时限。接口返回地址不等于正文已完成。诊断时的旧版本收到地址后立即核对一次 `/list`，没有自动接续；缺匹配记录或记录名称为空都会保留一次性回执并返回本地 `SUBSCRIPTION_ID_PENDING`。这个码不是供应商业务码，也不证明上游任务仍在正常执行；提示应说明本次未获得完整身份，不能断言数字 ID 未返回或列表没有记录。

本轮唯一链接的订阅地址已含数字 ID。供应商既有日志显示 `/addurl` HTTP200 后约29秒才出现该号任务完成记录；随后一次获准的只读列表核对已得到同一 ID、精确 feed 路径及非空名称。未重发新增、触发采集或请求正文。最初那次列表响应体未保存，不能追溯断言当时是缺记录还是空名称。当前公众号身份已可在供应商列表核对，本地绑定仍需原入口使用持久回执接续；此诊断不代替缓存正文、图片及本地保存验收。

### 一次提交内的有界身份接续

原新增入口现在在上游返回地址后执行前台身份核对，阶段总时限35秒：立即核对，必要时等待3秒、再等待27秒，最多3轮；所有分页累计最多6次 `/list` GET，重试前最多2次 `/login/list` 只读账号检查。读取耗时计入期限，超时或分页预算耗尽保留等待回执；名单已就绪立即返回，不继续等待。账号无可用状态或受限立即停止；HTTP、业务错误及结构冲突立即失败，不换端点、账号或重新新增。全程不重复 `/addurl` 或调用 `/add`，没有脱离本次请求的定时器、后台抓取或持续轮询。

身份在这个窗口内就绪时，本次提交直接建立本地订阅并消费首批已有缓存，无需用户第二次提交；空缓存仍独立显示缓存待就绪。35秒仅是受理后的身份核对阶段，不包含此前备份/新增请求或之后缓存事务耗时。超过窗口仍未就绪则明确保留链接，用户稍后主动继续同一链接仅核对身份，不重发新增。已在旧版本结束并返回等待的请求不会因部署自动恢复，须用户主动继续一次；本轮部署不为它发平台请求。模拟时钟与临时SQLite覆盖延迟名称、一次提交建立、等待耗尽、受限、HTTP失败、期限和分页总预算，以及持久回执不重发。

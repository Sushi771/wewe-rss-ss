# 微信读书官方人工验证与后台停止状态

2026-10-05 的原入口实测发生了新拒绝：绑定账号 Platinum963 的普通同账号续期成功，随后第一次目录请求 HTTP 200 / 63 字节，业务码 `-2041`；正文和图片请求没有继续。这不是旧的 `-2012` 登录超时，也不能把昨天最新十篇已保存的成功当成今天更新成功。私有响应、会话和原始停止证据保留在忽略目录，不提交。

## 产品行为

订阅、账号、单篇工具等本机页面共用“腾讯官方验证待处理 · 更新已停止”提示。显示订阅名、已核实的绑定昵称和尾号，提供官方微信读书入口、账号页和本应用状态查看。浏览页面每十秒只读本机保存的状态；不会请求腾讯、执行刷新、续期或验证码。登录页不轮询。

“打开官方微信读书”只打开固定官方首页，不携带 Cookie、完整 VID、票据或私有路径。用户需确认官方网页所用账号与提示一致。默认浏览器已有账号不代表它等于后台绑定账号，不能通过切换后台账号规避原拒绝。

人工打开网页、点击“查看本应用状态”或网页验证完成都不会解除停止。只有后续真实后台更新成功晚于该停止记录，提示才消失。当前没有已证实可将官方网页验证结果合法回传本应用、恢复同一被拒会话的桥接，界面明确显示后台仍停止；不能称为自动验证恢复已实现。未绑定的其他订阅保持原状态。

## 依据和范围

2026-10-05 只读重新获取[微信读书官方公开客户端脚本](https://cdn.weread.qq.com/web/wrwebnjlogic/js/app.88f998b2.js)：5,147,686 字节，SHA-256 `996a561d9fb7f79bf4289a91e2b6f77dc617eb2bb9352c0320b33c87b9f3bf51`，与既有审计一致。其 `-2041` 分支在官方浏览器上下文加载腾讯验证码，由人工回调的 `ticket` / `randstr` 添加 `x-wr-ticket` / `x-wr-randstr` 并续接原请求。该代码不能证明票据可跨域、跨账号或跨后端会话使用；不存在已审计的 localhost 回传协议。

[腾讯验证码客户端升级文档](https://www.tencentcloud.com/document/product/1159/72724)说明一般接入的 SDK 和回调形式。它不能证明 WeRead 的 AppID 允许本机来源，也不能将此前真实 `1006` 配置请求失败解释为已解决。因此本次没有搭新 SDK 试验、变更 AppID/来源、执行验证码尝试或重放已停止的目录请求。

对[维护中的 we-mp-rss 源码](https://github.com/rachelos/we-mp-rss/blob/main/core/wx/model/weread_mp.py)只核实际实现：`-2041` 属于不可重试错误，文章列表失败时使用 cover 回退；没有为此提供已核实的同会话官方验证桥。cover 回退不足以替代最新十篇完整目录验收，本项目不采用它掩盖失败。

后续需要用户在同一绑定账号的官方网页正常处理实际出现的验证，并有合法、可核实的同会话返回方式，才能实现受控继续。没有回传依据时保留停止，不伪造票据、不转存其他浏览器插件登录信息、不把正常续期当作验证码票据，也不绕过既有工具安全停止。用户已收到单篇原链接的正常打开步骤，此时无需重复催促；网页能打开与后台取得正文/图片分别验收，见[单篇正常恢复契约](SINGLE_ARTICLE_NORMAL_RECOVERY_CONTRACT.md)。

# 本次前端更新的发布范围

前端源码固定为 `f618e48f48ff0e3df1c646cb8a666a2461815732`，后端基线固定为 `48fdf73f4d770001bbb6de3e2383189811e56ccb`。`frontend-update.cjs` 只适用于这次更新，独立复核通过前不得执行 apply。

从完整校验通过的旧包复制出新目录，保留全部旧包及旧哈希资源。仅覆盖 `client/index.hbs` 并增加固定清单内的前端资源；后端、运行时、依赖、链接和迁移逐项哈希必须一致。新包清单由旧包预期文件集加已固定资源推导，不能把后来发现的文件或修改刷新成新证明。候选目录身份、完整清单和创建后元数据固定，发布前持续校验。

原完整构建的3槽限制继续保留；本模式不做完整构建，不删除、覆盖或回收任何历史包，所以分别核算全部历史库存及一次新包增量。包括无清单目录在内的历史树均进入有界扫描，记录真实物理容量、身份及文件元数据；内部junction不重复计物理容量，越界链接拒绝。历史容量可以高于旧构建阈值，本模式不因此获得更多增量：新增包加前端资源及清单预算不得超过768 MiB，并保留至少4 GiB空闲。总预算为已核算历史容量加本次精确预留，不静默排除历史目录或提高原完整构建上限。历史文件元数据变化、容量不足或扫描超限均停止，不刷新基线。

使用原公共文件/进程网关及原精确进程停止、就绪检查。持有构建锁、前端更新锁及发布指针锁；发布指针锁是安装根固定的36字节管理文件，不是包产物、缓存或外部写入接纳。原 active-release 发布入口也使用该锁，完整发布策略的库存和证明要求不改变。锁不能抢占或自动清理。复核时应核对真实安装启动入口使用的工具版本及所有并发发布者是否合作；历史包不因增加锁而改写。

应用进程须匹配PID、创建时间、执行文件、完整参数和4000端口；同库应用写者冲突仍拒绝。无关系统进程的空属性保留为 unknown，永远不声称全机完整，也不据此授权清理。原进程退出后确认无同库写者及端口空闲，才启动新版。配置文件、原数据库路径及身份固定；不迁移、不复制或还原生产数据库。启动失败先确认新版退出，再启动完整校验过的旧包；回退失败明确报错并保留包，不循环重启。

计划文件包含私有路径、进程和配置哈希，只保留本机。准备命令读取 `--installation`、`--web`、`--artifacts`、`--expected` 并以 `--plan` CreateNew 写出计划；独立审查准确计划文件SHA后，apply才允许读取同一计划。工具依赖及辅助脚本哈希也绑定计划。`--approved-sha256` 绑定的是已审查内容，不是工具自动产生的审批。

程序就绪后核验实际提供的JS/CSS哈希及HBS所引用资源，再比较指针前值并切换。真实导出弹窗、阅读器、选择/分页/排序/原搜索等页面仍需人工或浏览器实际验收，资源检查不能替代全部功能验收。当前只完成合成数据反例测试，未在生产创建候选包或重启，未完成上线页面验收。

复核后的执行前提：宿主原发布入口 active-release.cjs 必须先按已审查补丁增加同一指针锁，计划阶段核对宿主文件与审查版哈希完全一致，避免旧入口不合作造成指针竞态。本轮未修改宿主该文件；该必要更新和 Windows 脚本运行权限均须在独立复核后按正常权限处理，不改系统安全策略。

独立复核后的三项修正：数据库参数使用既有Windows命令行解析器，规范正反斜杠后通过真实文件身份比较，支持带引号及文件别名；相关但相对、缺失、多值或无法解析的路径拒绝。回退旧包就绪并取得实际快照后重新检查同库写者，冲突视为回退失败，仅停止自己创建的回退进程。写者和退出查询外层固定15秒、4 MiB上限，CIM固定10秒，写者最多4096条；超限或超时均失败，不把不完整结果当作无冲突。新增反例使用合成文件与桩，不表示真实Windows适配已通过。

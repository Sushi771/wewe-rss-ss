# 原订阅页的只读搜索候选（2026-10-02）

受保护的 `feed.searchCandidates` 查询读取服务器私有历史快照，原订阅页增加独立的“待核验搜索候选”折叠区。它与已保存文章列表分开显示，提供标题、经过身份校验的 HTTPS 原文链接和明确标注的搜索索引时间；采集时间、页数和截断状态说明快照覆盖。搜索索引时间不是发表时间，搜索游标结束也不能证明全号列表完整，因此响应固定 `complete=false`。

“重新读取快照”只读本地文件；“扫描新候选”调用独立受保护的 `feed.scanCandidates`，复用现有正常 Web 会话、跨进程锁、15 分钟冷却与访问停止记录，默认最多两页，并原子替换私有候选快照。它不请求原文，不写数据库、不改文章或更新成功时间，也不会把候选添加到 RSS 或导出。扫描失败时保留上一份快照，不自动续期或解除停止。候选可能与旧库文章重叠，列表条数不能算为新增文章或订阅恢复。此源码阶段尚待受控部署。

## 私有配置

在服务器私有环境设置 `OWNER_SEARCH_CANDIDATE_FEED_ID` 和 `OWNER_SEARCH_CANDIDATE_SNAPSHOT_FILE`，扫描还需既有 `OWNER_SEARCH_CONFIG_FILE` 的目标号绑定及本人正常 Web 会话。前者必须是要展示的 `MP_WXS_数字` 目标号，快照文件须为管理员指定的绝对私有 JSON 路径。浏览器仅传目标号，不能选择文件路径；未绑定的公众号返回 `null`。两个候选变量均不设置时此区域隐藏，填好的配置和快照不提交 Git。

快照采用 `{ mpId?, result: { candidates, pages, requests, capturedAt, truncated, termination, coverage, complete } }`。当前私有旧快照有 71 条目标号候选、5 页、预算截断，只能按历史搜索结果显示。旧非空快照可以没有顶层 `mpId`，但每个候选都必须匹配配置目标号；空快照必须声明顶层 `mpId`，以区别错误的号绑定与真实零结果。

查询限制快照为不超过 2 MiB 的普通文件、最多 500 条候选、最多 5 页及 5 个请求。它校验所有候选的稳定 ID、号身份、URL 的 `__biz/mid/idx/sn` 唯一性和签名格式，并拒绝重复身份。只返回显式安全字段，移除原始 `requestUrl`、发现元数据、额外 URL 参数及外层证据；损坏、过大或缺失文件返回固定错误，不返回私有路径或原始异常。

## 验证

`pnpm --filter server test -- --runInBand trpc/search-candidates.spec.ts` 覆盖登录保护、号与路径绑定、字段脱敏、身份冲突、重复身份、空快照、索引时间、文件限制和只读行为。Web 与 Server 构建用于确认查询类型及原页面接入。离线测试和构建不代表线上订阅验收。

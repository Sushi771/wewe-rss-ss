## 本轮修复及证据边界

- 置顶卡片不再强制存在阅读指标；统计祖先里的全部标题，包括屏幕外节点，并用 RuntimeId 判断归属。旧实现一边扫描屏幕外置顶，一边只数可见标题，且强制指标，是明确存在的失败路径；没有原失败时的完整树，不能断言这是当时唯一原因。
- 点击前核对控件矩形完整位于目标窗口。旧证据中底部标题只有部分露出，`IsOffscreen=false` 不能证明可以点击。
- 从当前选中的目标公众号文章页开始，不切第一个标签，不向不明焦点发 Ctrl+Home。要求 UIA 标签身份、唯一选中项、列表 ScrollPattern、顶部位置及稳定首部标记均可核验。当前微信是否暴露这些模式尚未实测；不满足时在开文章之前停止。
- 开文章前记录全部标签 RuntimeId。只有恰好新增一个标签且它被选中，才认作本次创建。复制、关闭前再次核验；关闭后确认原标签集合与选中项恢复。无归属证明不关闭，不使用同标题猜归属。
- 文章等待纳入异常清理；主错误代码、阶段和计数诊断独立保留。首次失焦、取消或标签集合异常后不再尝试关闭标签；这些情况下可能保留本次文章标签，由用户处理。
- Esc 由本进程监听并锁存，后续输入先检查取消。取消写暂停标记，定时和普通更新不会自动清除；本机专用“开始/恢复采集”动作才显式恢复。原生监听仍需真实单篇测试验证。
- 剪贴板只在本次官方复制动作后读取一次，在锁内先核验序号和所属进程，再读取严格格式的官方短链接。旧剪贴板不读、不保存、不恢复；官方复制会覆盖剪贴板。
- 卡片 RuntimeId 与标题、日期的关联须保持稳定；复用、重复短链、顺序异常、超预算或不支持的折叠组都失败，不跳过卡片凑数。置顶另取原文时间再与普通 20 篇合并、去重、排序。
- helper 协议版本为 2；服务端仅接收完整成功结果。Windows 跨进程锁与 Node 子进程锁阻止重叠采集；超时后直到子进程确实结束才释放 Node 锁。应用仅显示受控 stderr 错误代码和阶段。

当前通道仅对应 **“文章”页近期 20 篇**；“全部”、贴图、转发及主次条展开覆盖未证明。页面说明和 coverage 已改为 `article-tab-latest-20-unique`。若无法取得原文身份或正文，整批失败且不写文章；受限/删除正文的独立状态尚未实现，不能称此类条目已成功保留。

## 写入保护与更新入口

统一采集入口先取得同号锁，再调用 SQLite 在线备份 API 并核验备份 `integrity_check=ok` 和 SHA-256，之后才允许写 `running` 状态、文章或失败状态。备份失败时不启动 helper，也不写状态。专用桌面入口必须是 SQLite；既有非桌面 MySQL 通道仅在调用方明确允许时跳过 SQLite 备份。

`apps/server/scripts/backup-sqlite.py` 以只读连接打开源库，备份及报告存于库旁的 `backups/before-collection-*`。Windows 默认 `python`，其他平台默认 `python3`；`SQLITE_BACKUP_PYTHON` 可设单个解释器路径，不经 shell。SQLite Docker runtime 已加入 Python 3；镜像尚未实际构建。没有新增迁移。

公开 RSS 更新不会操作桌面。手动/定时共用采集实现，但普通更新选择桌面通道仍依赖 `WECHAT_DESKTOP_MP_IDS`；专用按钮成功不会自动保存该配置。定时还需 `WECHAT_DESKTOP_ALLOW_SCHEDULED=1`，默认关闭；有暂停标记时仍拒绝。桌面必须已打开对应公众号主页，目前没有自动切换多个账号主页的实现。因此**尚不能称所有订阅号已可无人值守持续更新**，不能在真实覆盖验收前启用定时。

既有 ID、非空正文、封面、来源、有效指标以及窗口外旧文章保留。缺失指标仍为 null。原文核验后可校正发布时间；验收必须单独记录校正证据，不能排除该字段后冒称零变化。

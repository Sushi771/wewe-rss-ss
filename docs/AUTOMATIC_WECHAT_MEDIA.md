# 公众号图片自动发现与补齐

本功能针对已启用、绑定为 Wechat2RSS 的公众号。正文提交后先发进程内提示；独立媒体 lane 用本地 SQLite 游标补漏，持久化任务，再逐个获取仍缺失的精确图片 URL。提示丢失或进程重启后，扫描恢复任务。提示本身不是数据库事务中的持久队列，也不代表图片已经保存。

正文同步不等待 CDN。图片下载期间不持有采集入口锁或 SQL 事务；校验并保存字节后，才通过原有采集锁、增量事务及正文/来源/时间 CAS 合并。订阅历史、阅读数据、用户文本和正文之外的批注保持原值。代码升级仍须经过正常启动保护；日常补图不逐次创建整库备份。

## 启用范围和操作参数

沿用 `WECHAT2RSS_ENABLED=1`、`WECHAT2RSS_CACHE_SYNC=1`。`WECHAT2RSS_CACHE_MEDIA=0` 暂停新下载，队列和本地已验证字节保留；正常下载设为 `1`。验收模式、启动审计未通过时不启动本 worker。上海时间 00:00–05:59、上游暂停或状态未确认、全局媒体停闸时不开始新请求。

**默认只处理本功能首次启动后的本地新写入/变更，以及正文提交提示命中的文章。** 首次启动时间写入私有队列，重启不前移；它不依赖进程内提示，所以提交后崩溃仍能由扫描补漏。启用前的旧库不会因此自动全库抓图。`WECHAT2RSS_AUTOMATIC_MEDIA_HISTORY=1` 才把历史文章加入同一有界扫描；本次交付不启用此参数，不要求完成任何特定历史文章。

唯一生产操作窗口在组合候选 CI 通过后，按正常发布流程设置 `WECHAT2RSS_CACHE_MEDIA=1`，保持 `WECHAT2RSS_AUTOMATIC_MEDIA_HISTORY=0`（或未设置）。先确认新内容入库、状态出现待补、合并后重新读取仍有 inline 字节；再重启确认恢复。不能把合成测试或本地夹具称为生产平台已验收。无需五篇专项资源目录、manifest 或旧 Vault 清理。

## 固定上限与恢复语义

| 项目       | 上限/行为                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 发现       | 每页最多 20 行，传输/解析正文合计最多 8,000,000 字节；超大单篇只报告未确认                                    |
| 扫描节奏   | 有后页至少间隔 2 秒；一轮结束等待 60 秒；新提示与普通游标交替，避免互相饿死                                   |
| 下载       | 同一数据库目录只有一个持 PID 锁的 consumer；每 tick 最多一个 GET，开始间隔至少 1 秒                           |
| 总请求预算 | 持久小时窗口最多 120 次尝试；重启不重置当前窗口                                                               |
| 单资源     | URL 原字符串为身份；最多 4 次 HTTP 尝试，退避 1 分钟、5 分钟、30 分钟；崩溃中的尝试也消耗预算                 |
| 网络边界   | 固定 WeChat CDN allowlist、HTTPS、禁止自动跳转、10 秒 timeout、单图片最多 10,000,000 字节，保留 MIME/容器校验 |
| SQL 重试   | 下载字节先保存；同一正文版本最多 4 次保存尝试，失败不重新 GET；正文变化需新快照                               |
| 队列       | 最多 1,024 篇、2,048 个活动资源、4 MB JSON；容量不足时保留有效队列和未推进游标并显示暂停                      |
| 字节缓存   | 最多 256 个文件、128 MB；新 GET 前保守预留 14 MB。满后停止新请求并显示容量暂停，不自动删除历史或用户文件      |
| 内存/写回  | 单篇输入和预计合并后正文均限制 8 MB；正文超过预算明确失败，不截断正文                                         |

408/5xx、连接错误和 timeout 可有限重试；404、非法来源、无效图片等报告失败。401/403/429 仍立即持久停闸，绝不自动清除原有 `.wechat2rss-media-blocked.json`。安全 marker 写入失败时，队列自己的 blocked 状态仍先落盘并阻止后续请求。

同一 URL 在不同文章、不同任务或重启后复用校验过的本地字节，不修改或猜测 CDN 参数。正常 inline 图片不会再次下载。空图片、CSS 背景、响应式/非图片媒体或无法确认的装饰保留“媒体未确认”，不能因普通 img 补完而宣称完整。失败资源不阻挡后面的可处理任务。

## 私有状态与界面

数据库旁新增 `.wechat2rss-automatic-media/queue.json` 和 `bytes/<URL SHA256>.json`。它们是绑定当前数据库物理身份的私有恢复数据，可能包含原始图片 URL 和字节，不能提交 Git、上传 CI 或当作可公开审计。写入使用临时文件、fsync、原子替换；PID 锁不因下载慢而超时失效，死亡 owner 由已有锁机制恢复。自己残留的临时字节计入容量、不视作成功缓存，也不自动删除。

`feed.cacheSyncStatus` 仍只读进程内状态。前端每 5 秒读取一次本地状态，后台标签不轮询，显示待补数量、重试时间/次数、有限失败、未确认媒体及暂停原因。不把“缓存已同步”当作图片已完整落库。存储损坏、数据库恢复后物理身份不符或容量不足均停止并显示诊断码，不静默重建队列或重置预算。超过预算的资源/写回不自动无限重试；需要操作负责人核查原因和私有状态后另作恢复决定。

## 回滚与发布验收

优先暂停 `WECHAT2RSS_CACHE_MEDIA=0`，阻止新 GET；已发出的请求受 10 秒 timeout 限制。若要连本地发现/合并也停止，关闭 `WECHAT2RSS_CACHE_SYNC` 后由唯一操作窗口重启。回滚代码走正常发布入口，保留队列、字节缓存、安全 marker 和数据库；不要删除 marker、伪造成功、重置失败预算或把旧数据库覆盖回去。没有 schema 变更。

补图成功后，现有导出器可从 SQLite inline 字节生成附件，浏览器和导出均无需再取 CDN。已存在的 Obsidian/Vault 文件不会被本 worker 自动改写；再次导出时仍由原有附件/笔记保护流程处理。导出清洁候选应按函数组合，保留当前媒体返回字段，不能拿较旧分支整文件覆盖。

合成测试覆盖跨页历史补漏、未来范围、重启退避、单 consumer、速率预算、部分成功、URL 去重、ACK 丢失、CAS、停闸、容量、已下载字节复用和真实 Prisma 增量事务/零备份。界面另用本机隔离浏览器验证状态自动刷新。上线后仍需在唯一生产窗口按上述范围验证一次新的真实内容链；本轮没有执行真实平台图片请求或生产启用。

# 列表批次的作者访问上下文

本机会话就绪不等于每个账号的作者访问上下文仍在。作者上下文只存在内存，重启、切换会话或有效期结束都可能使它不可用。`XHS_ACCESS_CONTEXT_EXPIRED` 同时用于上下文缺失和过期，不能据此推定 Cookie 失效、登录过期或平台拒绝；应结合发送阶段和正式请求回执判断。

正式列表批次使用既有定时审核链路。在新任务获得账号、会话、历史基线和请求预算准入后，basic 阶段复用 `prepareScheduledContext`：先在任务记录内原子写入一次 `started` 标记，再通过原有公开资料解析流程校验作者身份，成功后原子确认。纯列表和带详情的 basic 任务都需要这一步，不能在测试或产品中手工填充私有作者 Map 来代替。

这个流程不会凭空生成或持久化分享 token，不修改 Cookie；解析仍受原有来源限制、请求预算、请求回执及账号绑定检查。资料解析失败、作者不匹配、未知结果、确认事务失败或会话变化时，不开始列表请求；同一任务的 started 标记不能自动重发。已有 confirmed 标记但内存上下文缺失，也维持保护，不把重启当作新授权。

该修复只作用于今后正式准入的新列表任务，不自动恢复 blocked、paused 或 unknown 历史任务。界面可以重新解析既有授权的账号链接，但该操作可能实际请求来源，应在明确范围和系统允许后执行。若账号存在资料或首屏列表的历史 unknown，应先精确排除整个受影响账号，保留原记录；本修复不扩大历史排除规则。

更新后的隔离回归从空作者上下文开始，使用生产资料解析器、真实 SQLite/Prisma、正式定时审核及合成来源响应，分别验证一次资料解析、一次或受页数限制的列表请求、无详情请求，以及并发、幂等、失败回滚和真实认证/限流保护。离线回归成功不代表真实平台可访问或订阅更新已经恢复。

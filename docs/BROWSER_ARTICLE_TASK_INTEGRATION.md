# 单篇官方文章任务应用接线（默认关闭）

原下载工具现有正文保存器可接受已核 Provider，但此前缺少应用侧任务发起、状态、取消和完成后保存的接口；过期也被混成取消。本次只补这段生命周期，复用现有 `BrowserTaskBroker` 与 `saveVerifiedArticle`，没有增加采集框架、依赖、后台任务或第三方服务。

**候选未部署或启用。** `AppModule`、`main.ts` 与扩展运行源未改，Broker 未注册，默认实例 `enabled=false`。任务入口只在能力查询明确可用时显示；没有环境变量自动启用路径。现有稳定包、定时关闭和原平台停止状态保留，不执行安装、配对、扩权或平台请求。

## 应用接口

所有接口复用原下载工具的本机、访问认证和 Host/Origin 检查。任务归属绑定发起时的应用认证；后续请求必须再次通过当前认证，不能用保存过的原请求绕过登录变化。

| 接口                                                 | 请求与行为                                                                                                              |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `GET /download/article/browser-task`                 | 只读能力。默认不可用；始终返回 `refreshAvailable=false` 与 `DIRECTORY_ROUTE_UNVERIFIED`。不返回配对配置。               |
| `POST /download/article/browser-task`                | 只接受 `url`，经原文章 URL 校验后内部签发五分钟任务。不接受公众号列表、文件路径、HTML 或 Provider。                     |
| `GET /download/article/browser-task/:taskId`         | 仅返回任务 ID、期限、阶段和固定错误码，不返回正文、图片、nonce、配对密钥或认证值。                                      |
| `POST /download/article/browser-task/:taskId/cancel` | 空对象请求；取消待接收或待保存任务并丢弃内存正文。已开始的原子保存拒绝取消。                                            |
| `POST /download/article/browser-task/:taskId/save`   | 只接受可选 `pickToken`。目标 URL 与已核正文来自服务端记录；以当前请求调用原保存链，再核认证、Origin、保存锁与目录授权。 |

扩展仍只调用既有 `/browser-task/claim|complete|cancel` 候选传输端，不通过上述接口取得或上传正文。这些扩展路由仍未注册。传输端的配对、严格 CORS、鉴权后 scoped parser 和来源验收是后续明确启用条件，新增应用接口不替代它们。

## 状态、取消与恢复

阶段为等待、已领取、待保存、保存中、已保存、已取消、已过期或失败。超时返回 `TASK_EXPIRED`，主动取消返回 `TASK_CANCELLED`；取消和失败均不能重放旧 nonce。验收失败后仅允许用户显式发起新任务，不自动重试原文。

接收完成不会触发写盘。用户点击保存后才调用既有 Markdown/图片保存器；接收期间不占用保存锁或保留过期的目录选择授权。保存失败时，在原五分钟期限内保留已核内容，返回 `SAVE_RETRY_REQUIRED`，可重新选择目录后仅重试本机保存。超时则丢弃正文。已开始的原子保存可完成，不因接收期限到达而删除正在发布的文件。

内存最多四个活跃或待保存正文，终态只保留有界元数据并清理。重启不持久化任务。页面离开会中止状态轮询并尽力取消；后端期限仍独立生效。迟到的状态响应不能把取消、过期或已完成任务改回接收中，也不能替换较新的任务。状态与权限查询失败不会落到原文网络下载。

待保存阶段允许单独更换目录，包括默认不逐次询问路径时的失败恢复；文章目标及其他下载动作继续锁定。接收中、忙碌或保存中仍禁用目录选择。取消目录选择保留原设置和已接收内容；目录选择与其他操作共用原操作锁。其他页面在选择期间取消任务后，迟到保存会被服务端拒绝，不因目录响应返回而恢复正文。

本机状态查询失败时保留原任务，不因轮询 effect 清理而取消接收或丢弃正文。用户可显式重新读取同一任务状态；读取期间禁用再次读取和保存，不重新签发任务或访问原文。保存请求后的状态查询失败也保留任务：先读到服务端的待保存或已保存状态，再决定本机重试，避免把已提交的保存当成失败。离开页面或替换任务仍尽力取消，重读状态只清理旧轮询，不发送取消。

首次保存设置查询失败时，可在页面重新读取本机设置，无需整页刷新；恢复已记住的目录和逐次询问选项。修改选项失败仍回退到先前设置，不触发目录选择或正文保存。

已清理的记录与临时断连分开处理：只有同一本机任务状态接口返回 `410` 且固定码为 `TASK_GONE` 时，页面才解除该任务的锁定。它不证明此前保存失败；已收到的保存路径结果仍保留，未收到结果时提示先检查保存目录。权限错误、其他错误码和普通网络失败不走此分支，也不自动重取正文或重复保存。

表单、文章输入和询问选项遵守操作门禁。忙碌时被拒绝的表单事件不清空现有任务；询问选项的乐观更新进入操作锁后才执行，连续事件不会先改变显示值再被拒绝。页面离开仍取消接收，返回页面从原保存设置开始，不自动恢复已取消任务或发起取文；未能送达的取消由服务端期限兜底。

## 未通过的来源条件

本次没有证明 MAIN 实站定位、真实 canonical、上游全篇正文、原图字节或未知短链映射；`routeVerified=false` 仍是门禁。官方验证成功不构成本机回调或内容回送，不解除原平台停止。

选中公众号刷新仍缺真实目录及发表时间来源。单篇成功不能推断目录覆盖或作为新文列表；本次未接入原刷新事务、写库或更改绑定。真实目录与各篇内容通过后才可复用现有 Provider 和原事务、备份与去重逻辑，不以缓存旧文或合成列表代替。

## 离线验证

首轮应用接线的相关五个服务端套件共 **62 项**通过；扩展原有 **23 项**离线测试通过。该轮服务端与 Web 构建、相关服务端 lint、全 Web lint 和格式检查通过。覆盖默认关闭、私有模式拒绝、认证轮换、跨 Origin、目标/正文/路径替换拒绝、取消与过期竞态、迟到状态、容量限制、目录 grant、保存失败后的本机重试，以及真实 Markdown/合成 PNG 字节与用户旧笔记保护。

HTTP 测试使用真实 Nest 控制器、合成官方页面数据和临时目录。只有测试注入的 Broker 配置可用；原文下载器被设为失败并确认未调用。保存器实际写出可读 Markdown 与精确 PNG 字节。这证明应用接线与本机保存合同，不证明实站取文或订阅恢复。未进行新 UI 的真实浏览器视觉验收。

实际 TSX 编译后的离线交互回归覆盖默认不逐次询问时失败后换路径、目标保持锁定、忙碌/接收/保存门禁、选择取消及迟到响应保护。本次增加受控 effect/计时器的本机状态失联与显式恢复、取消后的迟到响应、保存失败或已提交但状态失联、初始设置恢复及询问选项写入失败回退。该 hooks/JSX/fetch facade 使用合成响应，不称为浏览器视觉测试。两套相关服务端回归核对真实 `SAVE_PATH_TOO_LONG` 后选择新目录、原 Markdown/PNG 保存器的结果与旧内容保护，以及选择期间并发取消；只有一次合成正文完成，无新取文。

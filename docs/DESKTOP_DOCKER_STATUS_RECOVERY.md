# Docker 冷启动检查恢复

桌面入口在 Docker 引擎尚未就绪时，会先查询原 Docker Desktop 进程，
确认它未运行才启动原安装。此前这条只读查询失败会立即退出，并错误显示
“容器状态异常”，实际还没有执行容器检查。

现在进程查询失败与容器异常分别报告。查询暂时失败时，在原有两分钟
引擎等待期限内继续核对；未知状态不当作“已停止”，不会重复启动 Docker。
引擎恢复后仍检查原容器身份、镜像、端口、数据挂载和 HTTP 就绪状态。
持续查询失败或依赖异常仍停止启动，不显示成功。

此变更只涉及启动器。不改采集、搜索、更新进度详情、数据库或备份，
不创建、删除或替换容器。已有桌面锁继续串行处理重复打开与重试。

验证命令：

```sh
node --test scripts/local-release/desktop-dependencies.test.cjs scripts/local-release/desktop-home-entry.test.cjs scripts/local-release/desktop-progress.test.cjs
```

回归包括真实适配器的进程查询超时、读取失败和无效输出；冷启动恢复、
等待超时、重复打开及失败后重试；容器身份不符、异常状态和健康检查失败。
旧日志没有记录进程查询的底层退出原因，不能将合成超时反例说成已证实的
现场超时原因。本补丁需另行批准发布后，才会改变已安装桌面入口的行为。

# 本机诊断启动握手

启动器在浏览器访问前检查已编译产物和两个 loopback 端口。重复启动遇到端口占用会立即退出；仅清理本次创建的子进程，不终止已有实例。

窗口显示固定启动阶段与白名单错误码，帮助区分产物检查、端口检查、依赖加载、数据库初始化、后端加载和就绪探测。原始应用日志、异常消息、HTTP内容和登录凭据不会进入启动控制管道。同步异常与未处理异步启动拒绝均及时失败。产物与网关模块预检也纳入错误处理。

PowerShell握手维持45秒绝对期限，每次读取使用剩余预算，进度消息不延长期限。后端就绪探测使用从控制初始化起35秒的剩余预算，单次请求至多2秒并向下取整毫秒值，避免 AbortSignal.timeout 拒绝非整数延迟。35秒不代表可打断同步模块加载的硬期限。

在本目录运行离线回归：

```powershell
cd scripts/redbook-local-confirmation
node --test redbook-startup.test.cjs redbook-pair-gateway.test.cjs
```

测试覆盖不泄露原始异常、异步启动拒绝、缺失编译产物、分数毫秒及已耗尽预算，以及既有本机确认网关行为。具体结果应对应交付提交的完整SHA。

此前一次启动只留下 PAIR_READY_TIMEOUT，缺乏失败阶段证据；其具体根因仍未确证。此次修复提高错误可定位性并限制探测时间，不能据此证明首次故障的原因。真实平台签名、全文与全图可用性仍须在本人明确确认后独立验证；离线fixture通过不能代表真实接口可用。

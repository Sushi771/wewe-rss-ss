# Wechat2RSS 无密钥接线交接

Windows readiness 合成测试继续用系统分配的空闲端口，并先检查该端口是否被当前 Node Fetch 允许。只有明确的 `bad port` 会关闭测试监听器并重新绑定，最多八次；其他错误立即失败。测试不会修改系统端口、网络、防火墙或生产 readiness。新增回归覆盖重新绑定、非端口错误不重试及次数上限，原认证、匿名拒绝和 RSS 数量断言保持，Windows CI 同步运行这些测试。

预检的应用私有配置读取错误也已纳入固定安全码路径：失败时输出 `PRIVATE_CONFIG_READ_FAILED` 并以退出码1停止，原路径、错误消息和配置值不进入日志；没有自动重试。纯合成回归同时核成功加载与外部环境优先级。填写入口仍是已有两个本机文件，真实密钥和平台验收没有提前执行。

已有 Provider、来源选择、缓存读取与原刷新流程继续复用。本轮增加 `--deployment-config` 离线检查现有实例与 WeWe 配置的一致性，输出字段存在性和固定安全码，不输出密码或授权值，不生成配置、不联网、不启用来源。默认预检仍只检查 WeWe 的配置格式。参数不能与 `--execute` 混用；真实读取中账号、JSON Feed、query 失败立即停止，最后 RSS 失败也以非零退出码表示。

独立发布运行器现在识别 Wechat2RSS：只有用户显式启用来源和定时更新、有效私有配置及已启用的来源绑定才放行；原有公众号来源规则及小红书路径保持兼容，默认继续关闭定时更新。此改动在源码中，当前生产软件没有被替换。

本轮验证使用合成配置、响应和绑定，没有读取真实授权值、请求真实平台或写生产数据库。配置检查、兼容回归、运行策略与构建通过只能证明本地工程行为。真实授权、正常登录、目标公众号最新十篇的身份与时间、完整正文和全部图片字节、原刷新去重及旧内容保护仍待用户填写后验收。

准确填写位置和命令见[本机填写与接入检查](../WECHAT2RSS_LOCAL_SETUP.md)。保存现有私有文件的其他设置；不要将密钥提交到聊天或 Git。生产部署前仍须核对运行版本、一致性备份并在副本演练。

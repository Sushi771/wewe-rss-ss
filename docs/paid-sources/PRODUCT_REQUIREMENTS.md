## 用户目标

本人用一个私人界面管理多个公众号和小红书博主，每日主动更新一次，集中阅读并归档完整图文。电脑常开，手机和其他电脑通过私人 Sites 界面查看。平台账号、授权和正常验证由用户处理；已有内容持续可读。

第一期包括：作者管理、手动单个/全部更新、逐作者结果、图文查看、完整性状态、重复去重、浏览器离线包和本机原保存能力。不包括视频下载、视频号、抖音、评论采集、推荐流、自动发布、全史保证或商业多人系统。小红书列表中的视频笔记显示“本期未归档视频”，不得混算为完整图文成功。

当前小红书正式本机入口已具备待接入名单、独立模型、缓存查看及原保存器直存，ZIP 为可选导出；来源未注册，保存名单不表示已订阅。隔离浏览器核心流程及合成文图本机保存已通过；确认移除、手机正文最后检查及真实供应商图文仍待验收。以下为目标验收合同，不能将合成验收写成真实更新成功。

## 每日流程

打开 Sites 私人页面 → 确认本机在线与来源状态 → 点击“更新全部” → 显示本次选中的启用作者和预算范围 → 服务端受理一个批次 → 本机按来源规则逐个执行 → 页面逐作者显示结果 → 查看/下载已完整归档的图文。读取任务状态不会提交第二次付费更新。首次添加和来源切换使用单独确认，不随每日点击自动登录或重绑。

本机离线时不自动创建过夜待执行的付费任务。执行中失联的任务保留已有结果并标为未知/中断；重新连接先恢复状态，不能重放不确定的上游请求。重新执行需要用户明确选择未完成部分。

## 成功的定义

一次批次结束与“获得全部最新文章”分开。作者级结果包含：本次覆盖范围、检查时点、新增数、补全数、重复数、正文/图片未完整数和错误分类。没有新文可以是“本次窗口无新增”，前提是确实读取并核验了该窗口；读到旧缓存只写“读取缓存”。任务受理、列表 HTTP200、mock 或构建通过都不是完整归档。

标题、作者、稳定内容身份和可信发布时间核验通过，并取得完整正文及本篇全部图片的可打开字节，才计作“图文已归档”。纯文字文章可没有图片；无图不能被当作图片失败。缺字段保持未完成，不用列表抓取时间代替发表时间。旧正文不能被空响应、摘要、较短不可信正文覆盖。

## 容量、费用与保留

作者数量由用户配置，不写死为现有库数量。单次批次设置可见的页数、新详情数和费用上限；超过预算标“窗口未完成”，不能漏页后仍显示成功。已有历史永久保留到用户明确删除；平台删除和上游留存上限不触发本地删除。

小红书费用模型为：列表调用量 × 列表单价 ＋ 新增/明确补全详情调用量 × 详情单价 ＋ 必要身份查询量 × 对应单价。按供应商实际计费成功条件核账，业务失败仍可能存在已扣费用，不能用 HTTP 状态自行保证零成本。源码 B 另计维护、运行依赖和网络；Sites 另计实际存储/传输条件。金额上限尚待用户确定，不在代码中假设预算。

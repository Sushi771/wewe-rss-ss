# 小红书开发、维护与发布

按[产品](PRODUCT.md)、[设计](DESIGN.md)、[接口与数据契约](TECHNICAL.md)和[验收](ACCEPTANCE.md)维护现有实现。评论正文/回复采集暂停；正文图片下载、本地保存及历史数据保留。不要从历史文档推导当前部署版本、真实来源成功或操作授权。

## 最小开发与独立复核

先绑定基线SHA和候选文件哈希，用脱敏字段结构、DB检查点、原始媒体字节或DOM建立独立expected；不得调用被测映射器产生expected。围绕一个已复现故障修改，Jest/Node测试在临时SQLite和隔离目录注入提交失败、丢应答、取消、重启、锁释放及超时。先证明旧失败再证明新成功；只运行受影响套件及必要共享前后端回归，不以测试总数替代覆盖。

启动/退出核对真实进程生命周期、端口、锁及实际服务JS/CSS；下载核对正文、媒体字节与保存回执；恢复核对来源计账、持久栅栏及冷启动不重放。浏览器使用编译产物验证真实事件、窄宽/矮窗口和迟到响应。真实来源字段、数量对账与Obsidian实际阅读须另有获准证据，合成支持不表示来源可用。

## 发布与回退

单一整合者冻结源码、前端资源、后端JS、完整SQL迁移和构建清单。源码哈希与包哈希分别正确仍不足，必须逐文件验证源码→构建配对，特别核SQL逐字节一致。记录同头CI结果、测试环境及未执行项；旧头绿灯不覆盖新差异。

先分清纯代码覆盖与数据迁移：没有迁移或生产写入时复用仍有效的一致性恢复点，不因改几个文件机械复制整库。确需恢复点时遵循现有空间/保留策略，未知覆盖不自动清理，不能以文件存在替代可恢复验证。按[事务恢复说明](../MEDIA_TRANSACTION_RECOVERY.md)使用停服一致副本完成基线及隔离恢复演练，线上只作短查询，连接在finally关闭。

安装核源码/运行包身份、前端实际资源、迁移、启动健康和数据/用户文件保护，再分别安排获准的最小真实验收。二进制回退保留新增表、账本和用户文件；不做破坏性down迁移，不删journal/锁文件或清unknown换取启动。恢复失败、清理超时或结果未知保持暂停，明确下一步证据缺口，不自动重放来源。

## 维护交接

每项记录需求→实现位置→反例/命令→原始证据类别→结论及边界，标为已实现、待验证或待开发。固定错误与实际HTTP数值可公开说明；真实用户身份/内容、token、凭证、绝对路径、私有账本及本机审计仅留获准私有材料。公共文档写通用标准和合成例子，不复制私人验收过程。

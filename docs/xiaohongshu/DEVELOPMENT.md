## 开发顺序

1. 核实给定目录 HEAD 与精确 SHA，从该 SHA 建隔离分支，不用远程 `main` 覆盖，不修改原运行目录。阅读根 `AGENTS.md`、[根开发指南](../../DEVELOPMENT.md)、[前端原则](../UI_DEVELOPMENT_PRINCIPLES.md)及本目录。
2. 后端先锁定 [共享契约](TECHNICAL.md#共享接口契约)，实现服务端短期解析身份、显式确认订阅，再拆分仅列表刷新与选中图文下载；必要契约调整先由主负责人同步两个实现窗口。
3. 前端接入链接识别、作者确认、原分组、笔记勾选及原保存偏好；按 [功能对照](PRODUCT.md#适用内容管理功能对照)保留搜索、日期筛选、排序、分组、阅读、导出和批选，优先复用通用组件。任务 UI 只读真实状态，防重、取消和选择归属与后端一致。
4. 复用 `XhsCreator` / `XhsNote`、现有唯一身份与事务协调。若需迁移，在隔离合成库应用并核对旧字段、ID、正文、分组和外键；不连接生产库。
5. 使用可重复的合成来源、临时 SQLite、合成图片和独立输出目录执行针对性回归。默认来源不应因测试而启用；测试不得调用真实平台或读取私人配置。
6. 集成后对齐实际接口、限制和错误文案，执行后端相关测试、前端交互回归与必要构建，再运行 [验收矩阵](ACCEPTANCE.md)。记录精确 SHA；测试、浏览器、真实平台和生产状态分别回填。
7. 各窗口提交自己的开发分支，主负责人审查并集成，再统一推送 draft PR，核对远端 commit 与 CI。不得自行合并、迁移生产库或部署。

## 验证入口

基线已有相关回归可作为保护网，新增测试名及最终命令由实现交接补充：

```sh
pnpm --filter server exec jest --runInBand xiaohongshu-contract xiaohongshu.service management-groups xiaohongshu-ui
node scripts/xiaohongshu-refresh-ui.test.cjs
pnpm --filter server exec prisma generate
pnpm build:server
pnpm build:web
```

命令是开发验证入口，不表示本窗口已经运行通过。集成负责人应先查看测试实现，确认数据、进程和来源均已隔离；不能直接在原运行目录执行通用启动、维护、线上验收或生产迁移脚本。格式检查限定本轮 Markdown，不使用全库 `pnpm fmt` 制造无关改动。

## 集成交接清单

每个实现窗口交接精确 commit、变更文件、测试命令和结果、接口变化、未覆盖边界及是否涉及迁移。集成时重点核对：

- `refresh` 确实仅元数据，`downloadNotes` 才取详情并落盘；旧待接入 `add` 不能仍作为新“订阅成功”入口。
- `resolutionId` 的过期/重复确认、稳定作者去重、旧博主兼容及平台分组校验。
- UI 能勾选尚未下载的图文，任务 ID、计数、取消和切换博主回执归属一致。
- 适用内容管理对齐：标题/作者/缓存正文搜索、上海日期、时间排序、分组、已加载批选、当前筛选全部与整博主导出分别核对；源专属差异逐项披露。
- 原本机目录设置及一次性凭证仍有效，缓存完整与文件完整分别核验；旧内容保护不被简化。
- 文档中的支持链接、字段格式、状态、错误码、上限、任务存储和重启边界与最终实现一致。

提交前用 `git diff --check` 和变更清单检查，只纳入本轮授权文件。不提交凭据、私人笔记、数据库/备份、真实响应、本机审计或构建产物。主负责人完成校准后在 [ACCEPTANCE](ACCEPTANCE.md)填写证据；未执行项继续明确标注待验收。

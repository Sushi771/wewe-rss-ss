# 取消已证实未发送的旧小红书批次

此入口只处理一种旧状态：批次 running/paused，恰有一个 reserved 项，其他项全部 queued；保留项绑定的旧 list 任务已 blocked，准备阶段的可靠诊断明确记录 dispatched=false，且没有任何发送、续派或进度证据。任务 code 与 taskFailure.code 必须均为 XHS_SOURCE_RISK_REVIEW_REQUIRED，只支持原来零进度的非定时旧任务。其他形态继续保持保护。

## 页面操作

1. 在小红书页面的批次操作区域展开“核查并取消未发送的旧批次”，点击“核查本地记录”。这一步只读，不验证平台、不发送采集请求。
2. 核对页面显示的账号、旧任务与取消项数。仅在核查成功后勾选确认范围，点击“确认取消旧批次（不发送请求）”。服务器会创建并验证一致性备份，在同一事务内重新核对预览状态，再写入取消审计回执。
3. 完成后批次变为 stopped，各项 cancelled。旧保留项仍保留原 operation，原任务文档及时间保持不变；取消回执记录原批次/项状态、任务摘要、预览摘要、备份 SHA-256 和审计校验值。不生成采集成功回执，也不会开始新采集。
4. 若响应不明，先重新读取批次状态或刷新页面；不会自动重试确认。已提交的相同确认可幂等观察。若来源状态读取失败，会单独提示取消已经记录，避免把状态读取失败当作需要重做取消。

恢复会话、确认资料验证、停止后新建批次都不能替代本核查。若记录仍含 unknown、存在真实认证/限流/验证限制、存在活动来源请求、状态发生变化或无法确认备份，操作保持阻断。旧的 unknown 保持 unknown；来源风险行、请求预算和既有审核授权都不会因取消而改变。

取消不代表订阅恢复。后续新批次仍须走原来的列表审核、来源保护与获授权的更新流程；本入口不会调用 advance、stop 或任何取源方法。

## 工程边界

- 只读预览 API：xiaohongshu.prepareRefreshBatchLocalCancellation，输入 batchId。
- 确认 API：xiaohongshu.confirmRefreshBatchLocalCancellation，严格校验 batchId、64 位十六进制 digest、acknowledgedNotDispatched=true；两者均受现有认证与本机同源访问约束。
- 正面证据要求规范的原任务 JSON、准确任务/账号绑定、零进度、准备阶段 dispatched=false；重复 JSON 字段、额外来源/恢复字段和关联任务/来源账本/预算/legacy job 都使其失效。
- 预览摘要绑定批次、项、原任务、来源风险、任务/作业、请求/预算和账号绑定；确认使用现有 protectedWrite、增量准入和 SQLite 事务。备份源身份、内容 SHA-256、一致性检查与文件/WAL 版本均须通过。
- 取消回执复用 refresh_batch_items.outcome，不新增数据库结构或请求权限。来源围栏重新校验审计与原任务；回执损坏或原记录被改变后继续阻断。
- 已取消 operation 的单任务恢复入口被拒绝；恢复与取消竞争时，最终任务写入事务会再次核对，不制造“提交未知”的新占位记录，不改变原任务或发送请求。
- 部署时必须同步服务端、前端解析器和前端资源。没有启动时自动取消或迁移。旧版本不能理解这种取消回执时会保持阻断；不得用直接改库清除保护来回退。

本能力只在隔离合成数据库完成验证，实际安装及生产确认由唯一安装任务在对应授权下执行。

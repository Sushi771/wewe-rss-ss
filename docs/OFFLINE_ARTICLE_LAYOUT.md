# 文章离线目录

文章列表的本机单篇/批量保存、工具页即时/后台保存及按号 ZIP 统一按真实公众号与分组组织：

```text
已确认保存根目录/
  YYYY-MM-DD_分组名称/
    公众号名称/
      文章标题.md
      另一篇文章标题.md
      image/
```

新导出按每篇原文的 `publishTime`（Unix 秒）换算 `Asia/Shanghai` 日期；下载日、同步日和任务受理时间不用于来源目录。不同原文日期分别保存，公众号的 `image/` 只在对应日期及来源目录共用，不增加文章子目录。正常分组、公众号和文章保留可读名称；无分组为“未分组”，不同稳定身份同名、非法字符或 Windows 保留名才加稳定 ID 后缀。隐藏的来源/文章回执持有真实 ID，不从文章标题猜来源。来源取现有 Feed 与 ManagementGroup 记录；工具已核 canonical mpId 后可关联 Feed，无需文章先入库，缺来源记录时明确停止保存。

正文含公众号、分组、原文发布日期（上海时间）及原文链接，使用相对 `image/` 引用。每个公众号共用自己的图片目录，文件名含稳定文章身份摘要和图片字节哈希，同一篇重复图片去重，跨文章和公众号隔离。保存失败只回收本次创建的文件，不清理其他文章图片。重复保存复用同一稳定文章 ID 和可信来源适配器的回执并保护用户编辑。

保存根仍沿用各入口已配置或已确认的目录；工具后台任务继续使用受理时确认的根，不采用后来更改的偏好。旧任务已保存结果与无来源的其他平台导出保持原合同，单篇任务读回兼容旧“正文.md”和新标题文件。目录与文件均需通过普通本机路径检查，禁止链接路径逃逸确认根。

列表本机保存只导出已缓存正文，正文缺失时停止，不请求公众号原页。按号 ZIP 会明确列出未完整篇目；目录结构正确不代表缺失正文或图片已经恢复。单篇工具仍遵守 Wechat2RSS 来源和精确文章身份约束。

缺失、零值、非整数、早于 2000-01-01 或晚于当前时间超过五分钟的发布日期不代填为今天，也不把毫秒值猜成秒。正文仍保存至 `日期待核_分组名称/公众号名称/文章标题.md`；正文与隐藏文章回执记录原因，接口返回 `publicationDate: null` 和 `datePendingReason`，供简短提示。

重下载先在已确认根内核对已有管理回执，可复用旧无日期来源目录、旧工具按下载日的独立文章目录，以及已有日期待核目录；不会迁移或另存一份，接口返回 `alreadySaved`，位置与当前规则不同则附 `legacyLayoutRetained`。日期后续补齐或分组改名仍保留旧笔记位置与编辑。多个同身份且同来源的有效回执会明确阻止另存，要求先核实保留版本；损坏回执、缺失资源或链接路径同样停止。没有可信 ID 回执的笔记无法仅凭标题自动认作同篇。

## 既有输出整理与回滚

发布日期目录已用三篇真实缓存的隔离副本核验：正文分别落在三个原文日期目录，ZIP 与暂存文件逐项哈希一致，图片引用可定位且字节可解码。核验不访问上游，不写生产数据库，不移动既有笔记；实际目录结构与图片可打开不等于所有文章内容完整。工具即时保存、恢复后的结果和列表批量保存仅在需要时提示“日期待核（原因）”或“保留原有位置及编辑”。

本轮不批量迁移旧笔记。后续另行授权后，已核来源和原文发布日期的既有文章可在完整逐文件校验备份后迁移到上述结构，只添加来源说明并改相对图片引用。相同文章的不同正文版本使用明确版本后缀保留，不合并或覆盖。先核 Obsidian 引用与持久任务路径；不能确认无损时保留原位置。无引用时原件移入备份，不留下重复正文与空壳入口。恢复时先保护整理后的新编辑，再按原路径取回备份原件。

下述脚本是上一版“每篇独立目录”历史维护工具，不是当前来源目录迁移入口；仅保留供历史输出盘点、测试和追溯。

`scripts/repair-article-layout.cjs` 用于维护时整理一个明确指定的日期目录，不在启动或保存时自动执行。默认只盘点；第三个参数为 Vault 之外的新备份目录，最后增加 `--apply` 才执行整理：

```text
node scripts/repair-article-layout.cjs <日期目录> <Vault根目录> <新备份目录>
node scripts/repair-article-layout.cjs <日期目录> <Vault根目录> <新备份目录> --apply
```

脚本先保存并逐文件校验完整备份，再把已识别笔记及图片复制到独立目录，只调整受支持的相对图片引用。原笔记和可安全移出的共享图片池保留在备份中；已有文章目录不合并、不覆盖，有冲突时使用另一个目录。原文件名入口保留裸名称笔记链接。

显式路径链接、Obsidian 书签、同名链接歧义、未知资源引用或路径安全检查失败会阻止对应笔记整理。其他笔记仍引用目标图片池时保留该池；其他日期的图片池不算本次目标。文件在盘点后发生变化时停止，不覆盖新编辑。

备份内的 `manifest.json`、`snapshot/`、`originals/` 和成功时的 `result.json` 用于检查及恢复。恢复前先保留整理后的新编辑，再按原相对路径复制需要的原件；不要直接覆盖当前笔记或删除整理后的目录。

回归包括上海时区跨日、原文日与下载日区分、日期待核理由、ZIP 多日期拆分、旧布局保留及重复回执停止，以及真实临时文件中的正文编辑保护、图片字节、重复保存、缺正文停止、ZIP 相对路径、备份、跨日期资源、现有目录冲突和笔记链接保护。迁移脚本在 Linux 和 Windows CI 执行；平台权限失败须单独记录，不能算作迁移成功。

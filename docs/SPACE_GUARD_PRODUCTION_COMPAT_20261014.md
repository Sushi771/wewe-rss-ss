## 上线与业务连续性门槛

1. 由维护者记录当前周期 owner、有效启动 receipt、迁移/身份回滚点引用。对历史文件形成逐文件清单，核验代表恢复点 SHA、quick_check、schema、恢复版本、时间范围和业务损失。只读盘点不授权删除或移动。
2. 明确批准 [有界恢复窗口](SPACE_GUARD_RETENTION_PROPOSAL.md)：活动至多16点/14 GiB，历史至多16点/12 GiB，迁移身份至多12点/4 GiB，共至多44点/30 GiB，余4槽及2 GiB。各子配额是人工维护规则，当前代码只实施统一硬预算。更早/更晚快照不保留被淘汰中间时点的精确状态，必须明确接受这项损失。
3. 对批准清单先核可恢复副本。无损压缩必须流式解压 SHA 一致并演练恢复；当前 owner/receipt 引用点不动；压缩/外部归档也有明确有限容量。同盘改目录不释放物理空间。失败半成品、重复点、过期独有点的处置授权分别记录。
4. 永不先删最后可恢复副本。保留生成空槽与 DB+WAL 保守字节余量，先完整生成验证新点，再处置批准的过期点。当前源库44份约29.98 GiB，加下一份预留约31.34 GiB；库增长、sidecar、其他文件会更早触限，44是上限而非必须填满的目标。至少每4小时复核，50%预警或连续变化预测不足24小时立即维护；没有长期轮换授权/执行能力时不激活无人值守写入。

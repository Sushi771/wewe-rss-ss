# 桌面启动速度与测量范围

双击原有 WeWe-RSS 图标，状态窗开始显示真实检查阶段。成功后同时请求打开4000产品页面和18080原订阅后台；启动期间连续点击会聚焦同一状态窗、复用服务，只请求一次双页。账号页的后台入口保留。关闭状态窗不取消正在启动的服务。

2026-10-11在Docker及原订阅容器已运行的同一条件下，各测3次：热启动中位数约1.86秒，原版约2.65秒；仅产品未运行时约18.77秒，原版约21.08秒。这里包含真实状态窗显示握手、安全检查、产品健康与浏览器派发，不包含快捷方式派发前的时间。数据库备份/校验存在波动，全部差异不能都归因于优化；它不是Docker/WSL或整机冷启动保证，3个样本也不能保证每次耗时。

本轮把互不依赖的窗口初始化和Docker检查同时进行，减少串行等待。冷启动仍须读取、核验并备份现有数据库，不能提前宣称服务已经就绪。失败保留原因、重试及日志入口；持续文件错误仍会阻止启动。

状态窗有Windows显示回执；本轮沿用此前CUA `CreateProcessInSandbox 203` 的视觉限制，实际默认浏览器两个标签是否露出仍待用户目视确认。性能收益、相关回归与部署证据详见 [工程记录](DESKTOP_START_REPAIR_20261011.md#启动性能小补丁2026-10-11后续实测)。

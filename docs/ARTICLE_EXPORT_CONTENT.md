# Markdown 导出内容

后续单篇、批量、浏览器 Markdown 和同目录新增导出共用 `buildArticleMarkdown`。导出器不再向笔记插入“媒体完整性未确认：原缓存含无源或未核图片项……”说明。正文、文章附图及原有来源信息保留。作者自己写在正文里的同样文字不做全局替换。

“跳转微信打开”来自页面正文中的平台尾部控件，不是导出器生成的固定文案。只移除文字精确匹配、位于正文末尾、独立成块且不包含图片或其他媒体的控件。链接仅在无有效目的地、微信协议或指向当前同一篇微信文章时移除；其他作者链接、正文中间的同名文字、引用、列表和带图链接保留。清理只作用于导出时的 DOM，不改数据库内原 HTML。

内部 `images-pending`、`mediaComplete`、保存回执、成功判断、图片预算和原字节校验保持原合同。取消笔记里的生成说明不等于把未知状态改为完整，不新增让用户再次核验这批媒体的步骤。

用户明确只修以后导出。已存在笔记、用户编辑、旧回执和图片均不做清理或迁移；重复导出继续遵守原有跳过/精确补图规则，不覆盖旧正文。没有旧文件扫描或清理入口。

原候选 PR59 基于集成线 `edb0ecb799852a37bd26b7879a7962b10fbd98f3`。本组合只移植其精确尾部控件清理函数及取消“媒体完整性未确认”生成说明，保留现有导出器的 `mediaStatus`、`missingImageCount`、已知资源失败报告和所有保存成功判断，不合入旧基线。本段移植不改自动补图、采集、写协调、备份或启动保护；尚未部署。

合成回归覆盖单篇与批量实际 RPC、同目录重复导出保留编辑和回执、浏览器 Markdown、真实本地 PNG 字节、正文链接、同名作者内容以及尾部控件边界。全部数据和图片由测试构造，不访问真实平台或用户 Vault。

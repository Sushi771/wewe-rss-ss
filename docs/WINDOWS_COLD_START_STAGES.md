## 修补与保留的保护

当前包有 15,060 个完整元数据条目（1,338 目录、13,305 文件、417 链接）。独立微测中原同步扫描为 3.807 秒，最多 8 个并发 lstat 的原型为 2.276 秒，结果逐项和顺序完全相同。最终实现先保留目录进入前的 lstat 类型/身份检查，拒绝 stale Dirent 被换成 junction；文件与链接的 lstat 才通过 Node 现有 I/O 池有界并发。没有调整线程池/OS 设置或新增依赖。

所有 dev/ino/mode/size/mtimeNs/ctimeNs、真实链接目标、完整目录枚举、manifest/verifier 绑定和平台检查保留。同步 verifier 和默认完整 SHA 审计保留；只有完整异步元数据与既有成功 receipt 完全一致才复用。缺失、损坏或变化的 receipt 仍调用原完整字节审计及核验前后元数据比较；没有接收外部传入的“已核验元数据”作为捷径。目录、ID、schema 校验通过后才原子更新指针，失败时原指针不变。进程句柄/身份、迁移、数据库基线、备份、网络限制和 RSS 验收均未减少。

本轮未引入模块解析缓存、V8 编译缓存、打包框架、常驻预热服务或登录/网络尝试。剩余实际时间仍主要在完整包核验、数据库保护和现有依赖图加载；现有证据不能支持冷启动一秒，也不能证明不存在后续结构性优化空间。

# 本地正文搜索合成测量（2026-10-20）

本开发分支的未部署结果。只使用全新合成库，30 个公众号，约 80% 文章有缓存正文（每篇约 700 中文字及 1KiB 合成图片属性载荷）。没有生产数据库、私人文章、真实账号或外部采集。

查询为受保护回环 HTTP＋实际 article.list/summary 路由＋SQLite＋片段，**不含浏览器渲染**。首建为后端 prepareBodySearch 直接调用，含 30 次并行合成正文更新，不含迁移回填、前台每批 HTTP 和调度等待；不能当成用户页面首建总耗时。系统页缓存不受控；每类查询 30 样本并包含第一请求，不能称物理冷盘。P95 用 nearest-rank，小样本不构成稳定尾延迟承诺。

## 判断与停止条件

初始未交付原型使用全结果 ROW_NUMBER 排名，并且每批整理扫描原文统计覆盖。实际 HTTP 基线在 60000 篇命中页约 0.6 秒、后端首建约 205 秒。最终实现按排序索引有限取页，游标用同一快照内的排序值＋ID，并把覆盖计数放到派生窄表索引。以上是本轮新搜索实现内部的设计修正，不是已部署产品或历史排序／批量导出的新收益。

在 1809 篇规模各类请求 P95 均约 7–26ms；60000 篇命中页／游标 P95 约 7–48ms。缺失词和全范围统计仍是线性包含扫描，60000 篇 P95 约 651／660ms，投影约 96.3MiB，后端首建约 59 秒，均是明确成本。正文更长、命中稀疏、指标排序和真实写入争用可能更慢。当前维持最小可维护方案，停止继续加缓存／分词／后台服务；不宣称所有词、所有库规模或生产采集都无等待。

同机首次构建进度可见、可停止和续接。自动整理只在活跃搜索页面发生；后端每次最多 128 条和约 8MiB 估算输入预算，单篇超预算单独处理。首次整理不是迁移时阻塞采集的大事务。

复现和一致性合同见[本地正文搜索](LOCAL_BODY_SEARCH.md)。原始日志、临时库和本机路径只保留本机，不上传。

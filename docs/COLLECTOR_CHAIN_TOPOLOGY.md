# Synchronous reference collector topology

The formal query uses a controller Node process, a separately spawned Node probe, then the pinned PowerShell collector. On Windows the probe can own its own console, while PowerShell owns another console. A direct imported probe invocation can have only the PowerShell-owned console. Checking that the probe has exactly one child therefore rejects a real supported synchronous topology.

The collector chain now uniquely identifies PowerShell by canonical executable and complete invocation. Each owner may have at most one console. Each console must have the exact parent, canonical configured System32 executable, supported NT-prefixed command path and exact arguments, a creation time at or after its own owner, and identical full identity in both snapshots. The probe console can precede PowerShell creation. The complete before/after subtree must contain only these verified identities. Extra siblings, descendants, incomplete rows, changed/reused identities and one-sided appearances still refuse. Console names alone grant no exception.

The existing execFileSync calls, timeout, buffer, encoding, error/exit behavior and all pin rechecks stay unchanged. An owned micro-collector test runs the actual Node-to-Node-to-PowerShell synchronous chain, querying only fixture PIDs and children. It imports no admission module and uses no production policy, lock, ledger, database, service, task or profile data. Separate tests retain both-console and adversarial trees even on platforms without Windows console processes. Existing collector fixtures substitute process rows and do not prove this launch topology.

## Failure evidence

The safe reference diagnostic adds an allowlisted `chainBranch`, explicit private truncation state and `diagnosticStored` when persistence was attempted. Normal admission CLI errors omit private rows. The probe's internal JSON/error object additionally carries `privateReferenceDiagnostic` with the actual related before/after rows: PID, parent, name, executable, command line and creation time. This is private host evidence and must not be uploaded or included in public output.

Private evidence is capped at16 rows per snapshot and64KiB overall, with field bounds, original row counts and an explicit truncation flag. No missing/truncated evidence is an authorization input. Scope propagates it to the owner. Admission/publication append `referenceFailures` to the existing single ledger under the existing ownership/hash checks and1MiB metadata budget. Existing entries are retained. No new sidecar, policy, retry credit or continuation is created. If admission cannot persist the diagnostic, its original refusal remains visible, `diagnosticStored:false` is emitted, and the lock remains held. Publication retains its existing held-claim behavior and reports persistence failure without leaking raw data.

An earlier error containing only collector-chain / REFERENCE_PROBE_CHILD_UNCERTAIN cannot identify which of its several assertions failed. New owned reproduction establishes a topology defect; it does not reconstruct missing historical production rows. A consumed production continuation remains held after this code fix. No new production retry is authorized.

Admission retains the original query error across the installer's generic finally/close error. It records failures before inner close releases ownership, including queries after initial admission, a started slot and final verification. Partial outputs remain held. A failed evidence save leaves the lock/tmp in place and does not automatically try the write again. The same invocation records a failure once; continued attempts keep their held status. This does not grant cleanup, replay or another allocation.

# 有界恢复点保留提案（待明确批准，未实施淘汰）

生成预算、可靠去重和失败关闭能限制参与入口的增长、减少相同状态的重复副本，并在生成前拒绝超额。它们不会把持续变化的全量库压缩成无限历史，也不能保证无人维护的服务永远继续写入。仅配置 32 GiB 上限而没有保留政策，最终仍会停止受保护写入。

## 同一总预算中的三个有限集合

所有物理目录（含明确列出的 legacy 目标）仍计入统一 **32 GiB / 48 库 / 生成后余 4 GiB** 预检，不能靠分根/白名单绕开。以下子配额是待批准的维护规则，不是已实现的独立豁免：

| 集合                |                    数量上限 | 字节子预算 | 具体恢复范围                                                                                                                                 |
| ------------------- | --------------------------: | ---------: | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 活动恢复点          |                          16 |     14 GiB | 近2小时每15分钟一个不同状态，之前至24小时每4小时一个；当前 owner/有效启动 receipt 指向的点固定保留且占本集合槽位。                           |
| 有界历史档案        |                          16 |     12 GiB | 最近7天每天一个、最近4周每周一个、最近3个月每月一个；同一内容/重叠时间桶只占一个槽位。                                                       |
| 关键迁移/身份回滚点 |                          12 |      4 GiB | 各旧 schema 的代表性回滚点及明确的身份合并前点；恢复版本和用途写入清单。预算不足不能悄悄删保护点，必须另行批准退出旧版本支持或有界外部档案。 |
| 下次生成和短期余量  | 全部集合合计最多44点，余4槽 |      2 GiB | 还需按实际 DB+WAL 的保守预留复核；源库增长后重新评估，而不是扩大成数百GiB。                                                                  |

保留时间范围意味着近2小时之外不再保证逐15分钟的任意时刻回滚。淘汰独有中间状态会失去该时间点的精确状态，即使更早/更晚的快照仍在；这项损失必须明确批准。常规清理顺序先是停止生成且无有效 receipt/引用的空残留，再是完整 SHA 确认相同并保留至少一份可恢复副本的重复点，最后才是批准后的过期独有状态。

## 具体维护与验证

1. 用规范路径和文件身份盘点，分别报告 C/E 物理占用与 junction 映射；目录链接不重复计字节。新旧点都需要纳入，不能沿用上次清理后的数字。
2. 记录当前 owner、启动/迁移 receipt 和身份回滚保护引用。只读流式 SHA 区分逐字节重复；SHA 不同只说明状态不同，不自动判定业务价值。选中保留的库必须 quick_check、核对 SHA/恢复版本。
3. 生成逐文件提案，给出代表保留路径、待淘汰路径、字节数、时间范围、schema 和损失范围。只审批清单中的文件；未知、正在生成、身份变化或当前引用的点保留。
4. 批准后由维护者执行该批清单，再核验统一预检和被引用恢复点。压缩或迁移也必须有独立有限档案预算，并核验解压 SHA；同盘改目录不会释放物理空间。
5. 要长期无人值守，仍须单独批准并实现同一规则的保留轮转：新点生成并验证成功后才替换已批准的过期槽位；保护引用优先，失败不得先删最后可恢复副本。当前候选没有启用未来自动永久删除。未批准轮转时至少每4小时检查，预警立即维护，硬限额继续失败关闭。

直接启动旧版本、任意直接写文件或故意更换受管根不受本候选的应用层预算约束。当前改动不是操作系统磁盘配额，不承诺阻止所有第三方写盘。源码和演练生命周期已有限化；生产保留策略和对应激活仍需明确决定。

# 隔离阅读与归档体验基线（2026-10-20）

基线产品 SHA：`548db6b3a2d43578dfbf9e0539aa97634f1e2fba`。仅使用合成 SQLite、临时归档目录和用户电脑上的 Chrome 独立临时配置；没有复制生产库、真实采集或修改生产配置。没有产品性能代码改动。

## 场景与阶段定义

1809 篇合成记录、6 个来源。长文约 22.9 万汉字，1 张图；多图正文 7000 字，24 张各异的 256×256 PNG，每图约 197KB（总原图约 4.7MB），以真实缓存路径的内嵌 data URL 返回。调用实际 ArticleList、TrpcProvider、受保护 HTTP、Prisma SQLite 和 saveCachedArticleBatch。并行场景同时运行两篇本地归档，不调用外部来源。

冷读清除浏览器资源缓存与正文查询缓存；热读保留查询缓存，实际默认策略仍可能后台重新请求正文。操作系统页缓存不受控，不能称物理冷盘。每次全新归档目录也不表示物理冷盘。

正文就绪取 iframe load 时刻，是正文及图片 load 完成的代理指标，非精确首字符绘制；完整显示取全部图片 decode 成功和两帧完成的保守上界。为了在夹具观察图片，读取组件副本仅将 sandbox 增加 allow-same-origin，脚本仍禁止；产品代码的 sandbox 未改变。服务 HTTP 是路由到响应 finish；客户端 HTTP 含回环传输与接收；渲染阶段以冷读正文 load 减客户端 responseEnd 估算。阶段可能重叠，不应直接相加。

归档“写入”包含查库、转换、回执及文件写入；“可打开”再实际读取 Markdown 和全部图片相对引用，不代表启动 Obsidian 或等待外部同步。图片逐张检查 decode、naturalWidth；文件逐个非空读回。

## 判断与复现

多图等待主要随约 6.3MB base64 HTML 传输、iframe 文档与图片解析增长。当前没有定位出值得小范围修复的日常缺陷，停止微优化；不把人工组合 SQL、历史索引或批处理跑分当成本轮收益。长文和小图的旧样本只用于夹具校准，未混入上表。

运行 `EXPERIENCE_SAMPLES=10 node --test scripts/experience-baseline.test.cjs`（PowerShell 用 `$env:EXPERIENCE_SAMPLES='10'`）。需要 Node 24、锁依赖及本机 Chrome/Edge；CI 以每场景 1 样本验证完整性，不作为本机性能结论。原始本机日志、路径和临时数据不提交。
